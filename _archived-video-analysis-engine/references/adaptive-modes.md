# 精简版输出快速参考

## 何时用精简版

| 信号 | 说明 |
|:---|:---|
| 视频类型 = 教程/How-to | 操作步骤 > 哲学分析 |
| 时长 < 20 分钟 | 信息密度不足以支撑全 8 章 |
| 弹幕/评论 < 5 条 | 受众数据不足以做量化分析 |
| 用户说"精简版"或"先看看" | 明确信号 |

## 精简版结构

```
---
YAML frontmatter（同全量版）
---

# 标题

## 0. 元信息（完整但紧凑）

## 1. 逻辑流（仅表层，不展开暗线/元叙事）

## 2. 弹幕/评论（≤50 字 — 数据不足就直接写"数据不足"）

## 3. 核心洞察（G3 精简版：≥2 个，每个 150-200 字）

## 4. 深度拆解（2-3 个 Module，每个 ≤300 字）
   - 优先覆盖：工具清单、配置要点、坑点

## 5. 高光时刻（2-3 条金句）

## 6. 知识图谱（核心概念表 + 命令/工具速查表）
   - 跳过：文化梗、弹幕用语

## 7. 批判与行动（完整保留 — 这是教程类最有价值的部分）
   - 价值评估
   - 局限与偏见
   - 可行动项（三档）

## 8. 附录（来源 + 版本，跳过延伸阅读）
```

## 全量版 vs 精简版对比

| 维度 | 全量版 | 精简版 |
|:---|:---|:---|
| 质量标准 | Depth Quality Gates（G1/G3/G4/G5/G7），非 KB 体量 | 同左，精简版列阈值 |
| §1 逻辑流 (G1) | 表层+底层+弹幕反应线+核心结论，≤100 行 | 仅表层逻辑链，≤100 行 |
| §2 弹幕 | 6 情绪分类+关键词云+互动图谱 | ≤50 字，稀疏就跳过 |
| §3 核心洞察 (G3) | ≥3 个 × ≥200 字 | ≥2 个 × ≥150 字 |
| §4 深度拆解 (G4) | ≥3 个 Module，每个 ≥500 字 | 2-3 个 Module，每个 ≤300 字 |
| §5 金句 (G5) | ≥5 条（视频+弹幕合计） | 2-3 条 |
| §7 批判与行动 (G7) | ≥3 价值 + ≥2 局限 + ≥3 行动 | 同左（完整保留） |
| §6 知识图谱 | 4 张表 | 核心概念表+工具速查表 |
| §7 批判与行动 | 完整 | 完整（最不该压缩的部分） |

## 反模式（精简版常见错误）

- ❌ 因为数据稀疏而在 §2 写 300 字"稀疏性分析" → 承认稀疏，50 字打住
- ❌ 在 §4 仍然写 5 个 Module → 精简到真正重要的 2-3 个
- ❌ 删掉 §7 可行动项 → 这是教程类最有价值的输出（G7 不削减）
- ❌ 盯着 KB 数凑量/停手 → 质量按 Depth Quality Gates 衡量，用 `verify_report.py --mode condensed` 自检
