# 长访谈：先理解，再分析，最后形成文章

适用：长访谈、观点对谈，或用户指出旧稿空泛、模板化、覆盖不足。此文件负责 `layout: editorial`，不是新的 CLI depth mode。证据准入、授权、隐私及单视频范围仍由入口技能约束。

## 1. 写作前建立全片覆盖

顺序分批读完现有完整转录，不得仅搜索关键词或依赖上轮摘要。按实际返回长度控制批次；遇到工具截断，缩小范围补读被省去的内容，因为发出覆盖全片的读取命令不等于完整内容进入上下文。按论题转折记录临时覆盖清单：时间范围、提问、说话人或归属可信度、主要主张、具体案例、目标章节或合并/省略理由。每个有实质信息的主题必须有去向，包括后半场、结尾、反例及主持人的有效追问。寒暄可省略，重复应合并；不能拿音频完整或转录字数证明文章完整。

检测长段重复及异常专有名词。重复文本可能来自原媒体重播、下载错误或ASR幻觉，先用媒体对应片段或声学比较取证，再判断；不得把重复次数当观点权重。音频复核与二次ASR、语境检查分别陈述，不把机器复核写成真人听审。无法确认的名字或术语用描述性转述，不凭印象修正后写成逐字引语。

## 2. 先重建立场，后评判

每个主题先回答：受访者面对什么问题？实际答案是什么？举了什么具体例子？论证如何从前提走向结论？再回答成立条件、证据缺口、读者可迁移部分。

保留确定性强度；绝对信任不能改写为辅助建议。疑似矛盾须比较前后语境：不同任务、时段、层级或变化不自动等于逻辑矛盾。分析者补充的流程、条件与建议必须显式归属，不冒充嘉宾已经讲过。无说话人分离时，不为模糊轮次编造准确人名归属。

在外部研究前，把重要原主张写入已有临时claim台账：时间范围、短原文、最小完整命题、说话者归属及确信程度、必要前提/让步。将“某事件发生”与“它如何发生”的解释拆成不同命题；说话者确信程度与外部证据裁决分列，不让后来的核查改写这份源文重建。价值判断、规范性排序也保留，即使无法作事实裁决。不能只记话题名，或把多个强命题压成一个温和摘要。该台账是研究和写作的输入，不是写完文章后倒填的覆盖证明。

## 3. 核查与知识拓展平级，不用免责声明代替研究

分析目标是视频驱动的知识资产，不是详细摘要、观点评论或逐条辟谣。先忠实还原各主要论题的答案、案例、推理及前提，再按重要性组织研究；承重问题决定优先级，但不能把学习价值高的概念澄清与知识背景排除在研究之外。不要先锁定漂亮主线，再挑视频片段与论文配合它。

从原材料提取会改变读者判断的承重问题，再决定检索。将“某句说法是否正确”的核查问题，与“读者为什么困惑、还缺什么概念或机制”的学习问题分开；后者决定需要拓展哪些知识，不能只沿容易纠错的原话搜索，否则研究齐全仍会生成批注式摘要。不以容易核查的数字、健康常识替代标题主问题。维护临时 claim 台账：原话与时间、可核查命题、优先级、正文证据、来源日期/版本、裁决、支撑边界、落文位置；裁决用 confirmed / partially / refuted / unverified，别用链接数量冒充验证深度。

两条研究线分别交付，缺一不可：
- **事实核查**：将强断言拆成可判断的小命题。读取原始研究、技术文档或当事方完整声明；高影响争议尽可能找独立材料，转载不算独立。明确事实、当事方自述和推测的区别。数字必须同口径保留样本、任务、指标、时间、研究设计；旧实验不描述当前能力。发现更新、撤回或更正就沿更新取证，不能只引用最适合自己论点的旧结果。
- **知识拓展**：按视频的学习价值选择定义、机制、历史背景、比较、应用、前置知识、反例、局限与延伸阅读；不把拓展收窄为风险提示，也不机械填满全部维度。每项拓展写清：源视频的具体困惑→外部研究/理论实际说了什么→增加了什么理解、如何改变本段解释→不能外推到哪里。优先原始论文和有方法说明的实证；组织理论迁移到个人、旧工具实验迁移到新工具，都要标为有限解释，不伪装成直接检验。

研究须实际进入承重段落：若删掉引用后论证完全不变，说明它只是装饰，应重写连接或弃用。既查支持也查限制/反例，不预设全盘赞同或辟谣。保留完整重建，但不要求对每个旁枝各写一篇核查。

研究缺口与文字缺陷分开处理：缺证、机制悬空或反证缺位，先定向补研并更新台账，再重写；只有证据充分时才做结构/措辞修订。关键问题尚可查时，不能用一串“未核实/不构成建议”结束任务。确实不可得的材料，记录已尝试路径、未定结论及其影响；不用未经核实命题支撑主结论。

官方产品页可证明接口存在，不证明行业优劣；争议报道不能裁决剽窃；形式化通过不自动证明命题翻译正确。研究来源质量和结论强度始终分开判断。

## 4. 读者文章，而非工程报告

研究后、写前，先在已有论证大纲中说清读者问题、材料共同支持的新判断、支持和反向证据、适用边界，再决定章节。新判断须解释材料之间的关系，不能只是话题分类或通用建议；若证据不支持新的解释，缩窄问题而不是编造洞察。大纲记录全文要回答的问题、证据支持的核心判断、每章接住的上一结论、该章推进的新判断及留给下一章的问题。它是可核对的论证摘要，不是内部思维记录。按判断需要调用跨时间材料，不把已完成的台账顺序变成正文顺序，也不要求每条主张独占段落。重要立场仍需准确交代；无法服务正文且不改变主要解释的旁枝，可在后台记录省略理由。

先检查章级论证再铺正文：每章指出一个读者问题、一项推进的判断、实际支持它的原命题与外部材料，以及为什么下一章需要这个结论。用现有大纲做删除/调换检查，不能用“信息→行动→自由”等抽象词串代替依赖。若实际只是在一个标题下连续安排几组“嘉宾说法→外部纠偏”，先合并为共同问题或把旁枝归位，不靠新增过渡句掩盖。研究用于解释共同问题，核查和知识拓展仍平级；不为制造单一主线牺牲全片重要立场。

“他先说A，再说B，这值得借鉴但有局限”的连续结构也是流水账，即使时间顺序已打乱。用少数足以承担论证的具体场景带动跨段综合，合并平行材料；旁枝可以简要归位或有理由省略。每章如果调换顺序、删掉或改成另一场访谈都不影响全文，返回重建主线。

自然段让原材料、外部证据与分析相互作用，避免机械地每段先表扬后纠偏。开篇建立真正的问题与张力，正文走完后再从成稿重写开篇/结论。短段落，一段一个任务，通常不超过240字；不强制字数、章数、金句或图表配额。

Claim/evidence/warrant/boundary是后台分析结构，不强制印成正文标签。高光引语留在有上下文的论述处，不为凑数量摘一句无信息量的话。没有观众材料时，文末一句说明即可，不建空的弹幕/评论章节。只有能压缩关系时才用表格和图，不强制每模块Mermaid。不给用户私人工具栈找无证据关联。

正文只保留简短来源说明；分段统计、模型、修复记录、搜索路由、失败详情、验证日志保留在临时证据目录。成稿时把编辑提醒转成完整归属的原主张与分析，不把“不能改写成”“删掉就写反”等验收指令带进正文，因为它们解释的是作者操作而不是读者问题。写一个正式成品，不输出转录、初稿和审核副本给用户。是否写入Vault遵循当次授权与Vault约定，不把scratch生成冒充落库。

## 5. 编辑验收与可定位记录

### 重复失败任务：把检查前移

当同一任务已反复出现强命题弱化、覆盖自评误判或主题拼接，先停在成文前，由非作者实际回读源文窗口与重建台账、证据综合与章级大纲。协调者可直接承担这次检查，无需固定多agent团队或新增一套产物；若采用独立实例则遵守当前通道和单writer约束。记录实际发现与通过/失败，再进入正文阶段。未通过先修复对应台账/大纲，缺证才补研，不先写完再靠作者承诺修正。此检查不代替最终全文验收，也不保证模型按规则生成。只关闭实际发现的承重缺口：补读相关原始材料，修正对应台账和大纲，再核对受影响论证；不要因为一处补证重做已通过且未受影响的研究。给下一阶段明确的通过范围、补正及仍未裁决项，不能把“允许成文”报告成“全文通过”。

### 实际成稿验收

从源文重建台账逐项查实际正文，再从正文判断反查证据，最后检查整体叙事和读者时间锚。不要先读作者的PASS自评再决定抽查。最终逐节读实际Markdown，并在临时目录保存验收记录，至少包括：
- 全片主题→正式章节映射及合并/省略理由；这只是导航，不是语义覆盖证据。对支撑结论的主张、绝对表达、规范性优先级和有效反问，逐项核对“原文时间范围＋最小完整命题→成稿实际段落＋所保留的含义”；不能仅填写目标章名便判覆盖。未在成稿找到的命题，明确记为遗漏或有理由省略。
- 核对主张与限定是否成对保留：不能只保留例外/让步而抹去主要立场，也不能只保留主张而删除限制。尤其复查结尾与结论引用的材料；流畅的综合不能把强断言替换成泛化的温和建议。
- 每个材料性外部判断→实际读过的来源、样本/设计/版本与不能支撑什么；来源已读正文或只读摘要须如实记录。
- 承重问题分别有哪些核查结果与知识拓展；具体指出新研究改变了哪一段解释，以及读者获得了哪些原视频未讲清的知识。不能以“来源齐全”代替此项。
- 洞察综合审查：事实与案例之间的关系是否产生新理解，是否检验替代解释与反证，是否交代可迁移条件；个人评论、复述与通用建议均不能冒充洞察。
- 主线审查：先不读作者大纲和PASS自评，对实际正文做反向段落提纲，概括每段解决了哪个读者问题、增加了什么判断或为哪个判断提供证据。检查主体是否仍按人物原话、论文或话题逐个换场，综合判断是否只在段尾/章尾出现；标题是问题句、章节有过渡、各段事实正确，均不能单独证明论证推进。核查关键解释是否实际组织了材料，而不是给并列材料补一个抽象总结；不要用减少“他说”、免责声明或字数代替这个裁决。
- 重复审查：同一核心解释只展开一次；结尾增加适用条件，不复述全部标题。
- 忠实审查双向进行：从重要原命题向正文查遗漏、弱化与归属，从正文关键判断向原文/外部证据查支持。读者能复述说话者真正的答案，建议没有取代原意；不能由作者的覆盖表或自评替代对正文的检查。
- 可读性审查：删掉名字后若仍可套用任何访谈，退回补具体材料；无空章节、凑词、模板标签或工具日志。
- 核查程度、ASR误差及没有做的检查清楚说明。

静态检查可以扫描占位词、私密路径、超长段落、时间戳范围、重复段落和来源引用，但不能证明语义完整或写作优秀。`verify_report.py`和`verify_publishable_report.py`仅适用于固定章节；editorial稿不得为过这些门又塞回旧标题或谎称通过。若调用方必须接收旧schema，交付旧schema或明确阻塞其消费，不伪装兼容。

## 6. 修改技能后的真实使用

### 方法比较与短篇探针

比较写作机制时，给候选相同的原命题窗口、研究材料和读者问题；需要新增来源时，标明知识增量来自补研，不能全部归因于组织方式变化。先逐项查实际文本中的立场、确信和成对限定，再比较新理解及段落推进，因为概念聚合也可能删掉不顺主线的关键限定。命题计数从实际文本核对，不能由作者的“全部保留”表格推导；只含承接词的短引语也不能证明完整命题。把模型内的结果、目标函数与假设一起迁移，不把理想模型的成功率当现实决策通用上限。

把看过旧稿的作者所写短片段标为探索性示范，而非独立生成测试。需要成对评价时，隐藏候选名称与作者自评，交换呈现顺序，并区分上下文独立与模型独立；模型偏好仍不等于用户认可。用审读发现来选择最小可测试修改，不预设概念矩阵、双层索引或洞察单元已经有效，也不凭文献提出的方法声称本技能行为已验证。

### 候选的真实执行验证

改完入口与模板后重新通过skill_view加载入口及本文件，再执行真实样本或受影响环节的定点验证。需要验证生成行为时，用独立新上下文从冻结原始证据启动，不把旧稿和已知失败答案提供给作者做定点修补；成稿后由非作者审核实际正文与源文。保留该attempt的原生执行回执和可定位工具日志，分别验证载入、分批读取、研究、大纲与成文顺序；截断日志只能证明已显示的调用，作者自述不能证明完整顺读。定点检错验证只证明验收能识别该错误，不证明再次生成正确。若协调者或独立审核在生成前补证、修正大纲或提供反馈，将其记录为本次流程输入；后续成功最多支持这个完整协调流程，不能归因为入口提示单独使模型一次生成正确。若主任务是优化技能，文章只是验证样本：先把失败归为执行遗漏、规则冲突、契约缺失或能力限制，再修改真正有缺陷的规则；不要不断润色文章替代技能交付，也不要因已有规则未被执行而重复堆叠同义禁令。验证结果区分：指令与链接有效、具体样本行为、CLI引擎是否支持新布局、跨视频泛化、用户是否认可；不互相外推。保留现有采集/证据合同，不为了改善文章重构无关代码或重复长耗时ASR。
