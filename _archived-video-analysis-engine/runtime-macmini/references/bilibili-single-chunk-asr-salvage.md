# Bilibili 单段 ASR 的正式笔记抢救流程

## 触发信号

适用于 Bilibili 已成功取得 H200/Whisper 转录，但 Writer 草稿出现以下任一情况：

- `author` 为空或 `duration_seconds=0`；
- 所有时间戳坍缩到 `0:00`；
- Source Appendix 暴露 `.p6r-cache`、`/tmp`、模型或端点路径；
- 仍有 `_目的：..._`、`暂无可抽取行动项` 等模板残留；
- 知识图谱只是词项共现；
- 自动门通过，但正文冗长、重复或不可读。

## 根因判断

H200 转录可能只有一个整段 chunk。`generate_report.py` 会认为 transcript 存在，但无法从单个起点推导真实时长与细粒度时间锚。与此同时，`fetch_all.py` 的顶层 `info` 可能为 `null`，导致 Writer 缺作者和时长。此时不能把 `has_transcript=true` 或静态门通过误当作正式笔记可发布。

## 稳妥恢复

1. **保留并可读地检查转录证据**：确认 ASR 文本非空，并记录转录方式、字符数、分片数；正式笔记不得暴露本地路径。若 ASR 把整段内容写成一个超长行，`read_file` 可能只显示开头或被截断；不要据此误判证据不完整。改用本地 Python 将连续空白归一化、按 `。！？` 分句并编号后再人工阅读，临时展开文本不进入 Vault。
2. **补权威元数据**：调用 Bilibili `x/web-interface/view?bvid=...`，从 `data.owner.name`、`data.duration`、`data.title` 获取作者、时长和标题。API 结果只用于元数据，不替代转录内容证据。
3. **承认时间分辨率不足**：若 ASR 只有一个起点，明确写“无法可靠恢复细粒度时码”；不要按文本长度猜时间，也不要生成一串伪 `0:00` 链接。
4. **重写而非修饰骨架**：当草稿同时存在元数据缺失、路径泄露、模板残留和词项图谱时，基于转录与元数据重写一份干净的正式笔记，避免在坏骨架上继续补丁。
5. **短视频优先 condensed**：约 10–20 分钟的教程视频可用 `verify_report.py --mode condensed --claim-first`；保持 2–3 个高密度洞察和 2 个模块，不为满足 full 阈值灌水。
6. **重写时遵守正式报告章节契约**：手工救援稿不能只追求可读性，还必须保留静态门识别的顶层章节 `## 0.`、`## 1.`、`## 2.`、`## 2.5.`、`## 3.`、`## 4.`、`## 5.`、`## 6.`、`## 7.`、`## 8.`。其中 condensed 模式至少需要：§3 两个 `### 💡` 洞察（每个 ≥150 中文字/词元，并显式写主张、证据/推理、边界）；§4 两个 `### 模块 N`；§5 两组独立 blockquote；§7 至少 3 条独特价值、2 条局限、3 条带 `[E#]` / `[C#]` 的行动项。不要等正文写完才发现结构门无法识别。
7. **静态双门**：对最终 Vault 文件运行 `verify_report.py --mode condensed --claim-first` 与 `verify_publishable_report.py`。注意：直接运行 publishable CLI 是 Markdown 静态门；若需要 claim bundle / evidence map 的报告级校验，必须在仍持有原始 `report` 对象的生成流程中执行，不能把静态 PASS 写成完整证据门 PASS。
8. **人工 QA**：逐项检查作者、时长、证据边界、评论/弹幕样本、无本地路径、无模板残留、无长转录、行动项具体、知识图谱有语义。单段 ASR 若无可靠时间码，宁可明确声明，也不要根据文本长度估算或伪造时间戳。
9. **Vault 验证**：按当前 `AGENTS.md` / `.vault-structure.json` 写 YAML；解析全部 wikilink 并确认目标使用真实文件 stem 或现有 alias（显示标题可用 `[[真实文件名|显示标题]]`）；随后运行 `qmd update` 与 `qmd embed`。任何最后修正都会改变索引内容，修正后需再次刷新并对最终文件重跑双门。

## 发布口径

- 评论极少或弹幕为 0：只能描述样本，不能推断群体共识。
- 视频中的仓库 Star、会员边界、产品能力等可变事实：若未独立核验，明确标为“视频中的当时陈述”，不要升级为当前官方事实。
- 最终只保留一份正式用户笔记；ASR、Writer 草稿、采集 stdout 和验证日志留在临时工作区，不进入 Vault。
