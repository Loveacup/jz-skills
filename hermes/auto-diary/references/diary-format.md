# 日记格式规范 v3.0

本文档定义日记 markdown 的完整输出格式。生成日记时必须遵循。

## 文件头（含 YAML frontmatter）

```markdown
---
created: YYYY-MM-DD HH:MM
tags: [type/日记, status/闪念, src/对话]
---

# YYYY-MM-DD 星期X

> [!abstract] 📋 今日速览
> - 🌤️ {天气}
> - 📅 {N} 个日历事件
> - 🐴 Hermes {N} 会话 · 💻 CC {N} 会话
> - 📚 {N} 个知识库变更
```

- `created` 用日记生成时间
- abstract callout 默认折叠（`-`），读者按需展开
- 各项数据从 `ai_logs` 中提取

## 段落结构（按此顺序）

### 1. 🌤️ 概览

```markdown
## 🌤️ 概览

| 项目 | 状态 |
|------|------|
| **天气** | {weather} |
| **心情** | (待补充) |
```

### 2. ⏰ 时间线

```markdown
## ⏰ 时间线

| 时间 | 事件 | 备注 |
|------|------|------|
| 14:00-17:00 | 🛍️ Naomi 万象城逛街 | 临时占位 |
```

- 来源：日历事件（优先）、AI 对话主题
- 按时间顺序排列
- 若无时间线数据则写 `(待补充)`

### 3. 🤖 AI助手工作记录

**🔴 铁律：严禁引用用户原话。** 所有会话主题必须以概括性标签呈现。

```markdown
## 🤖 AI助手工作记录

### 🐴 助理体系（小黄 + cron-worker）

> [!info] 📊 数据概览
> - 会话: {N} · 消息: {N} · 用户轮次: {N}

**今日重点**: {概括主题}

**核心成果**:
- ✅ 成果1
- ✅ 成果2

#### 📖 知识输入
- ...

#### 🔍 技术调研
- ...

### 🏛️ 治理体系（太子 + 三省六部）

> [!info] 📊 数据概览
> - sessions: {N} · msg: {N} · turns: {N}
> - 覆盖 profiles: {列表}

- 主题概括（穷举覆盖，每类至少一行）

### 💻 Claude Code

> [!info] 📊 数据概览
> - sessions: {N} · msg: {N} · turns: {N}
> - 覆盖项目: {列表}

- 主题概括（穷举覆盖，每类至少一行）
```

- 助理体系 / 治理体系 / CC 三段结构固定
- 无数据段：`当日无 {体系} 活动记录`
- `> [!info]-` callout 默认折叠，避免数据轰炸主体内容
- 主题按类别分小组（📖知识输入 / 🔍技术调研 / 📝文档管线等），每组至少一条概括

### 4. 📚 知识库更新

```markdown
---

## 📚 知识库更新

### 目录名/
- **[新建]** [[文件标题]] — 摘要内容
- **[修改]** [[文件标题]] — 摘要内容
```

- 基于 `vault_changes` JSON 数据生成
- 按文件夹分组（取路径第一层目录）
- 每条格式: `- **[新建/修改]** [[文件标题]] — 摘要`
- 使用 Obsidian wikilinks `[[]]` 包裹标题
- 若无变更: `> [!NOTE] 今日知识库无更新`

### 5. 📅 日历事件

```markdown
---

## 📅 日历事件

| 时间 | 日历 | 事件 | 地点/备注 |
|------|------|------|-----------|
| 14:00-15:30 | Naomi | 🎾 网球课-钱江湾 | |
| 18:00-20:30 | 个人 | 🍽️ 老叶请客·群乐饭店 | 群乐饭店（滨江路1197号） |
```

- 表格格式，四列：时间 · 日历 · 事件 · 地点/备注
- 时间格式：HH:MM-HH:MM 或 "全天"
- 若无日历事件: `> [!NOTE] 当日无日历事件`

## 🔗 Obsidian 集成要点

- **Frontmatter**：每个日记文件必须含 `created` 和 `tags`
- **Wikilinks**：知识库变更用 `[[文件名]]` 格式
- **Callout 密度**：日记约 2000-5000 字 → 3-5 个 callout（abstract、info × 2-3、tip）
- **分隔线**：`---` 用于划分核心段落组（AI工作 → 知识库 → 日历 → 个人生活 → 总结 → 笔记）
- **不使用**：Mermaid 图表、链接关系分析、脚注——这些是研究笔记的工具，不适合日记

## 合并规则

当 `existing_content` 不为 null 时（用户已手写部分内容）：
1. 保留用户已写的所有内容
2. 仅填充空白段落或 "(待补充)" 占位符
3. 不修改或覆盖用户手写文字
4. AI助手记录 和 知识库更新 段落可以追加（如果之前没有）
5. 若用户已写了完整日记，只追加缺失的自动化数据段落
