# 日记格式规范

本文档定义日记 markdown 的完整输出格式。生成日记时读取此文件获取格式要求。

## 文件头

```markdown
# YYYY-MM-DD 星期X
```

## 段落结构（按此顺序）

### 1. 概览
```markdown
## 概览
**天气**: {weather数据}
**心情**: (待补充)
```

### 2. 时间线
```markdown
## 时间线

| 时间 | 事件 | 备注 |
|------|------|------|
| 08:30 | Naomi 寒假班-外出研学 | 小朋友-杭州日历 |
| 09:00 | 水土保持 AI 会议 | 工作日历 |
| 14:00 | 🎾 网球课-钱江湾 | Naomi 日历 |
| 18:00 | 🍽️ 老叶请客·群乐饭店 | 个人日历，群乐饭店（滨江路） |
```
- 来源：日历事件（优先）、AI对话主题等
- 按时间顺序排列
- 包含日历来源和地点信息
- 若无时间线数据则写 "(待补充)"

### 3. AI助手工作记录

**🔴 铁律：严禁引用用户原话。** 所有会话主题必须以概括性标签呈现，如「视频内容分析」「技术配置与调试」「文档整理与知识管理」，绝不出现用户的具体消息文本。

```markdown
## 🤖 AI助手工作记录

### 🐴 Hermes / 助理体系
**今日重点**: {从采集数据中提取}

**核心成果**:
- ✅ 成果1
- ✅ 成果2

### 💻 Claude Code
- **会话数**: N
- **模型**: {model}
- **主题**: 主要主题概要（概括性标签，非原文引用）
- **覆盖项目**: {projects}

### 🎯 其他 AI 工具
- 待扩展（OpenAI / Codex 等，可后续接入）
```
- 基于 ai_logs JSON 数据生成
- Hermes 助理体系（小黄 + cron-worker）和治理体系（太子 + 三省六部）从 ai_logs JSON 分类提取
- Claude Code 从 `~/.claude/projects/` JSONL 提取（含模型、项目信息）
- ⚠️ 主题必须用概括性描述，严禁直接引用用户消息原文

### 4. 📚 知识库更新 (NEW)
```markdown
## 📚 知识库更新

### 003_AI/
- **[新建]** [[Chain-of-Thought]] — 链式推理是一种提示工程技术...
- **[修改]** [[Prompt Engineering]] — 更新了最新的提示词优化方法...

### 004_视频整理/
- **[新建]** [[Clawdbot Demo 视频]] — 演示小黄的自动化能力...
```
- 基于 vault_changes JSON 数据生成
- 按文件夹分组（取路径第一层目录）
- 每条格式: `- **[新建/修改]** [[文件标题]] — 摘要内容`
- 使用 Obsidian wikilinks `[[]]` 包裹标题
- 若无变更: `> 今日知识库无更新`

### 5. 日历事件
```markdown
## 📅 日历事件

| 时间 | 日历 | 事件 | 地点/备注 |
|------|------|------|-----------|
| 14:00-15:30 | Naomi | 🎾 网球课-钱江湾 | |
| 18:00-20:30 | 个人 | 🍽️ 老叶请客·群乐饭店 | 群乐饭店（滨江路1197号）<br>包厢：四楼V8二号包厢 |
```
- 来自 OpenClaw agent 内置日历读取
- 时间格式：HH:MM-HH:MM 或 "全天"
- 地点/备注列显示 location 和 notes 信息
- 若无日历事件: `> 当日无日历事件`

**旧格式（兼容）：**
```markdown
## 📅 日历事件

- ✅ 事件1描述
- 📅 事件2描述
```

### 9. 临时笔记
```markdown

```

### 10. 页脚
```markdown
---

*日记草稿由 auto-diary skill 自动生成 - YYYY-MM-DD HH:MM*
*请补充缺失部分后删除此备注*
```

## 合并规则

当 `existing_content` 不为 null 时（用户已手写部分内容）：
1. 保留用户已写的所有内容
2. 仅填充空白段落或 "(待补充)" 占位符
3. 不修改或覆盖用户手写文字
4. AI助手记录 和 知识库更新 段落可以追加（如果之前没有）
5. 若用户已写了完整日记，只追加缺失的自动化数据段落
