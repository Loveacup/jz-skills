# 日记格式规范 v3.3

本文档定义日记 markdown 的完整输出格式。生成日记时必须遵循。

## 设计原则：倒金字塔

叙事性内容（每日总结）放在最上层，AI 会话台账收进折叠块。读者一眼看到最重要的反思，需要时才展开细节。

## 文件头（含 YAML frontmatter）

```markdown
---
created: YYYY-MM-DD HH:MM
tags: [type/日记, status/闪念, src/对话]
---

# YYYY-MM-DD 星期X

> [!abstract] 📋 今日速览
> - 🌤️ {天气}
> - 📅 {N} 个日历事件
> - 🐴 Hermes {N} 会话（助理 X + 治理 Y）· 🤖 Codex {N} 会话（💻独立 A + 🤝Guardian B + 🤖程序 C）· 💻 CC {N} 会话（🤝协作 N + 💻独立 N + 🤖程序 N）
> - 📚 {N} 个知识库变更 · 📦 jz-skills {N} 个 commit
```

- abstract callout 默认展开
- CC 数用 `claude_overview` 的 `agent_team`/`standalone`/`program_call` 分组数据

## 段落结构（按此顺序）

### 1. 🎯 每日总结（倒金字塔顶层）

```markdown
## 🎯 每日总结

> 来自"清晰提示工作流"系统的三个问题：

1. **今天我做了什么推动进展的事情？**
   - (基于 AI 记录和日历事件填写)
2. **明天我可以构建什么未来的事情？**
3. **我可以从过去淘汰什么流程？**
```

- 三问从底部提升到顶部，成为整个日记的核心
- 叙事后空行接分隔线 `---`，然后才是细节区块

### 4. 🤖 AI助手工作记录

**🔴 铁律：严禁引用用户原话。** 穷举覆盖：所有 topic 必须体现。

#### 📊 全天AI活动概览（必须）

```markdown
## 🤖 AI助手工作记录

> [!info] 📊 全天AI活动概览
> - **🐴 Hermes**: {N} 会话（助理 X + 治理 Y）· 全平台（telegram + cli）
> - **🤖 Codex**: {N} 会话 · 💻 独立 {N} + 🤝 Guardian {N} + 🤖 程序 {N}
> - **💻 CC**: {N} 会话 · {N} 消息 · {N} 轮次
```

- Hermes 总数 = 助理体系 + 治理体系，不再单独列 Regent 行
- Codex=0 时标注 `（Codex 尚未接入体系）`

#### 🔗 跨运行时协作主线（必须，v3.3 新增）

```markdown
> [!note] 🔗 跨运行时协作主线
> - **{任务线名}**：🐴 Hermes 发起 → 🤖 Codex 审计 → 💻 CC 执行 → 📝 Obsidian 落地
> - **{任务线名}**：🏛️ regent 决策 → 💻 CC Agent Team → 📦 jz-skills 提交
```

- 从 Hermes/Codex/CC 三段数据中提取跨运行时任务流
- 按 `→` 展示端到端链路：发起方 → 审计/中转 → 执行方 → 交付物
- 最多 4-5 条主线，按重要性排序
- Codex=0 时标注 `（Codex 接入前夜）`，只展示 Hermes↔CC 协作
- ⚠️ **🔗主线为 agent 综合推断**（`_detect_cross_runtime` 仅做 cwd 字符串匹配）。diary-format 和 SKILL.md 的 Red Flags 均要求穷举覆盖+不凭记忆写——agent 必须基于会话数据做端到端链路推断，**不得凭记忆杜撰**。未来待做：在 `collect_data.py` 做真正的三方任务线 join 给数据支撑。

#### 🤖 Codex（v3.3 富格式）

```markdown
### 🤖 Codex

> [!info] 📊 数据概览
> - 会话: {N} · 💻 独立 {N} + 🤝 Guardian {N} + 🤖 程序 {N}
> - 总消息: ~{N} · 跨运行时协作：{简述协作角色}

##### 💻 独立对话（{N} 会话）

- **🔗 {项目/任务名}**（{N} 会话 · HH:MM · {N} 消息 · {N} 轮）
  - {每会话 2-4 行具体操作描述}
  - → 成果：{产出}
```

- 🔴 **每条独立对话必须有**：时间、消息数、轮次数、2-4 行具体描述
- 🔗 标注联动关系（审查 Hermes / 联动 CC / 维护共享基础设施）
- 自动化会话标注 `automation_id`
- 无独立对话时写 `> 今日无 Codex 独立对话`

#### 💻 Claude Code（v3.3 🔗联动标注）

```markdown
### 💻 Claude Code

> [!info] 📊 数据概览
> - 总会话: {N} · 消息: {N} · 轮次: {N}

#### 🤝 Agent Team 协作（{N} 会话）
- **项目名** ({N}): 主题概括
- **项目名** ({N}): 🔗 联动标注——与 🤖 Codex / 🐴 Hermes 协同说明

#### 💻 独立对话（{N} 会话）
- **项目名** ({N}): 🔗 主题概括——联动其他运行时说明
```
#### 🤖 程序调用（{N} 会话）
- **项目名** ({N}): 主题概括
```

- CC 分三组：🤝 Agent Team 协作 / 💻 独立对话 / 🤖 程序调用
- 分类来自 CC 元数据（entrypoint + parentUuid），不再使用文本匹配
- 每组按项目展开，每项目至少一条概括
- 数据来自 `claude_overview.agent_team`、`.standalone`、`.program_call`
- 优先展示 🤝 Agent Team（最重要的协作链路），其次 💻 独立对话（Alex 自己的），最后 🤖 程序调用（observer 等自动会话）

### 5. 📚 知识库更新

```markdown
---

## 📚 知识库更新

### 00-Inbox/ — 🐴 助理体系
- **[新建]** [[文件名]] — 摘要 → 关联：Hermes「会话主题概括」

### 00-Inbox/ — 💻 CC (项目名)
- **[新建]** [[文件名]] — 摘要 → 关联：CC 项目名 任务

### 20-Areas/ — 🏛️ 治理体系
- **[修改]** [[文件名]] — 摘要 → 关联：太子 工作流

### 20-Areas/ — 🤝 CC (hermes-a2a)
- **[新建]** [[文件名]] — 摘要 → 关联：A2A P0 修复任务
```

**关联规则（agent 在日记写作阶段执行）：**
1. 遍历 `vault_changes` 每条记录（path + title）
2. 与 `ai_logs.hermes.*.topics` 和 `ai_logs.claude.*.projects` 做**关键字交叉匹配**
3. 路径含 `hermes-a2a` → 关联 CC hermes-a2a 项目
4. 标题含「多 profile 治理 / regent」→ 关联 🏛️ 治理体系
5. 标题含「CC」「Claude Code」「skill」→ 关联 💻 CC 相关
6. 无法匹配 → 归入最相关的体系，标注 `(推断)`
7. 按「来源体系 + 目录」双层分组，每组内按文件名排序
8. 关联不可靠时标注 `(推断)`，可靠时不标注

- `vault_changes` 数据可能 > 30 条 → 只列前 20 条最重要的，加 `> 另有 {N} 个变更未列出`
- 若无变更: `> [!NOTE] 今日知识库无更新`

## 🔗 Obsidian 集成要点

- **Frontmatter**：`created` + `tags`
- **Wikilinks**：知识库变更用 `[[文件名]]`
- **Callout 密度**：4-5 个（abstract、info × 2-3、tip）
- **分隔线**：`---` 划分核心段落组
- **不使用**：Mermaid、链接关系分析、脚注

## 合并规则

当 `existing_content` 不为 null：
1. 保留用户已写的所有内容
2. 仅填充空白段落或 "(待补充)"
3. 不修改或覆盖用户手写文字
