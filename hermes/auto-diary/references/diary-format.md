# 日记格式规范 v3.1

本文档定义日记 markdown 的完整输出格式。生成日记时必须遵循。

## 文件头（含 YAML frontmatter）

```markdown
---
created: YYYY-MM-DD HH:MM
tags: [type/日记, status/闪念, src/对话]
---

# YYYY-MM-DD 星期X

> [!abstract] 📋 今日速览
> - 🌤️ {天气}
> - 📅 {N} 个日历事件
> - 🐴 Hermes {N} 会话 · 💻 CC {N} 会话（🔗联动 N + 🧑独立 N）
> - 📚 {N} 个知识库变更
```

- abstract callout 默认展开
- CC 数用 `claude_overview` 的 linked/standalone 分组数据

## 段落结构（按此顺序）

### 1. 🌤️ 概览

```markdown
## 🌤️ 概览

| 项目 | 状态 |
|------|------|
| **天气** | {weather} |
| **心情** | (待补充) |
```

### 2. ⏰ 时间线

```markdown
## ⏰ 时间线

| 时间 | 事件 | 备注 |
|------|------|------|
| 14:00-17:00 | 🛍️ Naomi 万象城逛街 | 临时占位 |
```

- 来源：日历事件（优先）、AI 对话主题
- 按时间顺序排列
- 若无时间线数据则写 `(待补充)`

### 3. 🤖 AI助手工作记录

**🔴 铁律：严禁引用用户原话。** 穷举覆盖：所有 topic 必须体现。

#### 🐴 助理体系

```markdown
### 🐴 助理体系（小黄 + cron-worker）

> [!info] 📊 数据概览
> - 会话: {N} · 消息: {N} · 轮次: {N} · profiles: default, cron-worker

**今日重点**: {概括}

##### 📖 知识输入
- ...

##### 🔍 技术调研
- ...
```

#### 🏛️ 治理体系

```markdown
### 🏛️ 治理体系（太子 + 三省六部）

> [!info] 📊 数据概览
> - 会话: {N} · 消息: {N} · 轮次: {N}
> - 覆盖 profiles: {列表}

##### 📋 流程审计与优化
- ...
```

#### 💻 Claude Code

```markdown
### 💻 Claude Code

> [!info] 📊 数据概览
> - 总会话: {N} · 消息: {N} · 轮次: {N}

#### 🔗 联动 Hermes（{N} 会话）
- **项目名** ({N}): 主题概括
- **项目名** ({N}): 主题概括

#### 🧑‍💻 独立会话（{N} 会话）
- **项目名** ({N}): 主题概括
```

- CC 必须分 🔗联动 和 🧑独立 两组
- 每组按项目展开，每项目至少一条概括
- 联动 = hermes-called + agent-team 类型合并
- 数据来自 `claude_overview.linked` 和 `claude_overview.standalone`

### 4. 📚 知识库更新

```markdown
---

## 📚 知识库更新

### 00-Inbox/ — 🐴 助理体系
- **[新建]** [[文件名]] — 摘要 → 关联：Hermes「会话主题概括」

### 00-Inbox/ — 💻 CC (项目名)
- **[新建]** [[文件名]] — 摘要 → 关联：CC 项目名 任务

### 20-Areas/ — 🏛️ 治理体系
- **[修改]** [[文件名]] — 摘要 → 关联：太子 工作流

### 20-Areas/ — 🔗 CC (hermes-a2a)
- **[新建]** [[文件名]] — 摘要 → 关联：A2A P0 修复任务
```

**关联规则（agent 在日记写作阶段执行）：**
1. 遍历 `vault_changes` 每条记录（path + title）
2. 与 `ai_logs.hermes.*.topics` 和 `ai_logs.claude.*.projects` 做**关键字交叉匹配**
3. 路径含 `hermes-a2a` → 关联 CC hermes-a2a 项目
4. 标题含「三省六部」「治理」「太子」→ 关联 🏛️ 治理体系
5. 标题含「CC」「Claude Code」「skill」→ 关联 💻 CC 相关
6. 无法匹配 → 归入最相关的体系，标注 `(推断)`
7. 按「来源体系 + 目录」双层分组，每组内按文件名排序
8. 关联不可靠时标注 `(推断)`，可靠时不标注

- `vault_changes` 数据可能 > 30 条 → 只列前 20 条最重要的，加 `> 另有 {N} 个变更未列出`
- 若无变更: `> [!NOTE] 今日知识库无更新`

## 🔗 Obsidian 集成要点

- **Frontmatter**：`created` + `tags`
- **Wikilinks**：知识库变更用 `[[文件名]]`
- **Callout 密度**：3-5 个（abstract、info × 2-3、tip）
- **分隔线**：`---` 划分核心段落组
- **不使用**：Mermaid、链接关系分析、脚注

## 合并规则

当 `existing_content` 不为 null：
1. 保留用户已写的所有内容
2. 仅填充空白段落或 "(待补充)"
3. 不修改或覆盖用户手写文字
