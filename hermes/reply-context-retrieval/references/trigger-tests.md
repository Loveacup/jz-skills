# Trigger Tests — reply-context-retrieval v1.0.0

## Should Trigger (12 scenarios)

| # | Scenario | Why |
|---|----------|-----|
| 1 | 消息以 `[Replying to: "腾讯云将向您在步骤6提交的银行对公账户转入0.01-0.99元..."]` 开头 | 匹配 `[Replying to:` 前缀，含专有名词 |
| 2 | 用户说 "我引用给你了，你看看" | 匹配 "引用" 触发词 |
| 3 | 用户说 "你看一下我的引用" | 匹配 "引用" 触发词 |
| 4 | 用户说 "我回复了你一条消息" | 匹配 "回复" 触发词 |
| 5 | 用户 reply 了一个含数字和专有名词的片段 | 片段有足够信息量，需检索 |
| 6 | 用户 reply 了一个以 `...` 结尾的不完整句子 | 被截断，必须检索完整内容 |
| 7 | 用户说 "引用那段的完整上下文是什么？" | 明确请求完整上下文 |
| 8 | 用户 reply 了一个跨 session 的旧消息 | 触发 fallback 到全部 session |
| 9 | 用户 reply 了一个 image/media 描述片段 | 需从描述文本定位原消息 |
| 10 | 用户说 "你能看到引用原文吗" | 明确请求查看被引用内容 |
| 11 | `[Replying to: "💭 Reasoning: Very helpful! The search results..."]` | 含 role tag + 明显被截断 |
| 12 | 用户说 "我引用给你的那段话" | 匹配 "引用" + 指向性代词 |

## Should NOT Trigger (10 scenarios)

| # | Scenario | Why |
|---|----------|-----|
| 1 | 用户直接发送普通文本消息（无 reply 标记） | 无引用标记 |
| 2 | 用户说 "引用某篇文章里的数据" | "引用"指文献引用，非 TG reply |
| 3 | 消息含 `[Replying to: "好的"]` | 自解释短回复，无需检索 |
| 4 | 用户在同一条消息里给出了完整上下文 | 不需要额外检索 |
| 5 | 用户说 "我刚才说了..." 然后重复了完整内容 | 上下文已在当前消息中 |
| 6 | 用户说 "回复" 但指的不是 TG reply 功能 | 语境是 "回复邮件" 等 |
| 7 | `[Replying to: "OK"]` 或 `"知道了"` | 简单确认，无需检索 |
| 8 | 用户说 "引用一下" 但不带 `[Replying to:` 格式 | 无实际引用标记 |
| 9 | 正常对话中出现的 "引用" 一词 | 无 reply 标记 |
| 10 | 用户说 "请回复我的上一个问题" | 无 reply 标记，正常对话 |

## Edge Cases (4 scenarios)

| # | Scenario | Expected Behavior |
|---|----------|-------------------|
| E1 | 引用片段超短但带关键术语：`[Replying to: "k8s pod crashloop..."]` | ✅ 应触发 — 有关键信息 |
| E2 | 用户同时 reply + 原文转发，消息里已含完整内容 | ❌ 不应触发 — 完整内容已在 |
| E3 | 当前 session 搜不到，但跨 session 找到了 | ✅ 触发 fallback，从旧 session 提取 |
| E4 | 两处都搜不到，片段太模糊 | 告知用户 "请转发原文"，不猜测 |
