# r2.1-context-template — 澄清式交接·增强版 context 模板

> **用途**：R2.1 澄清式交接（PRD §5 R2.1）的可复用 context 模板。**复杂任务**派发 CC 时用它，
> 把首轮 context 从「一段文字」升级为「带方向、带路标、带红线的起点」，让 CC 先**只读工具查证**
> 理解任务、形成方案，与 Hermes 讨论对齐后再执行。
> **简单/机械任务**：用简化版 `templates/discuss-first-snippet.md`（只复述、不调工具）即可，别套这个重模板。
> **怎么用**：复制 `>>> 粘贴起 <<<` 区块到任务 context 文件，Hermes 逐段填写（删掉填不出的段，别留空占位），
> 再 `cc-send.sh` 发送。CC 读到时**按 section 行动**。
> **配套**：完整协议见 `references/r2.1-clarification-protocol.md`；验收契约（criterion）见 SKILL.md §5.1 委派包格式。
> **只读约束靠 convention**：澄清阶段「只读不写」是协议约定，不靠 hook/脚本强制（同三段协议节点①）。

---

>>> 粘贴起 <<<

# 任务：<一句话标题>

## 1. 任务简报（软性方向，不是硬指令）

> Hermes 对 Alex 需求的理解 + 优先级判断。给 CC 一个**带方向但不带手铐**的起点。
> 写「我理解你要做 X，关键看 Y，注意 Z」，不写「你必须用 A 方案」——留给 CC 工具澄清后自己判断。

- **目标**：<我理解这个任务要达成什么>
- **关键点**：<最该关注/最容易出错的地方>
- **优先级/边界**：<这次做什么、明确不做什么>

## 2. 相关记忆（Alex 的偏好 / 历史决策 / 已知陷阱）

> 来源：本地 memory + SuperMemory。把跟本任务相关的偏好、过往决策、踩过的坑摘进来。

- <偏好/决策/陷阱 1>
- <偏好/决策/陷阱 2>
- （无相关记忆则删除本段）

## 3. 知识库路标（OB vault 里相关内容在哪）

> 「相关内容在 X、Y、Z，你可能会用到」——给路标，不搬全文，让 CC 自己按需读。

- `<OB 路径或 [[wikilink]]>` — <为什么相关>
- `<repo 路径 / 文档>` — <为什么相关>
- （无则删除本段）

## 4. Skill 建议（建议用哪个 + 验收标准）

> 来源：Hermes 本地 skill 列表（+ 必要时 CC 本地 / WRR 搜 GitHub）。建议而非强制，CC 可在澄清后推翻。

- 建议用 `<skill 名>`，因为 <理由>；验收标准 <Y>
- （无则删除本段）

## 5. 约束与红线（不可触碰项）

> 已知的硬边界。**验收契约（criterion/threshold/risk/auditor）单列在委派包**（SKILL.md §5.1），
> 本段只放红线；可执行任务在澄清达成共识后、执行阶段仍需附委派包 criterion。

- 🚫 不可：<kill-session / 删文件 / git push / 生产部署 / 改架构方向 …>
- ⚠️ 用量：<天花板预估 / 提醒敲 /usage>
- 📋 验收契约：见本文件末尾委派包（criterion 必含，否则不准发送）

## 6. 澄清指令（先查证，再讨论，别直接执行）⏸️

> 这是 `discuss-first-snippet.md` 的**增强版**——不只是「复述理解」，而是「先用只读工具查证，再讨论」。

**在动手写任何代码/文件之前，请按以下顺序做，然后停下等我确认：**

1. **读任务简报**（上面 1-5 段）。
2. **用工具查证理解**（澄清阶段**只读、不写**）：发现任何不明确的点，**不猜测，用工具查**——
   - 背景知识/技术方案 → WRR `web-research-router` 联网搜
   - Alex 的历史决策/偏好 → SuperMemory + 本地 memory 检索
   - 过往讨论 → `session_search` 翻历史会话
   - 项目文档/日记 → OB 知识库检索
   - 现有代码/架构 → 读本地 repo + CodeGraph
3. **形成「我的理解 + 执行方案」**，逐问对齐（grill 节奏）：用 2-4 句复述理解（目标/产物/约束），
   列关键决策点（你打算怎么做、哪些不确定或有多走法需我拍板），**每个决策点带你的推荐答案**。
4. **发起讨论**：「我的理解是 X，方案是 Y，Z 点需要你确认」。若查到的信息与简报矛盾，**立即指出**
   （「你说的 X，我在代码/记忆里查到的是 Y，哪个对？」）——可以反向拷问 Hermes。
5. **停**。达成共识前**不要**写文件/改代码/跑改动性命令。等我回复「确认」或「按 X 调整」后再进入执行阶段。

> 硬性要求（保存到文件、测试覆盖、产物路径等）请在复述时一并确认你接收到了。

>>> 粘贴止 <<<

## 与现有协议的关系

- 本模板对应三段协议**节点①（发任务前讨论）**的强化版（SKILL.md §3 in-turn wait）。
- 简化版 `discuss-first-snippet.md`：只「复述理解→停」，不调工具。**简单任务用简化版，复杂任务用本模板。**
- 验收契约（委派包 criterion/threshold/risk/auditor）单列，见 SKILL.md §5.1——与本模板**分离但配套**。
- 只读约束、停下等确认都是 **convention**，不靠脚本强制（同 Pitfall #8、节点①）。
