## What cc-tmux Has That V4 Doesn't (Advantages)

| cc-tmux Feature | V4 Equivalent | Advantage |
|----------------|---------------|-----------|
| **mkdir atomic lock** (`/tmp/cc-lock-${TARGET}`) | No lock at all | V4 has zero concurrency protection. cc-tmux prevents parallel CC collision. |
| **Zombie lock auto-clean** | N/A | If CC is force-killed, lock dir persists. cc-start.sh detects and auto-cleans. V4 would wedge forever. |
| **Heartbeat file** (`/tmp/cc-heartbeat-${SESSION}`) | Prose-only "every 30-60s" | Mechanical proof of monitoring. cc-finish.sh rejects if stale. |
| **State log JSONL** (`/tmp/cc-state-${SESSION}.log`) | None | Full audit trail of CC states. cc-finish.sh reports state sequence + transitions. |
| **Relay contract** (`===📡 BEGIN/END===`) | Prose-only template | Hermes agent told to relay stdout verbatim. No formatting ambiguity. |
| **Hard gate on monitoring gap** (exit 2) | Prose red line ① | Script-level consequence for silence. V4's red line has no teeth. |
| **6-state machine** (SHELL/WAITING_AGENTS/IDLE/TOOL/THINKING/STARTING) | 3 ad-hoc signals | Crash detection (SHELL), worker stall (WAITING_AGENTS), token freeze tracking — all automated. |
| **Token freeze detection** (>120s WAITING_AGENTS, >180s THINKING) | Manual observation | Script detects frozen workers/thinkers that V4 requires human to notice. |
| **Session collision guard** (PID suffix) | None | Same-minute same-target collision prevented. |
| **tmux failure rollback** (lock released on start failure) | None | V4 leaves lock dir orphaned on start failure. |
| **Dangerous pattern detection** (rm -rf, git push in residual) | Partial (Pitfall ★28) | Script-level detection vs prose warning. |
| **Density-based compliance scoring** | count ≥ 1 | eval-compliance.sh requires ≥1 report per 120s. Single report in 30-min session = fail. |

## Design Principle Validation

The core bet — "scripts do enforcement, prose only tells which script to call" — is validated:
1. **Obligation count**: 80+ → ~7 per turn. LLM attention is finite.
2. **Mechanical teeth**: 5 hard enforcement points vs 0 in V4. Prose cannot enforce.
3. **Graceful degradation**: Bypassing scripts still works (manual tmux), just less safe. No wedge.
4. **Size ratio**: 34% of V4's prose, but more actual enforcement.

## When to Use Which

| Scenario | Use |
|----------|-----|
| Quick single-task, Hermes can do it | Neither — Hermes does it |
| Heavy multi-file work, need safety | **cc-tmux** (lock + heartbeat + hard gate) |
| Need CQI event tracking | V4 claude-code (JSONL emission) |
| Need full pitfall reference | V4 claude-code (39 items) |
| Need tmux-bridge MCP | V4 claude-code |
| Parallel multi-CC (rare) | **cc-tmux** (collision detection + --ack-active) |
| Agent team with full alignment gate | Either — discussion protocol is in both |
| Maximum safety for critical work | **cc-tmux** (mechanical enforcement > prose) |
