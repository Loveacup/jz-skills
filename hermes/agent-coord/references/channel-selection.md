# 通道选择：选择通道而非抹平差异

> 本文只做通道的定位与准入判断；任何通道的操作命令、门控与恢复细节，以该通道 skill／原生随版本文档的现行版本为准，冲突时以通道现行版本为准。通道能力缺口一律标「未验证/受限」，不用文档描述补齐。

## 基本原则

- **一个业务任务同一时刻只有一个决策控制者；一次执行尝试只有一个生命周期控制通道。**不同子任务可由不同通道执行，父级仍由 Hermes 汇合。
- 通道的「成功」只证明其合同覆盖的事实；不能假设各通道有同样的消息、取消、隔离与恢复保障。
- 「有启动命令」不等于有取消、送达证明、问答、恢复、审计或资源治理能力。
- 准入对**所有通道用同一标准**，按证据分级，不按品牌分级。

## 准入核对

**五维准入（每通道逐项核对）**：

1. 原生支持：该通道当前版本确实声明支持所需 CLI/任务形态。
2. 目标宿主安装：执行宿主上确实可用（版本可查）。
3. 认证可用：所需认证在现地有效。
4. 实际投递/执行：有过真实投递与执行证据，不以界面回显充数。
5. 产物与生命周期闭环：产物可回收、尝试有可回读的终态。

**按需保障核对（任务需要什么才核对什么）**：问答、停止、接续/恢复、证据留存、权限/资源限制。缺失就限制该场景使用，不必阻塞其他已验证场景。

## 各通道定位（一段定位＋指针，不复制操作正文）

- **Orca — 优先验证底座**：优先用于其原生可承接的多 CLI、项目/worktree、依赖、消息与监督任务。操作权威见本机随版本文档（`skills get orchestration` 及其 references）。已验证范围有限（特定小任务链路）；复杂工程、全 CLI、无人值守未验证——不外推。注意其原生语义边界：accepted/enqueue 不等于完成或已读。
- **cc-tmux（终端交互通道，非 Orca 的合法路径之一）**：需要 tmux 终端交互能力时的合法通道；使用时引用其 SKILL.md 现行真实门控，不用裸 tmux 冒充等价。保障边界：其 marker/watcher/sleep 等补偿机制仅约束该通道自身，不叠加到其他通道；投递成功证据分层等限制以其现行文档为准。
- **call-omp（受控 RPC）**：仅使用现地已核实的工具权限与资源边界。**受限项（原样引用）**：其 supervisor 文档与现地脚本不一致，重新准入前须核对，不能宣称文档声称的资源硬保护当前生效。verdict 方法可作为验收参考吸收。
- **Hermes Kanban（持久任务通道）**：派工与生命周期以 `hermes kanban` 原生命令为准。硬规则：
  - **派工必设上限**：每张会启动 worker 的卡都带 `--max-runtime` 或 `--max-retries`，让超时/失败走原生计数与熔断，不靠 stale 阈值兜底。需要取消留证的卡用 `dir:` 或 worktree 工作区（`archive` 会删除 scratch 工作区）。
  - **运行中的卡不得 `block`**，也不在 Dashboard 拖动运行中卡片。
  - **取消且不替换：用 `hermes kanban archive <id>`**。archive 在同一事务里把卡置为终态 `archived` 并释放 claim，之后才终止 worker，dispatcher 不会再派发它；`dir:` 工作区保留，worktree 只在干净且提交已推送时删除。不要用 `reclaim` 或 `reassign … none --reclaim` 做取消：reclaim 先提交 `ready`（审阅 run 为 `review`），`reassign` 再用第二个事务取消指派，中间可被 dispatcher 重新认领；`kanban.default_assignee` 非空时未指派的卡也会被自动派发。
  - **需要换新 attempt 时，也先 archive 旧卡**：协调者不用 `reclaim` 做重派。worker 退出后 dispatcher 会在同一 tick 回收并重新派发 `ready`/`review` 卡，而 worker 另起会话的子执行可能仍在写。顺序固定为：archive 旧卡 → 停掉子执行 → 确认下两条的停写证据全部成立 → 新建一张卡承接（在正文或评论里引用旧卡 id 与旧 attempt 身份）。任何一步证据不全就不建新卡，停止并升级人工。
  - **子执行另行停止**：archive/reclaim 只向记录的 worker PID 发信号，不覆盖 worker 另起会话的子执行（实测 call-omp 受监督的 OMP 进程树在 reclaim 和 archive 后都仍在运行）。这类子执行须用其通道自身的停止命令（call-omp 用 `omp-stop.sh` 加 SEND 身份），并用 `ps` 回读确认已退出。
  - **终止事件不等于旧 worker 已停**：读 `archive_worker_termination`/`reclaimed` 事件，并用 `ps` 回读 `prev_pid`。`prev_pid` 不存在或为 `Z`，或存活进程命令行不含 `work kanban task <id>`（PID 已被复用），才算已停。若仍存活且命令行含 `work kanban task <id>` 与 `-p <assignee>`，即使事件写着 `terminated: true`、`pid_recycled: true`，旧 worker 仍在写：卡已是 archived 不会重派，按该命令行核实后只向这个 PID 发 SIGTERM 并回读退出，核实不了就升级人工。已知成因：常驻 gateway/dashboard 里的 psutil 在系统时钟跳变后会调整进程启动时间，与新 CLI 进程算出的指纹不一致，Hermes 因此误判 PID 已复用、不发信号。
- **其他通道**：按公开合同与实际能力准入，走同一五维核对；未核实项标「未验证」。

任何通道不是任何角色的必要条件；「必须经某品牌通道」不是本层规则。选 Orca 之外的通道只需满足同一准入标准并声明保障边界。

## 跨通道切换 6 步顺序（原则收录，不是租约服务）

1. **冻结**：旧控制者停止新增派发与跟进写指令；记录切换原因、旧尝试 IDs、授权与待办。
2. **回读**：读旧通道/host 回执，处理未决问题、未确认投递与结果不明的请求；用原生身份查证，不盲重放。
3. **保全**：在可确认的安全检查点保全成果（diff、必要 untracked 内容、报告、消息证据），扫描秘密后持久化。
4. **停写证据**：取得旧 writer 已停止/已失去写入能力的**正向证据**。超时、abandon、终端不在列表、子代理结束都不单独构成证据。
5. **交权与新尝试**：新控制者确认同一交接包版本；新通道另建原生尝试并显式绑定前任与新权限。
6. **旧方只读**：原控制者退为只读，不双重发送。

状态未知时不派第二个重叠 writer；不靠换目录/换品牌绕过原限制。多个协调会话并存时，文档时间戳不是锁：没有可证明的独占机制或用户明确串行交接就暂停。
