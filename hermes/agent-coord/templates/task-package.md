# 最小任务包模板

> 以下字段是**上层文档约定，不是任何原生 API 字段**；原生 ID 不伪造、不跨通道复用。
> **小任务一段即可**（覆盖：目标、输入、允许/禁止、输出、验收、停止条件），复杂任务才扩成下表。
> **运行状态不在本包内维护**：只记录原生定位指针与最后观察时间，状态每次从所选通道原生回读；本包不设任何自维护生命周期枚举。

## 小任务（一段式示例）

> 目标：〈做什么、交付什么〉。输入：〈产物路径 @ 版本〉。允许：〈写面/动作〉；禁止：〈边界〉。输出到：〈位置〉。验收：〈可观测标准〉。停止条件：〈何时停并上报〉。问题发回：〈返回入口〉。

## 复杂任务（按需扩表，用不到的行删掉）

### 目标与身份

- **目标/角色**：交付物、承担角色（执行/研究/独审……）
- **专业 skill 引用**：〈skill 名＋适用局部要求〉（引用，不复制正文）
- **契约与授权**：业务任务标识、契约 revision、锚点来源、授权依据

### 输入与边界

- **输入产物与版本**：〈路径〉 @ 〈revision/sha256〉（逐项）
- **允许动作**：〈逐项：编辑/stage/commit/……〉；**禁止动作**：〈逐项〉

### 控制与工作区

- **控制者与通道**：唯一决策控制者；所选通道及其**原生定位指针**（Run/Task/Dispatch 或 session/request 等原生 ID）＋**最后观察时间**
- **host / allowed_paths 及 owner**：执行宿主、允许路径；workspace / execution / Git writer / document 四类 owner 分别记名
- **Git（适用时，否则标 not-applicable）**：base SHA、branch、逐动作 Git 权限、集成目标

### 交付与收口

- **输出位置**：〈消费者可访问的路径〉
- **验收**：〈可观测标准，绑定契约 revision〉
- **停止条件**：〈命中即停并上报的情形〉
- **有界预算**：〈时间/费用/轮次上限；无数值则标未知，不默认无限〉
- **问题返回入口**：〈向谁、经何处提问与回报〉
