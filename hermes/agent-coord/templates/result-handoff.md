# 结果 / 交接模板

> 文件承载成果，消息传递变化：先落盘产物、核对校验，再发本交接。**关键交付不覆盖旧版本**——新结果用新版本路径，旧版保留。

## 交接正文（小结果一段即可，逐项对应）

- **归属/版本**：任务标识、契约 revision、producer/attempt；产出对应的输入版本
- **产物引用**：〈路径〉 @ 〈revision/hash（关键交付时）〉；路径须对消费者可访问，跨宿主注明传输与完整性验证方式
- **摘要**：结论与关键变化（短摘要，不贴全量日志、不转述整段聊天）
- **证据**：测试命令/结果、审查记录、原生回执定位等（引用，不复制全文）
- **缺口**：未完成项、已知限制、待裁决问题；缺失如实列出，不补造
- **下一步**：建议动作与接续入口

## 四类事实分别留证（不互相替代）

| 事实 | 证据形式 |
|---|---|
| 消息接受 | 所选通道的入队/ack 回执定位 |
| 文件存在 | 产物路径＋（关键交付）hash |
| worker 完成 | 通道原生终态定位（保留原生事实，不改写） |
| 业务验收 | Hermes/指定验收者的独立核对结论 |

- 消息 ack 只是 inbox 处理确认；worker 完成只是交接；均不等于业务验收通过。
- 生命周期 succeeded 可与业务 blocker/stale 并存；按契约最新适用版本验收，旧版结果标 superseded/待重验。
