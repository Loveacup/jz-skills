# CQI Instance 模式 — Skill CQI 计划从「独立厚计划」重构为「母计划实例」

> 2026-06-04 CC CQI Plan 修订实战验证。5 轮讨论 → 273 行成稿。

## 何时用

一个 skill 的 CQI（持续质量改进）计划已经自己长成了独立厚文档——自创了六维模型、日志金字塔、门禁体系、角色职责表——但体系里已有 [[skill-authoring 持续质量改进计划]] 母计划定义了统一框架（四平面/七阶段/四分类/P01-P12/5-way gate/EP-1~EP-5）。

**信号：** CQI plan 行数 >200、有自创指标体系、与母计划从未交叉引用、Kanban 可行性方案的「待回写文档」清单漏列了它。

## 模式

### 三步走

1. **实证先行**：实测当前真实状态（hash/行数/文件存在性），不依赖文档自报。用一个 `md5` + `wc -l` 就可能推翻整篇「全✅」。
2. **继承接口对照**：逐条列出母计划接口（四分类/P库/七阶段/5-way gate/EP/D2真相源/Phase 1 五件套/四平面），标注当前文档是「平行自创」还是「已对齐」。
3. **三桶分流**：旧文档的所有缺陷/条目分流——
   - **命中现有 P** → 一行引用，不重复
   - **skill 专属** → 详述，是实例存在的理由
   - **新通用模式** → 回写母计划 §2.2

### 8 节骨架

```
§0  定位与继承声明（继承接口清单 + 作废声明 + 角色映射）
§1  真实状态快照（诚实基线 —— 取代旧「全✅」）
§2  去分叉方案（Phase 0，待执行 —— 解决方案，不顺手修）
§3  Skill 专属缺陷登记（三桶分流 + 详述）
§4  裁判面（skill 独有特性 —— 如递归审计悖论）
§5  真相源落地（继承 D2 + Kanban §11 schema）
§6  路线图（对齐母计划 Phase + skill 特有 Phase 0）
§7  回写母计划清单
§8  执行履历（保留真实史料 + 按实证修正旧版错误结论）
```

### 铁律

- **不在写文档时顺手「修复」再自报已修**（杜绝 RA-13 重演）。方案写在文档里，执行另起。
- **每个声称必须有 artifact**（hash/行数/文件路径/命令输出）。不写「已验证」「已通过」这类无锚表述。
- **文件名不变**（保其他文档的 wikilink 不断），仅在 frontmatter aliases 加 instance 标识 + 标题副标注明实例关系。
