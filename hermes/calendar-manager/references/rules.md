## 日历账户归属规则

- 日历已从原来的 iCloud 迁移到 `<redacted>` 的 iCloud。
- 用户已确认：**带 `1` 的这组日历是新账户日历**。
- 所有 Calendar.app 查询、创建、修改、去重、归档操作，默认只操作以下实际显示名称：

## 医疗类日程规则

### 触发关键词

脱敏、门诊、牙医、眼科、皮肤科

### 处理逻辑

1. 判断是否已有预约时间
   - 有具体时间 → 直接创建
   - 仅说"要去看病" → 询问："是已预约还是需预约？"
2. 自动添加备注：携带就诊卡/电子医保码
3. 默认提醒：提前 1 天
4. 预估时长：脱敏治疗自动设为 3 小时

### 脱敏治疗特殊规则

- **地点：** 浙江大学医学院附属儿童医院滨江院区 1 号楼二楼（A区）
- **日历预估时间：** 3 小时
- **必填备注：** 携带就诊卡/电子医保码

### 医疗事件示例

```
🏥 脱敏注射-Naomi
时间：2026-01-05（周日）09:30
地点：滨江儿保 1 号楼二楼 A 区
备注：携带就诊卡/电子医保码
提醒：提前 1 天
```

## 全天事件 vs 时间事件

### 判定规则

| 输入特征 | 判定结果 | 处理 |
|---------|---------|------|
| 含具体时间（14:00、下午 3 点）| ⏰ 时间事件 | 创建带时间的日程 |
| 明确全天（全天、一整天）| 📅 全天事件 | 创建全天事件（0:00-23:59）|
| 节假日类（休业式、寒假开始）| 📅 全天事件 | 创建全天事件 |
| 仅日期无时间（10 月 1 日）| ⚠️ 询问用户 | 询问时间类型 |

### 无时间询问格式

```
"下周网球课" 没有具体时间，请问：

[ ] 时间待定 → 备注标注"⏰ 时间待定"
[ ] 全天事件 → 创建全天事件（0:00-23:59）
[ ] 补充时间 → 请告诉我具体时间
```

## 重复事件规则

### 识别关键词

| 关键词 | 循环类型 |
|-------|---------|
| 每周 X、every Friday | 周循环 |
| 每月 X 号、monthly | 月循环 |
| 每天、daily | 日循环 |
| 工作日 | 周一至周五循环 |

### 处理流程

```
识别到重复关键词
    ↓
询问用户："这是一次性还是周期性事件？"
    ├─→ 一次性 → 创建单次事件
    ├─→ 每周重复 → 创建周循环
    └─→ 自定义周期 → 询问具体规则
    ↓
检测是否有结束条件（"持续一个月""到 6 月底"）
    ├─→ 有结束条件 → 设置结束日期
    └─→ 无结束条件 → 备注标注"持续进行"
```

### 结束条件处理

| 输入 | 处理 |
|------|------|
| "持续一个月" | 计算开始日期 + 1 个月作为结束日期 |
| "到 6 月底" | 设置结束日期为 6 月 30 日 |
| "10 次" | 设置重复次数为 10 次 |
| 无结束条件 | 在备注中添加"持续进行"标注 |

## 冲突处理规则

### 冲突检测

在创建新事件前，查询目标日历同时段是否已有事件。

### 冲突类型

| 冲突类型 | 定义 | 处理 |
|---------|------|------|
| 时间重叠 | 新事件与现有事件时间有交集 | 询问用户 |
| 完全相同 | 标题+时间+地点完全相同 | 自动合并 |
| 同名异时 | 标题相同但时间不同 | 询问用户 |

### 询问用户选项

```
❗️ 时间冲突检测：
目标日历在此时段已有事件：
• 2026-02-05 17:00 网球课-Naomi

请选择处理方式：
[ ] 替换 → 删除旧事件，创建新事件
[ ] 保留 → 保留旧事件，忽略新事件
[ ] 合并 → 合并两条信息
```

## 信息合并 vs 拆分规则（2026-02-05 新增）

### 判断逻辑

| 场景 | 判断 | 处理方式 |
|------|------|---------|
| **完全重复**：标题 + 时间相同 | 同一活动 | 合并备注信息 |
| **不同活动**：标题明显不同（如"休业式" vs "烘焙活动"） | 不同活动 | **询问用户** |
| **时间冲突**：时间段重叠但不同 | 不同活动 | **询问用户** |
| **同一活动补充**：对已有事件的细节补充 | 同一活动 | 将备注合并到已有事件 |
| **新活动 + 旧备注**：新活动的相关信息在旧事件里 | 同一活动 | 提取旧备注合并到新事件 |

### 合并流程（同一活动）

```
发现重复事件
    ↓
判断为【同一活动】（标题相同或同一活动的细节补充）
    ↓
    ├─→ 提取旧事件备注（如"烘焙活动"）
    ├─→ 与新信息合并
    ├─→ 删除旧事件
    └─→ 创建合并后的新事件
```

### 拆分询问流程（不同活动）

```
发现不同活动（如"休业式" + "烘焙活动"）
    ↓
❓ 询问用户：
"检测到两个不同活动，是否合并为一个事件？"

[ ] 合并 → 创建一条事件，合并标题和备注
[ ] 拆分 → 创建两条独立事件
```

### 不同活动合并示例

**场景**：已有"🎂 烘焙活动"，用户新添加"📚 休业式"

**询问**：
```
❓ 检测到两个不同活动：
• 📚 休业式（8:20-11:10）
• 🎂 烘焙活动（寒假班最后一天）

是否合并为一个事件？
[ ] 合并 → 📚 休业式 + 🎂 烘焙活动
[ ] 拆分 → 创建两条独立事件
```

**合并结果**：
```
📚 休业式 + 🎂 烘焙活动
时间：2026-02-06 8:20-11:10
备注：
• 带回学校物品（见详细）
• 烘焙活动（寒假班最后一天）
```
