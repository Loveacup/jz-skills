# CC Audit Findings — 2026-06-03

Full audit report for morning-news-briefing v4.0. Read alongside SKILL.md.

## P0 — Skill Loading (Three Gates)

1. **Gate 1: Scan path mismatch** — `morning-news-briefing` is a top-level bare directory. The loader only scans leaf entries inside classified directories (e.g., `apple/`, `productivity/`). Bare top-level skill dirs are invisible.
2. **Gate 2: Platform readiness** — `platforms: [macos, linux]` is compared against delivery platform (cron/telegram), not OS. Always mismatches → `readiness_status: unsupported`.
3. **Gate 3: Missing dependency** — `jobs.json` references `news-assembly` skill, but it only exists at `productivity/news-assembly` in global skills, not in cron-worker profile.
4. **Smoke guard missing** — When "could not be found" is injected, agent proceeds without alerting.

## P1 — Content Structure

- **今日要闻 layer not rendered**: Both LOCKED templates lack `{{今日要闻}}` placeholder. Parser doesn't produce 今日要闻 HTML.
- **MARKET_GRID hardcoded empty**: `render_pdfs.py` sets `{{MARKET_GRID}}` to `""`. Data exists in lane-mixed.json but isn't used.
- **Anti-hedging gate failed**: 4 instances of `可能` in final output. No rejection triggered.

## P2 — TTS

- Actual: single segment, 225 chars. Expected: three-segment (摘要→分析→总结), 800-1500 chars.
- Output path: `~/.hermes/audio_cache/` (wrong). Expected: `workspace/output/morning-news-{date}.mp3`.
- Not pipeline-driven: called after render error as ad-hoc patch. No `tts-script-{date}.txt` produced.

## P3 — Execution Mode Gap

- Mode B (Kanban Swarm) requires gateway dispatcher → unavailable in cron.
- Mode A (shell background parallel) not implemented.
- Current execution is single-threaded linear LLM call.

## Fix Priority

1. P0 first — all other fixes depend on skill being loaded
2. P1 Market snapshot — independent, data-ready, quick win
3. P1 今日要闻 + P2 TTS — requires P0 first
4. P3 — documentation cleanup last
