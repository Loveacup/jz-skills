# 早新闻 URL 质量教训 — 多轮稽核实录

> 2026-05-19 · 47条新闻精选18条，经四轮御史稽核

## 常见 URL 违规（按频率排序）

| 问题 | 出现次数 | 典型表现 |
|------|---------|---------|
| 年份错误 | 1轮全量 | 全部15条标2025年，应为2026 |
| 无URL仅来源名 | 1轮全量 | 17条全无链接，不可验证 |
| 跨条目URL复用 | 2+轮 | #13/#15同源，#7的2/3链接与其他条目重复 |
| 声明代URL | 1轮 | "经搜索验证"不为URL |

## 预防措施（应入子 Agent 任务定义）

1. **年份校验**：任务 body 中显式写"日期必须为当前年份"  
2. **URL 格式强制执行**：要求每个来源提供完整可点击 URL，不接受来源名称
3. **独立来源约束**：明确写"每个 URL 必须为独立来源，不可与其他条目复用"
4. **时效窗口**：标注 24-48 小时的时效窗口

## 多次稽核的容忍边界

经4轮稽核后仍可能有小瑕疵（如来源声明写"央视"实为新浪但URL正确），这些属于 MINOR 级别，可在输出中注明但不阻断。判断标准：URL 正确 > 声明文字精确。

## 四轮稽核时间线

```
轮1: 年份全错(A) + 无URL(B) + 声明代URL(C) → 全部返工
轮2: URL复用(A) + 时效超窗(B) → 返工A/B
轮3: 同源复用(A) + #7独立来源不足(B) → 精确修复
轮4: PASS（1条MINOR：来源声明失准但URL正确）
```

**关键教训**：子 Agent（hanlinyuan gemini-2.5-pro, planner kimi-k2.6）在 URL 质量上反复出现同类错误。应在任务定义中加入显式的 URL 质量要求，而非期待 Agent 自行遵守。
