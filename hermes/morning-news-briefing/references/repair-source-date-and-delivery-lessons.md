# 早新闻修复来源日期与交付完整性教训

## 场景

早新闻链路进入御史复稽后，常见阻断不是大范围事实错误，而是精准修复阶段引入的新问题：替换来源时使用旧年份页面、把转载页误当独立来源、或门下交付只整理新闻正文而漏掉分析 artifact。

## 教训

1. **修复来源前先验证年份**
   - 每个替换 URL 必须检查页面发布日期/正文年份。
   - 2025 或更早页面不得作为 2026 当日新闻证据，除非该条明确是背景资料且另有当日双源支撑。
   - 御史复稽应把“URL可打开”与“URL年份匹配”分开检查。

2. **不同域名不等于独立来源**
   - 若转载页正文标注“来源：新华社/新华网/央视”等，它与原始来源不构成独立双源。
   - 媒体名应按页面真实署名标注，不能把转载站误标成新华社。

3. **精准修复不要全量重写**
   - 先列阻断条目编号、原问题、需要替换的来源字段。
   - 只修被阻断条目；未涉条目不得改写，避免引入新错误。
   - 修复报告应写明每个条目的旧源、新源、年份、独立性判断。

4. **最终交付必须合并分析 artifact**
   - fan-in 正文通常只含新闻与来源，分析卡可能在另一个 workspace。
   - 门下交付卡 complete 前必须检查最终 Markdown 含 `### 🔍 分析` 与 `### 📌 今日总结`。
   - 若缺失，读取分析 workspace 并合并；这属于交付封装，不是太子亲自分析。

## 复稽 checklist

- [ ] 每个修复条目仍有 ≥2 个独立来源。
- [ ] 替换 URL 年份/日期与新闻时效匹配。
- [ ] 转载来源署名未被当成独立原始来源。
- [ ] 没有跨条目 URL 复用。
- [ ] 最终交付件含新闻正文、分析、今日总结、来源清单。
- [ ] 修复报告列明旧源→新源与判断理由。
