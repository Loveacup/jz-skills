# 外部项目取经与评估流程

多 profile 体系吸收外部开源项目的方法论参考。用于评估 GitHub 项目是否值得整合。

## 流程（内治九步精简版）

```
监国接旨 → 中书拟制 → 门下封驳 → 尚书派工 → 六部施行 → 御史监察 → 门下复核 → 监国复命
```

1. **监国接旨**：父皇分享 GitHub URL，要求评估
2. **中书拟制**：确定评估维度——项目定位/核心概念/技术架构/对多 profile 体系的可吸收性
3. **门下封驳**：审方案（是否需要全量 clone / 是否只需 README）
4. **尚书派工**：delegate_task（toolsets=["terminal","web"]），令子 agent 获取 README + 中文总结
5. **六部施行**：子 agent 执行 curl + 分析
6. **御史监察**：验交接字段、越界检测
7. **门下复核**：审内容是否覆盖关键维度
8. **监国复命**：对比分析表 + 吸收建议优先级 + 请父皇定夺

## 评估输出模板

```markdown
### 📊 [项目名] 评估

星数 | 协议 | 语言 | 定位

核心价值：一句话

| 吸收项 | 优先级 | 成本 |
|--------|--------|------|
| 具体点1 | 🔴高 | 低 |

结论：适合/不适合。原因。

建议：下一步行动。
```
