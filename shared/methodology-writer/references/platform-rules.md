# 平台适配规则

## 适配总则

1. **完整版是母版**：所有平台版本从完整版派生，不独立创作
2. **内容完整性优先**：语法转换不能丢失信息，只改展现形式
3. **引用不可缩减**：任何平台版本都必须保留完整的来源索引
4. **适配是转换不是删减**：Mermaid 图变成文字描述，不是直接删掉

## Obsidian 知识库版

**支持全部语法**，是完整版的默认格式。

格式要素：
- `> [!type]` callouts（abstract、info、tip、warning、quote、important、note）
- `==高亮==`
- `[[wikilinks]]`
- Mermaid 图表（flowchart、sequence、timeline、graph）
- `$$LaTeX$$` 数学公式
- `[^1]` 脚注
- YAML frontmatter（status、type、priority、aliases、tags、related、created、modified）

YAML 注意事项：
- `related` 中的双链必须用引号：`related: "[[笔记名]]"`
- tags 不能有空格，用 `-` 或 `/` 连接
- 禁止 YAML 中使用 `#` 行内注释

## 微信公众号

**支持**：加粗、斜体、引用块、有序/无序列表、标题（h1-h3）、图片、超链接
**不支持**：表格（部分客户端）、代码块语法高亮、Mermaid、LaTeX、脚注

适配规则：
| 原始元素 | 适配方式 |
|----------|----------|
| Callout `> [!tip]` | `> **提示**：内容` |
| `==高亮==` | `**加粗**` |
| Mermaid 图 | 截图为图片嵌入，或文字描述 |
| LaTeX 公式 | 纯文字：`输出质量 = 意图清晰度 × 规范完整度 × 上下文丰富度` |
| 表格 | 转为列表格式 |
| `[^1]` 脚注 | `[1]` 行内标注 + 文末参考列表 |
| `[[wikilink]]` | 删除 |

额外要求：
- 段落更短（手机阅读，每段 2-4 句）
- 小标题更密（每 200-300 字一个小标题）
- 开头必须有"钩子"（数据冲击/故事/反直觉结论）

## 知乎

**支持**：Markdown 基本语法、表格、代码块、LaTeX（部分）、图片
**不支持**：Mermaid、callout、wikilink、脚注

适配规则：
| 原始元素 | 适配方式 |
|----------|----------|
| Callout | `> 内容`（标准引用块）|
| `==高亮==` | `**加粗**` |
| Mermaid 图 | 截图嵌入或文字描述 |
| `[^1]` 脚注 | `[1]` 行内标注 + 文末参考 |
| `[[wikilink]]` | 删除 |
| 表格 | 保留（知乎支持） |

额外要求：
- 知乎读者偏好"为什么"型内容，加强论证部分
- 开头可保留完整摘要

## AI 发电社区

当前社区分享版的默认目标平台。后续扩展其他社区平台时，以此为基准参考。

**安全假设**：仅支持标准 Markdown 基本语法。

**支持**：加粗、斜体、标题、列表、引用块、链接、代码块（无高亮）
**不支持**：表格、Mermaid、LaTeX、callout、脚注、高亮

适配规则：
| 原始元素 | 适配方式 |
|----------|----------|
| Callout | 加粗标题 + 标准引用块或普通段落 |
| `==高亮==` | `**加粗**` |
| Mermaid 图 | 纯文字描述流程 |
| LaTeX 公式 | 纯文字 |
| 表格 | 转为结构化列表 |
| `[^1]` 脚注 | `[1]` 行内标注 |
| `[[wikilink]]` | 删除 |

**表格转列表示例**：

原始表格：
```markdown
| 要素 | 核心问题 | 日常类比 |
|------|----------|----------|
| Spec | 我到底要什么？ | 装修设计图 |
| Test | 怎样算达标？ | 验房清单 |
```

转换后：
```markdown
- **Spec（想清楚）**：核心问题——我到底要什么？日常类比：装修前的设计图纸
- **Test（定标准）**：核心问题——怎样算达标？日常类比：验房时的检查清单
```

## 扩展其他社区平台

添加新平台时，按以下模板补充：

1. 确认平台的 Markdown 支持范围（支持/不支持列表）
2. 编写语法转换规则表（原始元素 → 适配方式）
3. 记录平台特有的额外要求（如读者偏好、段落长度、开头风格）
4. 以 AI 发电社区的规则为基准，只记录差异项

## 引用系统适配

### 完整版（Obsidian）

使用 `[^1]` 脚注语法，文末集中定义：
```
正文中[^1]的引用。

[^1]: 来源完整信息。
```

### 平台版（通用）

使用 `[1]` 行内标注 + 文末参考列表：
```
正文中[1]的引用。

## 参考来源
[1] 来源完整信息。
```

分类体系保持不变：正文引用 [1]-[N]、网络来源 [W1]、公开数据 [D1]、学术论文 [A-1]、专家观点 [E1]。

## 适配检查清单

- [ ] 目标平台不支持的语法已全部转换
- [ ] 转换过程中无信息丢失（图表→文字描述，不是删除）
- [ ] 引用系统完整（正文标注 ↔ 参考列表一一对应）
- [ ] 段落长度适配目标阅读场景（手机/桌面）
- [ ] YAML frontmatter 适配目标系统（如 Obsidian 需要特定字段）
- [ ] 无残留的原始格式语法（如社区版中不应出现 `==` 或 `> [!tip]`）
