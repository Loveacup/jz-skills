# 拓扑模板：星型（单编排 + N 执行）

> 角色槽位模板。`<...>` 是绑定时由 goalgen 填的槽位（参与者不写死，每次可变）。对齐方法论 03 §3.2（Contract Net announce→bid→award→contract→report）。

## 元信息
- topology: `star`
- role_bindings:（组队绑定结果，每条 `{role, cli, model, effort, work_mode, driver_skill?}`）
  - `{ "role": "orchestrator", "cli": "<编排者CLI>", "model": "<model>", "effort": "<effort>", "work_mode": "<mode>", "driver_skill": null }`
  - `{ "role": "executor", "cli": "<执行者CLI>", "model": "<model>", "effort": "<effort>", "work_mode": "<mode>", "driver_skill": "<驱动skill或null>" }`  ×N
- gate_modes: `{ "gate_default": "<human|auto|hybrid>", "per_gate": { "audit": {...}, "publish": {...} } }`
- driver_skill 提示：若执行者由编排者驱动（跨 CLI），从 cli-registry 的 `cross_cli_drivers[(编排者→执行者)]` 取；编排者须加载该 skill。

## Goal 骨架（19 字段）

```text
# Goal（星型）：<objective 一句话>

## 拓扑声明
star；编排者=<role/CLI>（不亲执，单点发布权）；执行者×N=<role/CLI 列表>；
通信基质=<inbox 文件队列 / HTTP /v1/runs / tmux PTY>。

## roadmap_node（P7 溯源，必填）
<映射的 roadmap 节点 id 或裁决引用；映射不出来不得生成>

## 终止条件（P6）
当全部 N 个工作单元 report 回汇且逐项验证命令全通过、归档完成时完成；触发升级时暂停。

## 角色分工（不可互换 P4；身份由 role_bindings 现绑）
- 编排者：announce 派单、汇总、唯一持发布权；不进入执行者边界。
- 执行者×N：仅在各自 scope 边界内执行，禁互相派单、禁发布。

## 每个工作单元的派单（announce，必带 P1/P2/P7）
- scope：includes=<...> / excludes=<...>
- acceptance_criteria（验收，每条三元组）：
  - { criterion: "<可裁决判定>", verifier: "<test|review|demo|inspection>", threshold: "<阈值>" }
- forbidden（deny list）：<非 publisher 自动注入 git commit/push/tag/...>

## report 回汇（P3）
执行者回汇必须是证据句柄（文件路径 + exit code + diff ref）；编排者凭句柄复算，不信自报。

## 确认门（gate_mode）
- audit 门：<human=人审 / auto=独立 auditor 凭证据裁决，producer≠reviewer>
- publish 门：<human / auto=N票多透镜+留痕+单点发布权隔离+block-on-uncertainty>

## escalation（升级出口 P6）
- mode: <human|auto>；triggers: <同一单元打回2次 / 不可逆操作 / 验收不可验证>
- auto 不达共识 → block + 留痕
```
