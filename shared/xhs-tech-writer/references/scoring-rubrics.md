# 选题评分体系 Reference

本文件汇总 xhs-tech-writer 的全部选题评分与过滤规则。所有选题在进入写作前，必须依次通过：硬门槛过滤 → 24h 新鲜度核查 → 禁区检查 → 信源评估 → 五维评估 → 三维预测打分。

---

## 五维选题评估 (Pre-write Gate)

5 条评估维度，每条给出"是/否"判定。综合得分决定是否值得写。

### 1. 是不是新工作流或新入口（而不只是新功能）

- 它改变了用户的做事方式，还是只是多了一个按钮？
- 是否创造了之前做不到的新场景？

### 2. 普通人能不能立刻理解它的影响

- 不需要专业背景，一句话能说清楚"它对我有什么用"
- 用户听完会不会有"这也行？"的反应

### 3. 有没有反常识点

- 是否存在与大众直觉相反的结论
- 能否制造"以为是这样，其实是那样"的认知差

### 4. 有没有明显风险、边界或不适用人群

- 什么人会踩坑
- 什么条件下会翻车
- 有没有隐藏代价（时间、金钱、隐私等）

### 5. 这个话题是不是已经被讲烂

- 搜索确认，如果满屏都是同类内容，说明红利期已过
- 能否找到一个还没被覆盖的缝隙角度

### 判定规则

- 5 条中 ≥3 条"是" → 值得写
- 5 条中 2 条"是" → 勉强能写，需要很强的切入角度
- 5 条中 ≤1 条"是" → 不值得写，直接拒绝

### 输出格式（值得写时）

- 结论
- 一句话判断（15 字内）
- 目标群体
- 最推荐切入点
- 3 个备选切入点
- 5 个标题
- 最容易写废的地方

### 输出格式（不值得写时）

- 结论
- 理由
- "如果一定要写，唯一可能的角度"

## 用户场景过滤 (硬门槛, Must-pass Before Scoring)

每个候选选题必须回答："用户读完这条会想干什么？"

只有以下答案能通过：

| 答案 | 选题归类 | 例子 |
|---|---|---|
| 想立刻试 / 想推荐给朋友 | 分享型 | Claude 操控 PS/Blender、49 个 AI Agent 搭工作室 |
| 想存起来回头看 | 收藏型 | Karpathy 金句、10 年设计经验压成一个文件 |
| 想发评论说话（有情绪点） | 评论型 | Manus 代码进 Meta 仓库（争议+八卦） |
| 答不出来 / 读完没下一步动作 | ❌ 直接砍 | OpenAI 做手机、Cerebras IPO、Google 75% 代码 AI 写 |

### 13 条已发数据复盘

综合分前 6 名都明确属于以上三类之一，倒数 5 名全部是"答不出来"。

## 24h 新鲜度核查铁律

- 必须是 24 小时内的新信息，过时的不选
- GitHub Trending 高星不等于新（11 万星项目大概率老的，今日新增 +N 只说明今天被翻红，不是首发）
- 任何 GitHub 项目入选前必须查 first commit / release 时间
- 任何 "X 早就出了" 能打的题，直接砍

---

## 选题禁区 (Direct Ban List)

以下类型不论其他维度多优秀，一律直接砍：

- **估值 / IPO / 融资类**（如 Cerebras IPO 综合分 182 但 0 评论 0 分享，纯靠阅读量充数）
- **政策 / 诉讼类**
- **纯产品发布**（"X 公司发了 Y" 但没说"你能拿它干嘛"）
- **没有可验证细节的"计划中"事件**（如"OpenAI 据说要做手机"）
- **工程师小工具但非工程师无法脑补使用场景的**（GitHub Trending 80% 是这类）

## 三维预测评分 (Prediction Scoring, Fill at Generation)

每篇生成时必填三维分（1-5 分），作为后续数据反馈的对照基线。

### 点击力

标题+封面能不能在信息流里赢冷启动？（1=普通陈述 5=必停）

- 加分项：数字反差 / 熟悉品牌的意外动作 / 情绪冲突

### 收藏力

内容是否值得用户存起来回头看？（1=看完就忘 5=必收藏）

- 加分项：可复用工具/方法/资源/金句

### 争议分享力

能不能激发"想说话"或"想推荐给朋友"？（1=看完没反应 5=必转/必评论）

- 加分项：争议点 / 八卦情绪点 / "我也想试"的产品案例

### 评分纪律

诚实打分，不要全打高分。如果点击力 5 但收藏力 2，老实写。打分目的是校准预测能力，全打 4-5 分等于没打。

### 综合分公式（用于后续反馈对照）

```
综合分 = 阅读 × 1 + 赞藏 × 10 + 评论 × 100 + 分享 × 50
```

## 三类内容的传播路径

13 条数据真实分布：

- **分享型**靠分享拉分（Claude 操控 PS/Blender 综合 #1）
- **评论型**靠评论拉分（Manus 进 Meta 综合 #2）
- **收藏型**靠赞藏拉分（Karpathy 综合 #3）

### 选题优先级

```
分享型 > 评论型 > 收藏型 >>>>> 其他全部砍
```

## 数量与类型分布原则 (Anti-padding Rule)

**质量 > 数量 > 类型分布**：

- 不强求每天 3 篇 / 4 篇固定数量——日报里有几条够格就出几条
- 不强求三种类型各占一篇——3 篇全是分享型 OK，3 篇全是评论型也 OK
- 宁可少出一篇，不为凑数硬选不达标的题
- 执行过程发现某选题过不了"用户场景过滤"门槛，自主替换，无需请示。说明理由即可
