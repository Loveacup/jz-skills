# 钩子与标题库 Reference

本文件是 xhs-tech-writer 在生成小红书 AI/科技笔记时的"标题与钩子"参考手册。所有规则、公式、范例都围绕 AI/科技领域内容设计，可直接被复用、改写、组合。

## Section 1: 标题规则总览

小红书标题是搜索入口，也是首屏点击的唯一抓手。AI/科技类内容尤其要兼顾"可被搜到"和"让人想点"两件事。

**硬性规则：**

- 字数：≤20 字（英文每两个字母按一个汉字计算）
- 必须包含：情绪词或数字（至少一个），最好两个都有
- 核心搜索关键词放在前 8 个字以内（Claude / GPT / Cursor / Agent / MCP 等）
- 同一标题不要塞超过 2 个产品名，否则读者认知过载

**禁止项：**

- 纯陈述句（例：`AI 编程工具介绍`）
- 低质营销号词（震惊！太牛了！绝绝子！YYDS！）
- 公众号腔（浅谈 / 几点思考 / 浅析 / 漫谈 / 杂记）
- 标点滥用（连续多个感叹号、问号、省略号）
- 玄学夸张（颠覆认知！改变世界！终结一切！）

**判断一条标题是否合格的三问：**

1. 用户在搜索框里搜某个关键词时，能不能搜到我？
2. 用户在信息流里 0.5 秒扫过去，会不会停下来？
3. 这条标题如果被截图发到群里，会不会被转发？

## Section 2: 五大标题公式

### 2.1 悬念型

**定义：** 通过"反转 / 意外 / 后悔 / 没想到"制造信息缺口，迫使用户点开补全。

**何时用：** 发现类内容、踩坑总结、隐藏功能、横评反转结论。

**AI 范例：**

- `测了 6 个 AI 模型做同一件事，只有第 3 个没翻车`
- `用 Claude 自动化办公一个月后，我后悔没早点这么干`
- `Cursor 这个隐藏功能，第 2 个我用了三个月才发现`

**反例：** `AI 工具好用吗`（没有悬念，没有钩子，纯陈述）

### 2.2 列表型

**定义：** 以明确数字承诺信息密度，让读者预判收益。

**何时用：** 合集、推荐、方法论、技巧清单。

**AI 范例：**

- `5 个让 ChatGPT 听话的 prompt 技巧`
- `3 个免费 AI 编程工具，第 2 个国内能直连`
- `49 个 AI Agent 搭出来的虚拟工作室长这样`

**反例：** `一些 AI 工具推荐`（没有数字，没有钩子，"一些"是劣词）

### 2.3 对比型

**定义：** 用 A vs B 结构放大差异，调动好奇心。

**何时用：** 效果展示、模型横评、工具对比、付费 vs 免费。

**AI 范例：**

- `用 AI 写小红书 vs 自己写，结果差了 3 倍互动`
- `Claude 3.5 vs GPT-4o 做同一道编程题，差距让我惊了`
- `花 200 美金 vs 0 元，跑同一个 Agent 工作流`

**反例：** `AI 编程对比`（没有具体场景，没有量化结果）

### 2.4 故事型

**定义：** 用第一人称 + 时间锚点 + 具体动作，把读者拉进现场。

**何时用：** 实战分享、亲身体验、复盘类内容。

**AI 范例：**

- `我用 Claude Code 一周做了 3 个上线产品`
- `被一个 AI Agent 折服后，我重写了所有工作流`
- `用 GPT-5 跑了 100 条数据后，我看到了一些反常识`

**反例：** `关于 AI 编程的思考`（无故事、无主语、无场景）

### 2.5 反常识型

**定义：** 直接挑战共识，强制读者验证是否同意。

**何时用：** 信息差揭露、共识颠覆、行业内幕、专家观点搬运。

**AI 范例：**

- `别再让 ChatGPT 帮你写文案了`
- `99% 的人不知道，Claude 其实可以这样调用 MCP`
- `Karpathy 说大部分人用 AI 的方式都错了`

**反例：** `AI 用法分享`（无颠覆点，没有立场）

## Section 3: 钩子库（用于第一句话和正文开篇）

**第一句话法则：** 用户划走一篇帖子只需要 0.5 秒，第一句话必须让人停下来。AI/科技类内容尤其忌讳"背景铺垫"，第一句直接进入冲突、数据或场景。

### 3.1 痛点钩子

**用法：** 开头直接戳一个具体痛点，越具体越好——用户脑子里会自动浮现"对，我就是这样"。

**AI 范例：**

- `每次让 AI 写代码，都要复制粘贴 5 次上下文，烦死了`
- `团队 5 个人花 3 小时开会，最后只产出 1 页纪要`
- `用 Cursor 一个月，账单 200 刀，但只用上了 30% 的功能`

### 3.2 反常识钩子

**用法：** 开头抛出一个与共识相反的结论，让读者下意识想反驳，然后被正文说服。

**AI 范例：**

- `GitHub 上最火的 AI 项目，居然不用写一行代码`
- `AI 最大的问题不是太强，而是太弱`
- `跑分最高的开源模型，实测连最基础的指令都跟不上`

### 3.3 故事钩子

**用法：** 开头进入一个具体场景，配合时间戳和动作，把读者拉进画面。

**AI 范例：**

- `昨晚 11 点，我让 Claude 自己改了一个 PR，今早合进了主分支`
- `周五下午开始用 AI 自动化客服，周一早上发现工单堆了 800 个`

### 3.4 数据钩子

**用法：** 开头直接抛硬数据，数据越具体（带小数点、带时间）越可信。

**AI 范例：**

- `Karpathy 昨天发了条推，409 万人看了，说的是 AI Agent 的最后一公里`
- `OpenAI 内部数据：模型新版本平均每周节省工程师 11.4 小时`
- `测了 6 个 AI 编程工具的实际响应延迟，最快的比最慢的快 17 倍`

### 3.5 好奇心缺口

**用法：** 开头抛出一个"为什么"或反问，让读者带着问题往下读。

**AI 范例：**

- `为什么 90% 的 AI Agent 项目跑 3 天就停了？`
- `Manus 的代码到底进没进 Meta 的仓库？`

## Section 4: 标签策略（3-5 个）

**组合逻辑：** 大流量词负责曝光、中等词负责精准触达、精准词负责长尾搜索。三层结构缺一不可。

**层级配比：**

- 1 个**大流量词**：`#AI` / `#人工智能` / `#ChatGPT` / `#科技`
- 1-2 个**中等词**：`#AI工具` / `#效率提升` / `#开源项目` / `#AI编程` / `#提示词`
- 1-2 个**精准词**：`#Claude` / `#GPT5` / `#Cursor` / 具体产品名 / 具体作者名

**避免：**

- 与正文无关的蹭流量大词（笔记讲的是 Cursor，却挂 `#美妆`——会被限流）
- 全是大词（覆盖面太广，反而无法被精准用户搜到）
- 全是小众词（没有流量入口，新账号尤其吃亏）
- 重复同义标签（`#AI` + `#人工智能` + `#AI技术` 等价于一个标签）

## Section 5: 收尾句法

收尾是决定"收藏 / 点赞 / 评论"动作的临门一脚。AI/科技类内容尤其要避免说教味。

**好的收尾**（三选一，不要全用）：

- **留悬念：** `但真正让我好奇的是，这件事三个月后会变成什么样`
- **回扣开头：** 开头讲了一个场景，结尾用同一个场景的变体收束（结构闭环）
- **抛出真实困惑：** `说实话我也没想明白，这到底是好事还是坏事`

**禁止的收尾：**

- `你们觉得呢？` / `评论区聊聊` / `关注不迷路` → 营销号味
- `以上就是今天的分享` → 教科书味
- `希望对你有帮助` / `希望大家都能…` → AI 总结味
- `点赞收藏不迷路` / `三连支持一下` → 求互动太硬

## Section 6: 封面文案

封面文案在信息流里比标题更早被看到，必须能"独立成立"。

**硬性要求：**

- 封面文字 ≤15 字（手机屏小，字多了看不清）
- 必须有一个视觉焦点（最大那行字 / 关键数字 / 关键人物）
- 文字要能独立传达核心卖点（即使不点开也知道在讲什么）
- 字体对比要明显（大号主标 + 小号副标，不要全部一样大）

**AI/科技类常用结构：**

- **数字+词：** `5 个 Claude 隐藏指令`
- **反差对比：** `花 200 刀 vs 0 元`
- **人物+动作：** `Karpathy：90% 人用错了`
- **工具+场景：** `Cursor 一键改 PR`

**封面 + 标题协作策略：**

- 封面讲"最抓人的那一点"，标题讲"搜索关键词 + 完整钩子"
- 两者不要完全一样（重复浪费曝光位）
- 封面用大白话，标题可以更克制
