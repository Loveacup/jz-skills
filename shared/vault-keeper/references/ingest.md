# ingest 判定规程（agent 的 AI 判断部分）

> 配套 `engine/ingest.py`（确定性写盘）。本规程是 agent 在调 ingest.py **之前**要做的判断。
> engine 不做判断，判断在这里。对应方法论 §二十一。

## 第一步：先读意图（purpose）
建/更新某区的页前，先读目标区根的 `_purpose.md`（该区"收什么、不收什么、成熟标准"）。无则按 `ROUTER.md` 分流语义。借鉴 llm_wiki purpose/schema 二分。

## 第二步：两步 CoT（先想清楚再动笔，质量高于一步生成）
**Step 1 · 结构化分析**（一次推理，产出六小节，落 `01-Staging/.analysis/SRC-….md` 留痕）：
1. **评分** 0–10（9-10 突破 / 7-8 高价值 / 5-6 有趣 / 3-4 低 / 0-2 噪声）+ 理由
2. **领域过滤**（AI / 知识管理 / 方法论 / 商业 / 心理… 白名单；分 <6 或越界 → 记 `reject` 日志后停）
3. **核心实体与概念**
4. **与现有 core 的冲突 / 呼应**（逐条对照；检出矛盾 → 标记送 §二十五 裁决）
5. 每实体一句话摘要
6. 建 / 更新页建议（标题、sources、ai_self 自评 0–1）

**Step 2 · 写盘**：对每个实体调
`python3 $VK/ingest.py --title "<实体>" --summary "<摘要>" --sources <SRC...> --ai-self <0-1>`

## 质量铁律（承 v1.7 §12.3「智能分析 ≠ 机械填充」）
抽取须是**有判断力的合成**——点出与已有知识的冲突 / 呼应 / 增量；**禁罗列填表、禁原文换行复制**。无判断力的填充页拿不到连接度 / 密度分，confidence 自然不足以晋升。"先分析后落笔"正是为逼出判断而非堆砌。
