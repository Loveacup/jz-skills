# 方法论判断规则参考

本参考提取自《Obsidian x AI 方法论 v1.6》中的判断逻辑。Obsidian 库的 `CLAUDE.md` 定义了"库级规范"（什么能做什么不能做），本文件聚焦于**执行判断**（怎么做得好）。

---

## 文件命名

文件命名规则见 Obsidian 库 `CLAUDE.md` 的「文件命名规范」章节。核心原则：
- 永恒型笔记：文件名 = 最常用称呼，英文/变体放 aliases
- 事件型笔记：`类型_主题_YYYY-MM-DD.md`
- 过长/不清晰/不当的文件名应根据内容重命名

## YAML Frontmatter Schema

### 五维元数据模型

> 文件所属区域（00-Inbox、10-Projects、30-Resources 等）由文件夹路径决定，不再使用 `class` 字段。

```yaml
---
# 管理维度
status: 常青                 # 必填 | 见下方"各区域 status 对照"
type: 概念                   # 必填 | 单个中文词
priority: 正常               # 选填 | 正常|重要|紧急

# 内容维度
aliases:                     # 必填 | 2-4 个（缩写、中英互译、口语化）
  - 别名1
  - English Name
tags:                        # 必填 | 3-5 个，四维分面体系
  - type/概念
  - status/常青
  - src/原创

# 关联维度
related: "[[相关笔记]]"       # 选填 | Obsidian Links 类型

# 元数据维度
created: 2026-02-18 12:00
modified: 2026-02-18 12:00
---
```

### 属性类型对照（Obsidian Properties 原生类型）

| 字段 | Obsidian 类型 | 说明 |
|:-----|:-------------|:-----|
| `status` | Text | 种子/树苗/常青/归档 |
| `type` | Text | 概念/人物/方法论... |
| `priority` | Text | 正常/重要/紧急 |
| `aliases` | Aliases（内置） | 影响 wikilink 匹配和搜索 |
| `tags` | Tags（内置） | 影响标签面板、搜索和 Dataview |
| `related` | Links | 可选，YAML 中用 `"[[笔记名]]"` 格式 |
| `created` | Date & Time | `YYYY-MM-DD HH:MM`，支持日历排序 |
| `modified` | Date & Time | `YYYY-MM-DD HH:MM`，支持日历排序 |

### YAML 禁忌

- 禁止行内注释 `#` — YAML 会解析错误
- 裸双链语法 `[[]]` 必须用引号包裹 — `related: "[[笔记]]"`（Links 类型）
- 冒号后必须有空格 — `type: 概念` 而非 `type:概念`
- 特殊字符必须用引号包裹 — 如含冒号、井号等

### 各区域 status 对照

| 区域 | status 可选值 | 说明 |
|:-----|:-------------|:-----|
| 00-Inbox | 待处理、已分类 | 收件箱处理状态 |
| 01-Staging | 待审核、已审核 | 配合 `reviewed: true/false` |
| 10~40 P.A.I.R | 种子、树苗、常青、归档 | Zettelkasten 四阶段 |
| 50-Self | 闪念、树苗、常青 | 自我认知沉淀程度 |
| 99-System | 常青 | 系统配置通常稳定 |

## 四维标签体系

**金科玉律**：标签描述"笔记是什么"（属性），不是"笔记讲什么"（内容）。

### Tags 语法规则（Obsidian 原生约束）

- **合法字符**：字母（任何语言）、数字（不能开头）、下划线 `_`、连字符 `-`、斜杠 `/`（嵌套）
- **禁止**：空格（用 `-` 或 `/` 连接）、特殊字符 `# @ ! ? . , ; : ' " ( ) [ ] { }`
- **嵌套示例**：`psych/concept`、`type/永久`、`src/原创`

### 四个维度

| 维度 | 前缀 | 问题 | 示例 |
|:-----|:-----|:-----|:-----|
| 类型 | `type/` | 笔记的形态是什么？ | `type/概念` `type/永久` `type/会议` |
| 状态 | `status/` | 笔记的成熟度如何？ | `status/种子` `status/常青` |
| 来源 | `src/` | 信息从哪里来？ | `src/对话` `src/视频` `src/原创` |
| 主题 | `topic/` | 属于哪个大类？**极度慎用** | `topic/技术` `topic/商业` |

### type/ 可选值速查

**Zettelkasten 流程型**：`闪念`（24-48h 必须处理）、`文献`、`永久`、`索引`
**内容型**：`概念`、`案例`、`工具`、`实验`
**会话型**：`会议`、`对话`、`访谈`
**其他**：`方法论`、`教程`、`提示词`、`人物`

### src/ 可选值速查

`对话` | `会议` | `阅读` | `播客` | `视频` | `剪藏` | `原创`

### topic/ 可选值（仅 4 个，不能扩展）

`topic/商业` | `topic/技术` | `topic/人文` | `topic/科学`

### 标签 vs 双链决策

```
遇到一个词
├─ 能写成一篇笔记吗？ → 是 → 用双链 [[词条]]
├─ 描述笔记的属性吗？ → 是 → 用标签 #维度/属性
└─ 都不是 → 写在正文
```

**错误示例**：用标签描述内容
```yaml
# 错误
tags: [MBTI, 认知功能, INFJ]
# 正确
tags: [type/概念, status/常青, src/阅读]
# 具体概念在正文用双链：[[MBTI]]、[[认知功能]]
```

**错误示例**：主题标签过度细分
```yaml
# 错误（标签沼泽）
tags: [topic/AI, topic/机器学习, topic/深度学习, topic/Transformer]
# 正确（极简主题 + 双链）
tags: [type/概念, status/常青, topic/技术]
# 具体概念用双链：[[AI]]、[[深度学习]]、[[Transformer架构]]
```

## 精准匹配协议（双链规则）

### 三层过滤

| 层级 | 规则 | 示例 |
|:-----|:-----|:-----|
| 同名匹配 | 文中词汇与笔记文件名字面完全一致 | `[[卡尼曼]]` |
| 别名匹配 | 文中词汇是目标笔记的公认别名 | `[[Artificial Intelligence\|AI]]` |
| 零臆测 | **严禁**将描述性语句概括为概念 | "下雨" 不能链到 `[[天气现象]]` |

### 链接密度标准

| 笔记类型 | 最少 | 推荐 | 说明 |
|:---------|:-----|:-----|:-----|
| 概念笔记 | 3 | 5-10 | 原子化知识 |
| 人物笔记 | 3 | 5-8 | 理论家科学家 |
| 根 MOC | 10 | 50+ | 唯一导航中枢 |
| 文献笔记 | 2 | 3-5 | 读书摘要 |
| 提示词/命令 | 0 | 0 | 不需要双链 |

### 链接关系符号

```
→  支持 — 引用权威来源或支撑论点
⊕  补充 — 补充相关信息
⊗  反驳 — 对立观点
↗  延伸 — 概念延伸或应用
≡  定义 — 调用核心定义
⇄  类比 — 跨领域结构相似性
```

### 双链构建工作流（三阶段）

**Phase 1: 扫描与过滤**
1. 扫描正文，识别潜在实体（人名、书名、术语）
2. 过滤：剔除泛指词，仅锁定特定专有名词或精准术语
3. 严格执行三层过滤（同名 → 别名 → 零臆测）

**Phase 2: 嵌入与分离**
1. 正文中自然嵌入 `[[...]]`，不破坏句子结构
2. 同步记录每个链接的逻辑属性（支持/补充/反驳/延伸/定义/类比）

**Phase 3: 概念深链**
1. 寻找非显性的跨领域深层关联（类比关系、底层逻辑共性）
2. 重点关注高价值跨学科链接：
   - 心理学 ↔ 品牌营销（消费者行为、情绪价值）
   - 哲学 ↔ AI（认识论、伦理学）
   - 博弈论 ↔ 商学（谈判、竞争策略）
   - 自然科学 ↔ 哲学（时间、因果性）

### 页尾链接关系分析模板

每篇笔记末尾附加：

```markdown
---

## 链接关系分析

### 核心关联
- [[概念A]] `→` 支持核心论点
- [[概念B]] `≡` 定义关键术语

### 延伸阅读
- [[相关概念]] `↗` 延伸应用

### 跨学科链接
- [[领域A概念]] `⇄` [[领域B概念]] — 结构相似性说明

### 导航
- [[知识库MOC]] — 知识库根 MOC
```

### 双链质量控制 Checklist

每次编辑笔记后自检：

- [ ] **原文检查**：正文里只有 `[[Link]]`，没有任何 `(关系说明)` 括注？
- [ ] **匹配检查**：所有链接基于文中原词或精准别名？（拒绝模糊归纳）
- [ ] **语法检查**：嵌入链接后句子读起来依然通顺？
- [ ] **密度检查**：达到该笔记类型的最少链接数要求？
- [ ] **深链检查**：是否发现了跨学科的非显性关联？

## Callout 选型指南

| Callout 类型 | 场景 | 判断标准 |
|:-------------|:-----|:---------|
| `> [!NOTE]` | 一般性补充信息 | 不看也不影响理解 |
| `> [!TIP]` | 实用建议、快捷方法 | 能帮读者更高效 |
| `> [!IMPORTANT]` | 必须了解的关键信息 | 跳过会导致误解 |
| `> [!WARNING]` | 潜在风险、易错点 | 不注意会出问题 |
| `> [!DANGER]` | 严禁事项、破坏性操作 | 违反会造成损失 |
| `> [!ABSTRACT]` | 章节概要、摘要 | 用在章节开头 |
| `> [!QUOTE]` | 引用原文、名言 | 非自己的话 |
| `> [!INFO]` | 背景信息、上下文 | 提供理解框架 |

### Callout 折叠判断

- 默认展开：关键信息（IMPORTANT、WARNING、DANGER）
- 可折叠 `> [!xxx]-`：补充信息（ABSTRACT 概要、长引用、详细解释）
- 常折叠的：章节概要（让读者按需展开）

### 嵌套规则

Callout 可以嵌套，但不超过 2 层，否则影响可读性。

### 密度控制

**核心原则**：Callout 是强调工具，过度使用会降低效果。

**密度限制**：
- 短笔记（< 500 字）：最多 1-2 个
- 中等笔记（500-2000 字）：最多 2-4 个
- 长笔记（> 2000 字）：每 500-800 字最多 1 个

**必须使用的场景**：
- 关键结论或核心观点（NOTE / IMPORTANT）
- 安全警告或重要注意事项（WARNING / DANGER）
- 密集引用块（3+ 段引用时用 QUOTE）
- 行动建议或实用技巧（TIP）

**禁止使用的场景**：
- 普通段落内容（用**粗体**或==高亮==代替）
- 单句引用（用普通块引用 `>` 即可）
- 装饰性美化（Callout 必须有实际功能）
- 连续多个 Callout（相邻之间至少间隔 2-3 个段落）

## 内容保护规则

### 代码块中禁止双链

`[[]]` 在代码块中不会被 Obsidian 解析为链接，会显示为字面文本。

**正确做法**：在代码块外的说明文字中建立双链，代码块内用纯文本注释。

```markdown
# ✗ 错误
# ```python
# # 使用 [[递归算法]] 实现
# def fibonacci(n): ...
# ```

# ✓ 正确
这个函数使用了 [[递归算法]]：
# ```python
# def fibonacci(n): ...
# ```
```

### 参考文献保留规则

编辑或优化笔记时，**不得删除**参考文献和来源信息：
- 保留所有原始引用格式和内容（作者、年份、URL）
- 保持引用格式完整性（APA、MLA 等）
- 保留所有脚注和尾注
- 参考文献条目之间不留空行（紧密连续排版）

## 六大核心陷阱（防御性检查清单）

在编辑笔记时，检查是否触犯：

1. **AI 代写笔记** → AI 只做整理和连接，不代写内容
2. **不人工审核** → AI 产出经 01-Staging 审核后才整合
3. **过度依赖自动化** → 保持人工写作和思考
4. **忽略双向链接** → 每篇笔记 >= 3-5 个链接
5. **标签沼泽爆炸** → topic 标签 <= 5 个，细节用双链
6. **YAML 格式错误** → 严禁行内注释、双链、无空格冒号
