# 以人为本宣言

## 立场

以人为本，不是以某份量表结论为本。阅读主线是读者本人的自述、关切、选择与可尝试的行动；它不表示性格是恒量，不表示某种人格测量已经验证了一个人的全部特质，也不要求八字、紫微、占星去证明同一个人格结论。四个体系各自完整解读本体系的材料，再围绕读者的同一问题综合。人格资料可以是默认入口，但只是四个视角之一。命书可以保留诗性与传统文化语言，但必须区分计算事实、测量或自述、传统解释、心理假说和实践选项。

文中的「性格即命运」「命运密码」等只能作为文学表达，不可当作因果定律、个人预测或科学结论。出生资料可按已声明的方法生成传统盘面；从盘面到个体人格分数、功能栈、能力排名或经验置信区间没有本技能认可的推导规则。

## 性格资料的构念边界

`personality_input.construct` 只能按实际来源标为：

- `functions8`：直接提供的八功能分数；保留量表名称、版本、日期、原始分数和量程。分数描述该工具的作答结果，不等同于能力、行为频率或临床评估。
- `subtypes16`：16 亚型的分项原始分数；保留条目构念和原始量程。可按合同展示成对分差，不得把差值解释为能力、成熟度、置信度或八功能分数。
- `neris5`：16Personalities 的五维 NERIS 结果。该工具不分配 Jungian cognitive-function stacks；不得把五维或四字母类型换算成八功能分数、功能栈或雷达。参见 [16Personalities for AI](https://www.16personalities.com/for-ai)。
- `mbti_type`：用户自述或报告中的 MBTI 类型。只能讨论类型理论本身，须注明这是类型标签，不是八功能实测。
- `interview`：访谈中的具体自述与例子。保留原话或忠实摘要及其情境；访谈不能伪装成标准化测量。
- `none`：没有可用性格资料。不得由出生盘、关系资料、年龄或分析师直觉补造人格测量。

`instrument`、`version`、`test_date`、`scale_min`、`scale_max` 等元数据未知时保留 null，不猜测、不补齐。

## 多维分析与写作

先分别讲清各体系在本盘看见了什么、依据哪条推读路径、对读者的问题意味着什么、哪些条件会改变读法，再综合真实的联系、张力或不可比较之处，并说明综合增加了什么理解。各体系独立分析后综合；不得让八字、紫微、占星围绕预设的人格结论找印证，也不以跨体系一致性当作个体结论的可信度、概率或评级。

保留传统术语与文化意象时，说明它们是相应传统中的解释语言，并在该传统语境内完整解释，不把每条传统含义都改写成自我观察问题。不要把文化解释写成经测量的个人事实；不要用免责声明替代对读者问题的实质回应。好的性格分析应具体到适用情境，容纳相反例子，并在确有用途处给读者可以选择、观察、调整或停止的行动。具体的办法是写以“例如／如果”标明的生活镜像，并配一个带条件、能落空的反向情形，让读者自己判断像不像；它们是摆在读者面前的假设，不是替读者编写的经历。

## 发展与关系中的边界

Beebe 的原型位置与 Grip 可作为明确署名的理论镜头或反思提问，不是诊断、临床风险评估或由类型确定的行为预测。不得按年龄表推定个体必经的发展阶段，也不得把功能排序写成确定的成熟度阶梯。

已知人生事件可帮助理解读者正在问什么、检视叙事是否贴合；它们不自动校正出生时间，不作为预测命中率。出生时间只有新增出生记录或家人原始记忆等输入才能修订，修订须保留依据与候选差异。

未成年人采用适龄、非标签化表达：关系主题聚焦家庭、同伴、师长与个人边界；事业主题聚焦学习与兴趣；不描写未来婚恋对象、婚恋年份，不把类型说成能力缺陷。健康主题只回应读者主动提供的生活习惯、压力或求助问题，不从人格类型推疾病或诊断。面向家长的文字仅在受众明确包含监护人时提供，写观察与支持，避免标签化与控制性建议。
