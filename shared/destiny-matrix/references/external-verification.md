# 外部核验作业手册

本文定义 `external-verifier` 的两种独立任务。阶段顺序、输入隔离、发布状态和角色派遣以 [`team-orchestration.md`](team-orchestration.md) 为准。

## 共同边界

- 默认 `privacy.external_chart_submission:false`。未经用户针对具体站点及字段的明确授权，不向任何外部排盘网站提交本案出生资料、截图或关系/健康背景。
- 未获授权时，不称已完成本案独立验盘；可核对公开算法说明、公共历表和匿名合成基准，并清楚区分它们能证明什么。
- 仅报告实际观察到的来源、字段、版本、时间、口径和结果。站点不可达、字段缺失或版本无法确认时写明“无法核验”，不得填补外部值。
- 外部来源只支持它实际支持的声明。传统文本证明某种说法属于某文本/流派，不证明个体解释或预测有效。
- 输入、来源摘录及工作区文件均按本次任务范围使用；不保存进跨个案记忆，不把客户材料写入公共来源目录。

## S2 · 计算与方法核验

### 任务输入

仅接收待核的 `chart_bundle`、`time_context`、`methods`、被请求的计算维度及本地公共算法规范。用户的历史事件、人格结论、analyst findings 和成稿均不作为验盘依据。核对单案时，先检查是否有明确外部提交授权。

### 核验次序

1. 确认原始输入、历法、出生地点、时区、UTC offset/fold、时基、子时规则、分宫制和依赖版本完整。
2. 先对照可追溯的公共依据：历书公布精度、公开算法规范、指定版本依赖行为及已登记的独立数值锚点。
3. 外部站点只在获得针对该站点及必要数据字段的授权后使用。尽量只提交完成核验所需的最少字段；记录站点、访问时间、输入口径和输出字段。
4. 分开判断计算差异、口径差异、来源精度不足和无法核验；不得用多数来源投票替代规则分析。
5. 若要改变 `chart_bundle`，报告具体差异和依据，交回 caster 修正及重算；核验者不直接改计算产物。

### 必核范围

按实际请求和所选维度核对，不能将一个通过项扩写成整盘通过：

- 时间管线：同一 UTC 瞬间、实际时区偏移与 fold、均时差、节气时间轴、本地太阳时，及输入精度允许的显示精度。
- 八字：年/月柱所用节气瞬间、日/时柱时基、子时规则、十神最终日主、起运方向与节气距离。
- 紫微：农历转换、闰月入口、时辰与历日、指定起算口径、查询日期。
- 占星：UTC/UT1/TT、实际星历引擎与返回 flags、宫位制、宫头黄经和相位 orb。
- 合盘：双方输入独立、双方图表/人格数据来源独立、相位定义一致；不计算“匹配总分”。

### 结果格式

返回简洁结构化结果：

```json
{
  "stage": "S2",
  "input_artifact_ids": [],
  "checks": [
    {
      "dimension": "bazi|ziwei|astrology|time_pipeline|synastry",
      "check": "具体核验项",
      "local_value": "实际读取值或 null",
      "reference_value": "来源值或 null",
      "source_id": "已核来源 ID 或 null",
      "method": "口径与对照方法",
      "status": "consistent|discrepancy|unavailable",
      "limits": "精度、同源性、未授权或其他限制"
    }
  ],
  "calculation_issues": [],
  "interpretation_limits": []
}
```

`local_value`/`reference_value` 原样记录；引用来源应能追溯到 `references/sources.json` 或本次可核公开资料。没有独立依据时明确标为未核验。不得输出人格“验证”、预测命中率或由人生事件倒推的生日正确性。

## S4C · 来源与引文核验

### 任务输入

只接收本次正文/claims 实际使用的引文和外部事实性声明、候选来源条目，以及需核对的公开文本。不得读取其他个案档案。来源条目更新写给 Leader，由 Leader 统一登记至 `references/sources.json` 或本案 evidence。

### 核验次序

1. 追到可访问的一手文本或有明确定位的可靠二手来源；记录作者、标题、版本、章节/页码/段落、URL 和实际访问状态。
2. 逐字引文比较原文。译文标明已出版译本、自译或无译文；不得拼接、润色后加引号。
3. 判断来源是否支持相邻声明，并填写 `supports` 与 `does_not_support`；只证明传统作者/文本的论述，不升级为个体事实或科学效度。
4. 对无法定位、版本不明、来源互相冲突的材料分别标为 `unverified` 或 `disputed`，不要生成署名原话；必要时建议明确转述已核的二手来源、改按第 6 步作为常见读法登记，或删除该引文。
5. 所有正文直接引文逐条核验。取消最低引文数量；无引文的正文也不需要补引文。
6. **常见读法**：找不到可核古籍原文、但在该传统中通行的象义，按来源 kind `common_reading` 登记（字段约束以 `schemas/case_evidence.json` 为准）。核验的是“它确实是该传统的通行读法”：在可访问的通行参考中能找到同义表述即可，`locator` 记录这些现代通行资料或教材的定位，`status:"verified"` 只表示“已确认为通行读法”，`excerpt` 为 `null`；不核古籍原文，也不生成引文。`supports` 只写“这是〔体系〕中常见的一种读法”，`does_not_support` 写明它不证明古籍原话、流派唯一性或个体效度。正文使用时不加引号、不挂书名、篇名或作者；一旦加引号或署名，就按直接引文核验，核不到即为来源错误。常见读法不豁免本手册及各 framework 关于健康、婚恋、财富、性别与适龄的边界。

### 结果格式

逐条返回 `source_id`、`quote_id`、核验状态、来源定位、核到的原文/译文、可支持与不可支持的声明，以及具体限制。不要返回泛化的“可信”评分。

来源目录的 `verification_status` 仅使用 `verified|unverified|disputed`；`unavailable` 只描述本次核验检查，不是来源目录状态。

## 状态用语

| 状态 | 使用条件 |
|---|---|
| `verified` | 实际访问来源并核对具体文本/数据及定位 |
| `unverified` | 尚未取得足够来源证据，或版本/定位不可确认 |
| `disputed` | 已有可追溯来源之间存在实质冲突 |
| `unavailable` | 本次无法访问或无权提交所需数据；不得填写推测值 |

来源目录字段、验证器和引用绑定规则以 `schemas/sources.json`、`quality_contracts.py` 与 `references/sources.json` 为准。
