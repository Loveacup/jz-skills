# 多维分析与综合

## 原则：独立深读后，围绕同一问题综合

以人为本，不是以某份量表结论为本：综合从读者的问题与现实选择出发，不代表人格是恒量，也不要求八字、紫微、占星为预先给定的人格结论找印证。各分析师只依据自己负责的输入、计算结果、规则与来源，按本维 framework 的推读路径独立作读；综合者之后才比较结果。跨体系相似不构成测量效度、概率或个案事实的证据；相似只能增加叙事视角。

综合的产物是**新增理解**，不是四栏摘要：同一个问题上，各视角分别照见了什么，张力落在哪一层，合起来比任何单一视角多理解了什么。综合不做四维投票，不让某体系裁决另一体系。对于每条重要判断，明确它是自述/测量观察、计算事实、传统解释、心理假说还是实践选项；回链对应输入、计算 claim 或已核来源。传统解释依赖的盘面字段与规则要能追溯，但典籍来源只说明传统怎么说，不证明该说法对个人有经验效度。

## 综合顺序

1. **选主题**：从 intake 问题和独立 findings 选共同主题。完整书默认可涉及自我表达、学习/工作、关系、节奏；没有对应资料的主题不强拉四维参与。
2. **读清各视角的独立含义**：同一主题上，每个体系解释的是内在取向、角色/情境、资源关系还是时间结构，各自依据什么盘面或分数。不是把四个词翻译成同一个性格标签。
3. **形成综合判断**：指出各视角补充了什么、张力发生在什么层面、删去其中一个视角会损失哪一部分理解。说不出新增理解的主题，不包装成“命运密码”，如实写成并列阅读或留在各体系章节。
4. **登记主张**：把判断写入 `synthesis_claims` 并关联 `parent_claim_ids`。纯文化综合用 `traditional_interpretation`；涉及真实心理特点的 `psychological_hypothesis` 必须另有自述/观察依据；现实尝试用 `practical_option`。父 claim 的限制与反例在审计层对子 claim 继续有效，子 claim 不得比父 claim 更确定；这些限制不抄进子 claim 的 `statement`，也不因层层继承而累加成读者层限制（见下文“限制的两层”）。
5. **写进提纲**：`outline.sections[].required_content` 写出本章实际要解释的关系与新增理解，以及它回扣哪一条核心命题，而不是“放综合矩阵”。有现实资料时说明它如何影响读者的选择；没有时提供以“例如／如果”标明、带条件可落空的对照情境，不补写传记。`limitation_ids` 只收 `required_placement:"adjacent"` 的读者层限制，同一限制只进一个章节。

**全书核心命题**：完成各主题后，从 `synthesis_claims` 中提炼 3–5 条 `core_propositions`，每条是“意象（可空）＋带对象或条件的判断”，回链 claim。它是全书骨架：导读预告，各章回扣，综合章对照，结尾回到读者本人。合格的命题过不了换盘测试（换一张盘就不成立），不是口号（“做最好的自己”），不是命运公式，也不把意象升级为能力或命运结论（“严丝合缝”“三重印证”）。

无法比较时保留两套不同解释及其各自用途，不用“不可比”三个字结束讨论。文学标题可用；主文不用公式、命运评分或四体系投票。

## 综合矩阵（分析索引）

`synthesis.matrix` 是分析索引，不是综合章已经完成的证据。每个主题使用以下结构，不添加评分、百分比或因果关系：

```json
{
  "theme": "主题或问题",
  "personality_claim_ids": [],
  "bazi_claim_ids": [],
  "ziwei_claim_ids": [],
  "astro_claim_ids": [],
  "relationship": "parallel",
  "limits": []
}
```

`relationship` 仅可为：

- `parallel`：不同体系各自的描述可以并列阅读；不表示相互验证或因果。
- `tension`：解释角度或结论存在张力；保留两侧证据与适用边界，不强行统一。
- `not_comparable`：资料、构念或回答的问题不同，不能作直接比较。

缺少某维资料时不虚构对应 claim；字段可为空数组，并在 `limits` 写明适用性或缺口。不要用“解释力评级”“一致性百分比”“签名回扣”或其他量化外观替代依据。矩阵行只说明哪些 claim 被放在一起读，真正的综合判断在 `synthesis_claims` 与提纲的 `required_content` 中。

## 限制的两层

- **审计层**：`claims[].limits`、`counterevidence`、矩阵行 `limits`、判官与 chief 的差异措辞。它们保证可追溯，供评审和附录使用，writer 不原样渲染进正文。父 claim 的限制在这一层向子 claim 继承。
- **读者层**：`case_evidence.limitations[]` 中由 Leader 登记的条目。`changes_reading` 回答“删掉它，读者会不会形成一个具体误读或误用，或者某句结论会不会因此改变”；为 `true` 时写 `reader_text`（面向读者的正向或条件句，如“如果〔前提〕，这一节改读为〔Z〕”“这里说的是 X，至于 Y 要看……”），并按 `required_placement` 落在开篇（全书通用边界，建议不超过五条）或受影响判断旁；为 `false` 时只进附录。
- 综合者只在某条限制会改变读者对综合判断的理解时，提出读者层限制增量；其余限制留在审计层，不因继承而在正文重复出现。

## 主张的依据与分层检验

对核心主张按来源类别说明依据和边界：

- **自述或测量观察**：回链本人提供的观察、量表原始数据及工具构念；不从类型分数推出未经测量的能力或经历。
- **计算事实**：回链计算产物字段、输入口径、所用规则与必要限制。检验的是输入与方法：输入是否一致、规则是否声明、时刻不确定性是否改变结果。
- **传统解释**：回链相应计算事实及传统规则/来源；表述为该体系中的解释，不包装成经验事实或预测保证。检验的是取法：说明哪些盘面条件（如破格、流派取法差异、宫位边界）会改变这条读法。
- **心理假说**：回链具体自述/观察及采用的理论镜头；明确不确定性，不把它写成诊断。只有这一层讨论真实生活中的反例和待观察反馈。
- **实践选项**：回链相关主张，作为读者可选择、评估和调整的建议，不是结论的证明。

不要求每个判断都追加一段竞争解释或“尚无法检验”：计算事实核输入与方法，传统解释说明改变取法的条件，个体心理假说才讨论真实反例与待观察反馈。资料不足以检验某个个体假说时，在该假说的素材处写明缺口（是否写进正文由对应限制的 `changes_reading` 决定）；不得杜撰反例、访谈或确认事件。不同体系的张力不是错误本身；算法错误、错引来源、无支持推断则按证据纠正，不能以流派差异掩盖。

## 主题与行动

“命运密码”仅可作为文学小标题，不得写成由人格与星盘计算得出的公式、预测模型或因果定律。`ultimate_task` 从读者自己的目标、具体可观察的困难及其已有资源中形成，不强制归因于劣势功能、阴影或固定人格类型。Beebe 位置可作为署名理论镜头，不作为唯一解释来源。

每项 `action_options` 的数据字段固定为：

```json
{
  "goal": "为什么是这位读者：回链判断的一句话，再写希望改变或理解什么",
  "claim_ids": [],
  "small_action": "本周可启动的低风险小行动，含载体与时长",
  "frequency_or_trigger": "具体触发线索或频率",
  "review_question": "读者能回答的复盘问题",
  "adapt_or_stop": "无效、不适或条件变化时如何调整或停止"
}
```

行动按“因—行—判”组织：先写一句为什么适合这位读者（回链判断），再写触发线索、载体与时长，最后给复盘问题。触发线索写成具体情境（“下次你发现自己又替别人把事扛下来时”），不写“在你愿意时”。调整或停止条件可以按章共用，正文每章说一次即可。未成年读者至少配一句可以直接说出口的原话。六个字段是数据结构，正文由 writer 写成连贯段落，不原样渲染成小标题。

行动需可观察、可修改或停止，不以“提升某功能”“顺势而为”代替具体步骤，也不要求等到传统时间窗口才开始现实行动。若涉及计算时机，只能使用确已计算的粒度，并明确这是传统解释而非结果保证。

## 年龄与个体发展

固定年龄发展表、类型成熟度时间表和年龄对功能阶段的映射，不用于断言个人必经阶段、可塑性百分比或能力走势。年龄只作必要的语境信息，不能代替个人经历与观察。未成年人遵循 `character-inference-workflow.md` 的适龄规则；不得将成年人经验或婚恋阶段套写到儿童身上。
