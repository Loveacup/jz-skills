# 发布验收清单（destiny-matrix v5）

本文件是 book-finalizer 唯一清单。每份 `final_verdict` 必须对 I1–I3、A1–A3、R1–R3、D1–D4、P1–P3 各记录一次，合计 16 项。状态机与修订分流以 [`team-orchestration.md`](team-orchestration.md) 为准；字段结构以 `schemas/final_verdict.json` 为准，其中必填的 `reader_takeaways` 按下方“读者先行”写出。

## 逐项判定

| ID | 必须通过的行为 | 主要证据 |
|---|---|---|
| I1 | 用户请求、来源和受众清楚；scope 中每个请求均有成品落点或用户接受的限制。 | intake、问题清单、chart_plan section 与成品位置 |
| I2 | 日期、出生时刻精度、时区/历法、方法口径和数据完整性如实记录；关键不确定性出现在适当位置。 | `time_context`、计算方法、限制披露及相关正文 |
| I3 | 隐私、外部提交授权、年龄、minor_mode 与 audience 均遵守；未知值未被猜定，未成年隐私没有因受众默认外泄。正文不把想象写成当事人已经发生的亲历；以“例如／如果／假如你……”明确标出的假设镜像不属此列；标注词之后仍写成具体过去事件（有时间、地点或他人反应）的，按亲历虚构处理。minor_mode 下正文不把盘面、类型、分数或功能位置贴成能力缺陷、风险标签或人生限制，不写“你是……的孩子”式身份标签，关系/事业内容限于 `character-inference-workflow.md` §5 的适龄范围；监护人段写观察与支持，不写控制方案。 | intake 快照与外部任务输入、正文受众及相关限制、未成年人正文原句、镜像句的标注方式 |
| A1 | 正文、表格、图表与计算 artifact 的值、单位、精度和方法一致；精确数字可追溯到有效输入或计算结果。 | artifact hash/JSON Pointer、HTML 绑定、可见读者文本 |
| A2 | 直接引文与来源目录逐条匹配，定位和译文类型正确，来源实际支持相邻声明；无伪署名或无法追溯的事实性外部声明。正文以“传统上常见的讲法”“常见读法”措辞的句子，其 `data-claim-ids` 须回链到引用 `common_reading` 或已核 `traditional_text` 来源的 claim；否则按 A2 fail。 | `sources.json` quote/source ID、原文/译文及正文位置 |
| A3 | 用户事实、计算事实、传统解释、心理假说和行动建议没有越级。`changes_reading:true` 的读者层限制按 `required_placement` 出现在开篇或受影响判断旁（`adjacent` 就近一次，带 `data-limitation-id`）；审计层的反例、方法分歧与误差保留在 evidence 或附录，可追溯即可。分值写成事实断言（“你总是……”）判越级；带条件、可落空的反向情形不判越级；反向情形须有一支明确说出“这条读法在你身上不太贴合”，两支都归到本盘或本组分数某一项、怎么选都成立的，按冷读判 R1 fail。传统象义或心理假说落到“你”时，同句须保留传统声源标签（“在〔体系〕的读法里”“传统上常见的讲法是”）、假说标签或条件；删去即越级。通行象义以“常见读法”标明（来源 kind `common_reading`），无引号、无古籍署名。无诊断或事件保证。终审另须抽查审计层（`claims[].limits`、`counterevidence`、chief `disclose`、`changes_reading:false` 条目）：若删去其中一条会使读者误读已读到的正文结论，即为错标，A3 fail（`fix_type:"analysis"`，owner Leader：改标 `changes_reading:true` 并补 `reader_text` 与落点）。 | claim/evidence 回链、`limitations[]` 的 `changes_reading`/`required_placement` 与正文 `data-limitation-id`、judge/chief 结果、正文原句 |
| R1 | 每个已接受的用户问题及各体系的核心问题（本盘结构是什么、为何这样读、对读者意味着什么）均得到实质回答；没有以空章节、术语表、免责声明或“详见附录”替代正文回答。**人称命题**：终审能对每章用一句以“你／这张盘／这组分数”为主语的话复述“这里说了你什么”；只讲“这张盘该怎么读”的不算。**换盘测试**：把盘面或分数换成另一个人的，命题仍然成立（讨好式笼统描述，或不夸不贬但对谁都成立的空转）不算回答。 | intake 请求 → chart_plan → 正文位置的逐项覆盖；读者可复述的人称命题；`reader_takeaways` |
| R2 | 具体盘面、分数或自述如何进入解释可定位；综合章给出各视角分别增加的理解与合并后的新增理解，而不只是四份摘要或“相互呼应”；个体心理判断有合适的自述/观察支持，并在该层说明可改变判断的观察或缺口。计算事实按输入与方法、传统解释按取法条件审查，不要求每段追加反例或“尚无法检验”。 | claims 与父 claim、反例/限制、成品中逐条可定位的论述及综合段 |
| R3 | 现实建议的数据采用 `{goal,claim_ids,small_action,frequency_or_trigger,review_question,adapt_or_stop}`，低风险、可开始、可复核、可调整，也可以不做；不是空泛劝说或预测依赖项。**行动有因**：正文每条行动先说明为什么适合这位读者（回链一条判断），再给具体触发线索、载体与时长和复盘问题；调整或停止条件每章至少说一次；未成年读者至少有一句可直接说出口的原话。 | 对应行动选项、回链判断与正文实施说明 |
| D1 | 正文主题、必要披露、附录、顺序、IDs 与冻结 plan 一致；details 仅位于附录并有唯一 ID，必要限制不隐藏。必须核对本次 `validate_book.py "$WS/book.html" --plan "$WS/chart_plan.json" --evidence "$WS/case_evidence.json" --json` 为 `ok:true`，并将其确切输出 JSON 哈希附入 D1 evidence。怀疑误报只能 blocked 并报告工具缺陷，不能自行豁免。 | 冻结 plan、语义 DOM，以及本次 validator `ok:true` JSON 输出与 SHA-256 |
| D2 | 每个图表有核准计划、有效数据/claim 来源、正确单位与尺度；缺值未补零，坐标和实际显示数值准确。正文解释空间/周期结构时，图确实表达该结构（如十二宫地支格位、周期分面与单位），而不是可复述不出结构的装饰或把全部结构退成无关表格。图数本身不是标准。 | chart_plan 与 `planning_rationale`、HTML figure、SVG/表格和可见数值、正文与图的互指 |
| D3 | 篇章清晰、连贯并保有自然文气，正文段落满足下方“有效段落”八条；不设词频或句数门槛。 | 定位的正文段落、章节承接、`reader_takeaways` |
| D4 | 在实际浏览器桌面与 320–430px 窄视口阅读；键盘/链接可用，普通文字对比度至少 4.5:1、关键信息图形至少 3:1；文字和图表在最终渲染中可读（逐图确认字号，不只看 CSS 值）、可重排或局部滚动，无整页横移、裁切、遮挡、隐匿或颜色单独承载信息。正文内 `<details>`、隐藏元素、夹带内容的 HTML 注释任一存在即 D4 fail。 | 实际 viewport、对比度/设备宽度、可见性逐项检查、图表与内容块位置的视觉证据 |
| P1 | PDF 可解析且保留正文、必要披露、附录、表格单元格、引文、首尾和纯矢量图页内容；无丢块/未分类折叠内容。 | exporter JSON、文本提取清单、疑似/不确定页码 |
| P2 | 实际 PDF 分页、图表、长表、字体、书签和阅读顺序可读；正文不低于 12pt、表格信息不低于 9.5pt、图内信息不低于 9pt；无裁切、孤立标题或不能判定的块冒充通过。 | 真实 PDF 逐页/图表视觉检查、实测字号证据与书签导航 |
| P3 | 本次 PDF 与正在审核的 HTML、verdict 和导出记录哈希一致；产物路径和版本对应本次交付。 | HTML/PDF SHA-256、pre/post verdict 与 export JSON |

## 状态规则

- 每项 `verdict` 为 `pass|fail|na|deferred`，并记录 `evidence:{artifact,location,quote}` 与 `reason`。证据必须能让另一位终审者复定位，不用“整体良好”替代。
- `na` 仅用于该项确实不适用，并写出条件依据。D2 无图时，只有已批准的 focused 计划无合适图且核心数据表达完整，才可 `na`；不得因成品漏图而判不适用。无引文时 A2 仍需检查伪署名、来源需求和外部声明，不能直接 `na`。
- `deferred` 仅能用于 `pre_export` 阶段的 P1、P2、P3。其他缺少证据的项不得 defer 或视为 pass。
- `pre_export` 所有适用非 PDF 项通过且 P 组 deferred，decision 才能是 `awaiting_export`；此阶段不得是 `pass`。
- `post_export` 必须复核真实 PDF，P 组不得 deferred。只有 16 项全部 pass 或有依据的合法 na、无 blocker 且 HTML/PDF 哈希匹配时 decision 才能是 `pass`。
- 读者先行：R1/R2/D3 先只读读者稿，记录每章的人称命题、推读依据、综合增加的理解及图揭示的结构，并写出 `final_verdict.reader_takeaways`：3–5 句“读者读完能带走什么”，每句带对象或条件；然后才看 evidence 核对。复述不出回答或命题过不了换盘测试，按 R1 fail；综合只是四份摘要，按 R2 fail；写不出 `reader_takeaways` 时给空数组，R1 与 D3 同时 fail；免责声明替代解读，或“有效段落”某条在一章的主要论述中不满足（能定位到段落并说出读者因此失去了什么），按 D3 fail 并给 prose 修订指令；零星措辞瑕疵列 `recommendations`。“每段都有反例/边界句”或“限制写得多”都不是通过理由。A3 仍独立检查虚构、诊断、确定性和越级推断，文学性不能抵消 A3/I3 失败。

## 有效段落（D3 判定）

以下八条供终审逐章复述判定，不按字数、句数或词频计分。

1. **首句见物**：章首和长段首句是关于读者或本盘的判断；方法说明、限定或否认不作段首，章节标题与章末句不用否定式限定。
2. **声源可辨**：随手抽一句判断，从句子本身就能看出它属于事实、传统（含“常见读法”）、假说还是选项。传统象义落到“你”时，同句须保留传统声源标签或条件；删去即越级（按 A3 判）。
3. **否定有的放矢**：每个否定式限定都能指出它防的是哪一个读者很可能形成的具体误读；指不出的属冗余。
4. **术语自足**：同段新术语首现即释，读者不翻附录也能读懂本段结论。
5. **边界一次**：同一限制在正文只完整出现一次；开篇通用边界只在必要披露说一次，正文需要时用短从句回扣；省去的取法正文不宣布“未核／未采用”，集中在附录一处。
6. **读者语言**：流程词、数据字段和审计记录不入正文（词典见 `agents/book-writer.md` 文风第 10 条）；图注只写来源、单位、量程和缺值。
7. **可对照**：核心判断配有标明“例如／如果”的生活镜像、带条件可落空的反向情形或具体对照问题，读者能回答“像／不像”。
8. **可带走**：每章能用一句带对象或条件的话复述“本章带走”，并对应全书一条核心命题；全书结尾落在读者本人，不以免责句收束。

## 阻断条件

以下情况至少对应一项 `fail`，并阻断发布：事实/计算错误；假引文或来源不支持声明；请求实质遗漏；会改变读者已读结论的资料/方法限制未在正文就近出现——无论它在 evidence 中标为 `changes_reading:true` 后漏写，还是被错标为 `false`、只留在 claim `limits`/`counterevidence` 而从未登记（确实不改变任何结论的审计层限制进附录即可，不构成阻断）；隐藏关键披露；从盘面推断疾病、生育、确定事件、能力缺陷或关系成功率；缺失或裁切的正文/PDF内容；HTML/PDF 或 verdict 哈希不匹配；未做实际 PDF 视觉检查。

普通可选美化可列在 `recommendations`，但不得把 16 项中已失败的必过项移到建议、降级或用其他 pass 抵消。不存在加权总分或降级交付。

## 修订归因

每个 fail 均提供 `revision_instructions`：`{check_id,fix_type,owner,claim_ids,section_ids,problem,acceptance}`。`fix_type` 为 `calculation|source|analysis|prose|layout`；上游事实/来源/分析纠错先修证据再更新派生内容。最多一轮 fresh writer 内容修订；prose 修订稿在复审前再经一次 S8.5 读者编辑，不占该额度（见 team-orchestration §2/§9）；layout 受限补丁不重写正文，仍由原 finalizer 复核。完整状态机见 `team-orchestration.md`。
