# 锁定判定清单（Locked Checklist · destiny-matrix v4）

> **Rulers 范式**（照搬 SIL v5.5 判定协议）：rubric 一次性编译固化，运行时**逐项二元判定 + 强制原文引证**，分数只能由判定结果按固定权重聚合——禁止 judge 现场重新解读规则或凭印象打分。
>
> 使用者：book-finalizer（S9），本清单是其**唯一出分依据**。判定顺序 = 先跑 `scripts/validate_book.py` 拿机器结果，再对机器无法判定的项做 NL 逐项判定，最后聚合分数、组装终审结论。**每项判定必须附「第 X 章原文『……』」或 validate_book.py 输出行的引证；给不出引证 = 该项自动 fail。**
>
> 来源：SKILL.md v3「输出前完整性检查」+「质量自检清单」+「措辞统一调整表/禁词清单」+ V4_PLAN §2/§3.2 图表验收 + memory/conventions.md，合并编 ID 而成。

---

## 判定规则

- 每项回答 **pass / fail**（语义统一：pass = 命书满足要求）。条件项（标「条件」）在条件未触发时记 **n/a**，按 pass 计入聚合，但必须引证「条件为何未触发」。
- 每项必须附 `evidence_quote`（原文引证或 validate_book.py 输出行）；fail 项额外走显性 CoT 四步（观察→依据→判断→建议）。
- 标 `[机]` 的项以 `validate_book.py` 的同 ID 检查结果为准（机器 fail 即 fail，不得人工翻案）；标 `[判]` 的项由 finalizer NL 判定；标 `[机+判]` 的项机器先筛、finalizer 复核语境。
- **🔴 级定义：M 组或 C 组任一项 fail = 🔴 级 fail → 触发修订流**（派 fresh book-writer，max 1 轮；仍不过则降级交付 + 显式披露缺陷清单）。
- **交付阻断级（🟠）**：W1 / E4 / P1 任一 fail 时禁止交付（依据 SKILL.md「违反禁词清单的命书段落必须重写」「任一项未通过，禁止交付」及 v4 双产物硬需求），但属可定点修补项，不必触发 fresh writer 全书修订。
- 🟡 项 fail 记入缺陷清单并扣分，不阻断交付。
- `validate_book.py` 的 exit code 1 = 存在 🔴（M/C 组）或 🟠 W1 的机器 fail；warning 不影响 exit code。
- 本清单为**锁定版**：新增/修改判定项只能通过 skill 版本升级（CHANGELOG 记录），运行时不得增删改任何项。

## 分数聚合规则（唯一合法出分方式）

1. 总分 = `10 × Σ(pass 项权重) / Σ(全部适用项权重)`，四舍五入到 0.1。n/a 项按 pass 计权；PDF 尚未生成阶段（S9 首轮判 HTML 时）P 组暂不计权，S10 交付前必须补判。
2. 分组分（供缺陷清单排序用）= 同式按组内权重计算。
3. **修订触发**（任一即触发，max 1 轮 fresh book-writer）：M 组或 C 组任一 fail（🔴 级）。
4. **交付阻断**（不触发全书修订，但修好前禁止交付）：W1 / E4 / P1 任一 fail。
5. 🟡 fail 只进缺陷清单；总分 < 8.0 时 finalizer 必须在终审结论中给出逐项改进建议。
6. 修订一轮后仍有 🔴 fail → 降级交付：命书顶部显式披露缺陷清单，会话存档记入 memory/known-issues.md。

> 判定完毕后 finalizer 输出结构：`{机器结果摘要, 逐项判定表(ID/verdict/evidence_quote), 总分, 触发动作(通过/修订/阻断/降级), 缺陷清单}`。
