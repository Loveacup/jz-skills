# 项目文档、参考模型与整理

建立、接续、整理或交付项目时读取。目标是让人从入口找到当前成果、理解需求与取舍、追溯全部参考和版本，并能继续修改。覆盖当前项目的资料；沿用合理的已有目录补缺，不为统一外观移动文件或建立空目录。

## 当前入口与资料分工

**存放位置统一在项目。** 需求、现场资料、研究、审核图、交付说明、最终Markdown/HTML/PDF及其本地附件，均在所属项目目录维护；跨项目通用参考放本工作区参考资料，技能维护沿用本工作区现有维护目录。此规则覆盖旧的Obsidian默认交付偏好，不再维护知识库正文副本。需要从知识库找回旧资料时，比对版本和内容，保留原文、来源路径/身份、附件与旧→新映射，再更新项目入口；历史副本不覆盖最新核心需求。迁入核验后知识库不保留正文副本或跳转占位，来源映射及后续更新只在项目目录维护。

**整理时检查旧位置。** 首次整理项目或发现资料散落外部时，检查Obsidian知识库（含`00-Inbox`收件箱）中本项目的正文和所引本地附件；区分独立项目资料与仅提及项目的混合笔记。核对项目内原文、附件及来源映射完整后，在当前授权与权限内移出旧位置的副本或占位，交付项目内入口，不另建跳转笔记。无新外部资料的小改不重复全库扫描；共享附件和无关笔记不随本次收敛擅自删除。

每个项目必须有独立的`核心需求.md`，按[需求维护规则](requirements-and-review.md#核心需求文档每次调整前必读)管理。已有同用途独立文件可以沿用，由README明确指向唯一入口；其余内容可按规模放README或链接专门文件。

| 内容 | 至少保留什么 | 常见位置 |
| --- | --- | --- |
| 当前入口 | 当前阶段、各有效用途/分支的准确版本和路径、部件/数量、整体预览、已验证/待验证、下一步、负责会话与核查日期 | 项目README；工作区项目状态只留摘要与链接 |
| 核心需求 | 当前目标、必须满足项、取舍偏好、范围边界、关键待确认项及确认依据 | 独立核心需求.md；短而可直接执行 |
| 现场资料 | 原图与标注索引、尺寸/基准/来源、实物版本、观察与设计影响、待补项及纠正记录 | 有现场资料即维护独立现场资料.md或已有同用途文档；按[收到即整理](requirements-and-review.md#现场资料收到即整理)执行 |
| 依据与决策 | 详细方案比较和否决原因；需求/审核确认对应的版本；链接现场资料作为依据 | 文档或研究/版本；核心需求只链接细节 |
| 参考与基线 | 所有收到/采用的参考模型、原始包及必要配套文件，来源清单、用途、单位与原件身份 | 参考资料、原始基线；保持原件不变 |
| 审核与开发 | 对应阶段的意向/结构审核图与图源、用户标注、候选/批准范围；可编辑CAD/参数化源和重建依赖 | 审核草图、研究、工作文件/版本 |
| 交付与验证 | 最终网格/3MF、部件和硬件清单、装配/打印说明；几何、路径、实际切片报告，哈希/配置与限制，实物反馈 | 打印文件、交付或对应版本的报告 |
| 历史与复盘 | 旧版、弃用方案、旧确认、阶段快照、整理映射；可复用结构候选与结论 | 归档/日期或历史版本，可从当前入口追溯 |

当前入口区分完整套件、单件、试验版和原始参考，每种有效用途明确当前文件；未生成/未审核/未验证按事实标注。交付链能串起核心需求与批准图→源模型/CAD→网格→实际图→3MF→验证。需要多个有效分支时写明适用对象，不让用户在多个“最终版”中猜。

## 参考模型全部有去处

盘点项目内模型、ZIP、附件、图纸与外部依赖，把每个来源包及其模型列入清单；同一包可按包登记并列出实际采用的成员/对象、原包与解包关系。未采用或未研究的参考也登记状态与用途，避免无从识别的散件。

清单记：本地路径、来源URL/作者或用户提供来源、可确认的版本/取得日期、许可信息（缺失写未知）、单位/缩放及其确认程度、角色（原件、接口基准、外形灵感、结构候选、弃用参考）、采用部位和派生文件；关键原件留哈希。资料少时可在README中列一张表，资料多时独立清单。

主动检索与下载交接按[参考研究](reference-research.md)，沿用这份清单登记；Dot返回路径不等于本地已收到，须由接收方核可读原文件与哈希。

原文件保留原样；修复、缩放或改名后的工作副本与原件关联。3MF源工程预设只代表源文件。照片/网页/视频记录定位信息和实际读取范围，用户标注关联版本；无法访问的来源记缺失，不冒充已归档或已审查。借鉴前检查工作原理、装拆、受力和制造条件。

按本轮任务实际打开采用的参考模型：外形灵感可看缩略图，判断接口、内部结构、尺寸或坡面时须读取对应实体/网格和实例变换。记录读到哪个成员及范围；源模型参数、缩略图比例与现场实测尺寸分别标注，不能相互替代。

## 整理与交接

1. **确定当前身份。** 先读核心需求、README、清单和最新确认，区分有效分支、原件、派生物与历史；不凭文件名或修改时间决定当前版。
2. **保留再移动。** 记录移动前路径、数量与关键文件哈希；批量搬迁保存逐文件清单/哈希。待改写的旧说明留快照，原始参考、旧批准与弃用方案保留。没有授权不删除历史。
3. **按内容归位。** 沿用既有目录补索引；确需移动时保留旧→新路径映射，更新当前文档链接、状态及输入引用。历史脚本保留旧路径时标明重建所需目录/依赖，不把它当当前可直接运行入口。
4. **核完整保留。** 每份原文件都有去处，未修改二进制哈希一致，新增/重写/移动分开记；核当前文档与归档入口链接、版本对应。有交付包时查成员与外部文件一致。仅数量相同不能证明全部保留。
5. **交接准确入口。** 给当前成果与README的绝对路径、有效版本、未验证项及整理结果。共享状态写入前重读，仅合并本项目段；实质进度后更新，不要求每条消息写状态。

核对随实际整理范围执行；单改一段说明无需全盘重哈希。文档完整不替代[几何复核](geometry-validation.md)或[切片验证](slicing-and-delivery.md)。

## 每个项目怎样回收结构

方案取舍或收尾时研究当前项目相关的连接、承托、活动、导流和打印拆分机制，结合最新使用反馈、弃用原因与实际证据，在项目复盘留候选和结论。多项目吸收任务记项目/已读来源/发现或无需新增/回填位置/待补证据，未读项目不算已吸收。

| 内容性质 | 回填位置 |
| --- | --- |
| 特定尺寸、配方、原模型、未解释现象和本次验证输出 | 原项目文档与记录，技能只链接 |
| 值得迁移的结构机制或参数化模块 | [项目结构库](project-patterns.md)：问题、工作方式、相比备选的收益、代价/失效方式、适用边界、证据等级与源路径；模块另指向可编辑源和必要参数，不复制整套模型进技能 |
| 有依据且能帮助同类选型的检查方法 | 合并到[对应结构卡](common-structures.md)，避免同义条目堆积 |
| 会改变通用工作顺序的教训 | 按[收尾流程](closeout.md)窄幅修正对应步骤并检验决策 |

先查已有内容，确有新增价值再收录；无新增则记理由。整体不好用时仍可提取局部机制，但必须保留反证。后续反馈变化就修正原条目；逐项目有依据地积累，不要求每个项目贡献一条通用规则。
