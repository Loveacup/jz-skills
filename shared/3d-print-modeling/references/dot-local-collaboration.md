# Dot与本地执行会话：轻量项目协作

仅在用户安排Dot协调、本地Codex执行，或明确需要项目经理与执行者协作时读取。独立执行时沿用主技能，不要求额外协调者。Dot自行定位项目/负责会话、派活、跟进和汇总；用户提供必要信息和作取舍，不负责搬运路径、ID或消息。本文件不证明双方已连接、已获发送授权或自动共享历史。

## 实际前提与分工

连接能力以当前产品与实际工具核查为准；可参考[电脑连接](https://learn.chatgpt.com/docs/dots/computers-and-apps)、[任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory)、[控制](https://learn.chatgpt.com/docs/dots/controls)。电脑可达、应用开启、用户允许访问和文件/图像可达分别核实，不能用一个连接开关推成所有历史或操作均可用。

| 角色 | 责任 |
| --- | --- |
| 用户 | 使用目标、必要照片/量测/标注、关键取舍与方案确认；也可以直接和执行者沟通 |
| Dot项目经理 | 找当前项目/负责会话，核最新要求；统一命名和分工、交接确认与原件、收节点报告、核成果并统一向用户汇报；按缺口搜取参考 |
| 本地执行者 | 实际读文件，维护唯一核心需求/现场资料与当前成果，完成草图/CAD/几何/切片；报告依据、限制和需决定项 |

一个模型/分支当轮只有一个写入者；协调者不为提速同时改执行者的模型、图或核心需求。双方用同一主源流程，复制版分别核修订、相关成员和实际读取范围；不把仅SKILL相同当整包相同，不自动安装全局副本或同步服务。

## 下发时统一命名

用“项目名｜具体任务”，如“厨房沥水｜结构设计”。同一任务跨阶段沿用会话，阶段/版本写进状态；不每推进一步就新建或改名。稳定ID、主机、工作路径和负责范围由当前可用列表/读取核实，标题只是入口，不写死私人ID到公开流程。

Dot正式下发时设置名称、阶段成果、审核停点和回报入口；优先续用已核实的负责会话，不能把整个项目清单擅自启动。新建任务/发送等操作须有用户对相应范围的授权；接口或授权缺失时记录准确缺口，不把代理间请求当人类授权，也不让用户常规充当消息中转。

## 直聊决定与唯一需求

用户直接向执行会话作出的明确决定同样有效。执行者更新唯一核心需求；接口、范围、优先级或关键需求变化及时报告Dot，日常细节并入阶段报告，不等Dot重复批准。Dot下次派活前核最新需求/用户要求和成果，协调跨任务影响，不用旧笔记覆盖新决定；冲突只问关键差异。

收到照片/尺寸/标注时，经可访问且获准的入口转交原件；由实际负责者按[现场资料规则](requirements-and-review.md#现场资料收到即整理)当轮归档并维护现场资料文档，Dot核归档路径、所看范围和待补项。文件ID或转述不证明看过图。优先自行利用已有附件/连接，确实无法取得原件才说明具体缺口并请求必要补充，不把重复上传作为默认办法。

## 阶段报告由Dot汇总

在实际经历的节点报告：需求/现场资料完成、意向待审、结构待审、模型/验证完成、交付或实物反馈复盘。小任务可合并；阻塞、关键变化、明显成本变化和需用户取舍及时报，不等最后。

一段即可：“项目/任务｜需求版本与阶段｜完成内容＋成果入口/预览｜已验证/未验证｜需决定项＋下一步”。Dot核实际可访问成果并转呈用户可看的附件/预览；执行者正在与用户直聊时正常回答，Dot不重复问同一问题或重复求批准。

通过实际可用且获人类授权的入口回报；若仅原会话输出可读，先在那里形成阶段报告，Dot负责用官方等待/读取跟进，用户不转发。分别记录已形成、已送达、Dot已读取；接口不可用就保留报告/待同步，不另造消息服务或谎称已送达。优先有界等待/状态接口，不频繁全量读历史或新增定时轮询。

## 按需取得MakerWorld参考模型

按[参考研究](reference-research.md)先查已有资料，缺口明确再搜索。Dot返回来源/许可、原文件与身份、本地核收件和量测，再用于设计。只有截图/URL时明确视觉参考，不冒称已取得可测几何；本机不可读或被叫停下载时保留缺口，不绕过身份/权限限制。已有资料足够的小改不重搜。

## 送达状态与当前工具

| 证据 | 可报告状态 |
| --- | --- |
| 工具存在、列表/读取成功 | 只证明对应发现/读取，不证明发送成功 |
| accepted、调用结束或目标active/inProgress | 保留真实回执；不能单独证明具体指令已接收或完成 |
| 官方读取关联本次消息/执行轮，有明确接收或执行该指令证据 | 指令已接收；保留项目内定位和时间 |
| 实际可读成果与需求/版本对应 | 阶段结果可核验；进程结束不等于验收通过 |

在原执行上下文查当前正式暴露/可发现接口；其他会话工具范围、旧函数名、共同目录或一次缺失不代表本次可发送、永久不支持或电脑离线。侧栏项目关联、消息客户端、执行主机、审批和目标接收分别核；没有发送不等于发送审批失败。

超时/断连先核回执、目标当前轮和接收证据，避免重复派发；明确未送达且授权/接口允许时才有限重试，无法判定保留未知。明确拒绝则停被拒动作、记准确返回与授权来源，不换接口、代理、私有RPC或受限存储绕过；未知原因不宣布修复。

## 中断与收尾

关键新要求冲突时先让原执行者停止依赖旧要求的步骤并确认收到，其余独立工作可继续；不另开第二写入者重做。用户暂停时核实并停止相应委派任务，暂停协调者不证明下游都停；控制不可用就明确未核状态。连接恢复后尊重暂停，用户明确继续后再续做；切换电脑不等于迁移已执行成果。

最终交接项目内README、核心需求、成果与限制，按[收尾](closeout.md)回收方法。只用现有项目文档/执行会话；不为协作新增任务数据库、消息总线、常驻代理或后台监控。文档留项目，Obsidian不留正文副本或跳转占位；发布/部署/打印仍是各自授权范围。
