# 实跑问题账本

历史起点：胜宏科技 300476.SZ（2026-09-27）与麦格米特 002851.SZ（2026-09-29）。这里记录**发现的问题、可观察证据、下一次优化要验证的防线**；不是可复用的个股参数、价格预测或已验证的新规则。现行规范仍以 `SKILL.md` 及对应 references 为准。优化时逐项判断是否已有覆盖、是否需改规则/模板/验收脚本；每项要么落实并验证，要么注明不采纳原因。原始产物分别在 `99_待整理/300476.SZ-2026-09-27-研究报告/` 和 `99_待整理/002851.SZ-2026-09-29-研究报告/`。

## 每次运行的追加规则

1. 开始时读取本账本，检查相关历史问题；不要沿用旧股票的参数、价格或结论。
2. 在本次输出目录的 `data/run-issues.md` 记录运行标识（代码、资料截至日、输出目录）、实际观察到的失败/修正/未解决缺口、证据文件及位置、影响和下一次优化的检查点。模型首次运行和每次复跑分别留痕，不能用最后一次成功覆盖首次失败。没有发现新问题也写「本次未发现新问题」并注明实际检查范围；未运行的检查标为未检查。
3. 交付或因阻塞停止之前，在本账本末尾**追加一个该次运行的小节**：运行标识、`data/run-issues.md` 路径、问题摘要与待优化检查点；无新问题也追加一行零发现记录。相同运行再次修订，在原小节补充带日期的更正，不新增同名运行，保留原记录。技能目录不可写时，仍保存输出目录的记录，并在交付说明账本未同步及具体原因，不能声称已入技能。
4. 账本只保留可迁移的失败模式和索引，细节留在每次的 `run-issues.md`；优化后标注处理结果与验收证据，不抹掉历史发现。

## 优化时的退出条件
