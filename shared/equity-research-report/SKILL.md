# 个股研究报告

对单只股票做可复现的研究：先核验证据，再分析经营与估值，按需做股价分布预测与回测，最后交付中文 Markdown 报告、图表与 A4 PDF。

**不启动本流程的请求：** 只查最新价格、单个指标或新闻 → 直接回答该事实并注明来源与时点。下单、自动交易、荐股保证 → 拒绝交易部分，可提供研究。

## 阶段关卡

每个阶段以列出的产物为完成条件；产物未达成时，不以后续阶段的文字掩盖缺口。

### 1. 界定任务

解析：股票代码与交易市场、截至时间、研究问题、预测窗口（仅预测任务）、输出目录。

- 先核对证券身份：代码、交易所、证券简称、公司全称要在交易所或公司公告中对应一致。A/H、同名或更名公司尤其要核对。身份没有核实，不进入后续阶段。
- 仅在名称对应多只证券，或预测请求没有窗口/目标日期时提问。其他缺项用合理默认并在报告写明。
- 用户未要求预测时，不添加价格预测。
- 默认输出：中文、Markdown + 图表 + A4 PDF。
- 在当前任务工作区新建 `<代码>-<截至日期>-研究报告/`；已存在则用 `-2`、`-3` 后缀新建，不覆盖历史成果。子目录建议 `data/`、`figures/`。

**产物：** 任务定义（标的、市场、截至时间、问题、窗口、输出路径）。

### 2. 建立证据表

每项关键输入记录：编号、值、单位/币种、期间或行情时间、发布日期、来源 URL 或本地文件、抓取时间、核验状态。优先交易所与公司披露，再以可靠数据服务交叉验证。来源冲突要列出；未解决的值不进入计算。

用户提供的数据以「用户输入」为来源，不补造 URL；合成/演示数据全程标注。

**产物：** `data/` 下的数据与时点核验表（CSV 或 Markdown）。

### 3. 经营与估值分析

分析收入、利润、利润率、现金流、资本开支、同业估值与催化剂；长线问题再加纵向因果、横向对手解剖与长期情景。先用脚本或可复现计算得到数字，再下判断。

**产物：** 「事实 — 推导 — 假设 — 反证」对应表。只有事实可溯源、计算可复现后，才能写成核心判断。

### 4. 预测与回测（仅预测任务）

在当前标的、当前窗口上实际运行计算与回测。其他股票或历史项目的参数、权重、缩放系数不可沿用。

**产物：** 统计分布（分位数与回测指标）、基本面情景，以及各自的适用边界。

历史行情、截止日期或运行环境缺失时：完成可达的其余分析，把预测数字标为「不可得」并说明缺什么；不用示例数字、经验值或他股结果顶替。

### 5. 成文与交付

按模板写报告，先给结论。每个主结论都要能追溯到数据/图、推理和反证或失效条件，但不必逐条套用同一格式，也不在各部分重复同一组数字。图表与正文数字须来自同一计算产物；核对一致并完成质疑复核后再导出 PDF，并逐页查看。
每次运行在输出目录保存本次问题记录（含修正、未解决缺口；没有新问题也写明），并按[实跑问题账本](references/two-run-lessons.md)的追加规则更新技能内账本。中途失败或只完成部分阶段，也在停止前记录已观察到的问题与阻塞；记录是交付关卡，不把待优化建议冒充已实施规则。

只有用户在当前请求中要求发送并指明收件方时，才转交 `blip-transfer` 技能。

**产物：** 同名的 `<公司名>-<代码>-<研究主题>-<资料截至日>.md` 与 `.pdf`、`figures/`、数字核对与质疑复核结果、逐页检查结论，以及本次问题记录和技能账本新增条目。

## 完成状态

最终回复按实际结果选用一种表述，不混用：

- **完成：** 列出报告、PDF 路径与核心判断。
- **部分完成：** 写明已完成的产物，以及被阻塞的阶段、缺失的数据或依赖。例如「Markdown 完成，PDF 阻塞：渲染依赖不可用」。
- **预测不可得：** 基本面报告可以交付，但预测部分明确未完成，并写明原因。

报告只描述实际运行过的计算与检查。未运行的模型、未通过的检验、未查看的页面，都不能写成已完成。
