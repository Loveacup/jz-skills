# 自动信号采集

> 吸收自 BayramAnnakov/claude-reflect 的 correction capture + session pattern discovery 机制。

## 核心理念

CQI 不应该依赖人（或 agent）手动发现所有问题。应该建立自动信号采集管道，从不完美但有规律的数据源中提取改进信号。

## 信号源

### 优先级 1：用户直接反馈（最高置信度）

**采集方式**：`session_search` 搜用户纠错关键词。

```
搜索 query: "不对|错了|不应该|你搞错了|no,|don't|actually"
```

每条命中提取：
- 用户说了什么？（verbatim quote）
- 上下文是什么？（前后 5 条消息）
- 涉及哪个 skill/系统？（从上下文推断）

**置信度**：0.90-0.95（用户直接说的就是最高置信度）

### 优先级 2：Session 中的异常模式

**采集方式**：`session_search` 搜工具调用失败/异常。

```
搜索 query: "error|ERROR|failed|FAILED|timeout|TIMEOUT|Traceback|exception"
```

**置信度**：0.75-0.89（工具报错是硬信号，但可能是环境问题而非系统缺陷）

### 优先级 3：代码中的技术债标记

**采集方式**：`search_files` 搜代码内标记。

```
搜索 pattern: "TODO|FIXME|HACK|workaround|XXX"
```

**置信度**：0.70-0.85（代码标记反映开发者当时的判断，但可能已过时）

### 优先级 4：Cron job 异常

**采集方式**：检查 cron job 输出中的异常。

```
搜索: "ERROR|FAILED|timeout" in cron output
```

**置信度**：0.65-0.80（cron 异常可能是瞬时的）

### 优先级 5：Supermemory 中的矛盾信息

**采集方式**：`supermemory_search` 搜相关主题，检查是否有矛盾结论。

**置信度**：0.60-0.75（跨 session 的矛盾需要人工判断）

## 信号处理管道

```
原始信号
  │
  ├─ 1. 提取 verbatim quote（原始文本，不改写）
  │
  ├─ 2. 置信度评分（按信号源类型）
  │
  ├─ 3. 语义去重（与已有 issue 比对）
  │     ├─ 重复 → 提升已有 issue 置信度 + 增加出现计数
  │     └─ 新信号 → 进入步骤 4
  │
  └─ 4. 分类
        ├─ 高置信 (>=0.75) → 创建 CQI issue
        ├─ 中置信 (0.60-0.74) → 标记 OBS，累积观察
        └─ 低置信 (<0.60) → 记录但不行动
```

## OBS 升级规则

| 条件 | 动作 |
|------|------|
| 同一 OBS 出现 3 次 | 升级为 P2 issue |
| OBS 超 90 天未升级 | 健康分扣 0.02，但保持 OBS |
| OBS 被用户直接确认 | 按用户指定的优先级升级 |

## 去重策略

两个信号被认为"重复"当：
1. 涉及同一个 skill/系统/组件
2. 描述同一类问题（语义相似，非逐字匹配）
3. 建议的 fix 相似

去重判断由 agent 做语义比对，不依赖精确字符串匹配。

## 使用方式

写新 CQI 或回写已有 CQI 时，**先跑一轮信号采集**：

1. 按上述 5 个信号源搜索
2. 提取 verbatim quote
3. 评分 + 去重
4. 将新信号加入 CQI 文档的 OBS 或 issue 列表
5. 在 CQI 文档中注明信号来源

## 反模式

| 不要 | 要 |
|------|-----|
| 所有信号都当 P0 | 按信号源类型设定合理的置信度 |
| 手动写信号摘要 | 保留 verbatim quote，原汁原味 |
| 跳过去重 | 去重防止 CQI 文档被重复信号撑爆 |
| 只搜不记录 | 采集完必须落地到 CQI 文档中 |
