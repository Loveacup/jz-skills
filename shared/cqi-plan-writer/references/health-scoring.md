# 健康度量化评分

> 吸收自 muratcankoylan/Agent-Skills-for-Context-Engineering 的 `skill_health.py`（确定性 skill body-quality scoring）。

## 用途

每次 CQI 回写前，对被改进对象计算 0-1 健康分。这个分数：
- 作为 CQI 文档 frontmatter 的 `health_score` 字段
- 作为改进效果追踪的基线/对标
- 多个 CQI 回写之间形成趋势线

## 评分算法

```
健康分 = 1.0
- P0 issue 数 × 0.15
- P1 issue 数 × 0.08
- P2 issue 数 × 0.03
- 超 90 天未升级的 OBS × 0.02
- 无 verify 的 fix × 0.05
```

最低 0.0（不出现负数）。

## 评分维度

不同 Profile 有不同的维度权重，但核心算法一致：

### 通用维度

| 维度 | 含义 | 常见指标 |
|------|------|---------|
| **功能完整性** | 核心能力是否可用 | P0 issue 数量、关键路径是否阻断 |
| **证据锚定度** | 多少诊断有实测数据 | issue 中实测数字占比 |
| **历史负债率** | issue 存续时间和严重程度 | P0/P1 存续天数加权 |
| **可验证性** | fix 是否可证明 | 有 verify 命令的 fix 占比 |

### Profile 特化维度

| Profile | 额外维度 | 权重调整 |
|---------|---------|---------|
| Skill | +文档完整度（10%） | 功能完整性 30% |
| System | +架构合规（20%） | 代码质量 25% |
| Incident | N/A（一次性的，不算持续分） | — |
| Process | +SOP 同步率（20%） | 流程效率 30% |

## 计算流程

1. **列出所有 issue**：按 P0/P1/P2/OBS 分类
2. **计数**：每类 issue 数量
3. **检查 verify**：数一下多少 fix 没有 verify
4. **检查 OBS 时效**：OBS 超 90 天未升级的计数
5. **套公式**：算出总分
6. **记录趋势**：如果已有历史分数，追加到 `health_trend` 数组

## 示例

```
某 Skill 当前状态：
- P0: 2 个 → -0.30
- P1: 3 个 → -0.24
- P2: 5 个 → -0.15
- OBS: 1 个超 90 天 → -0.02
- 15 个 fix 中 3 个无 verify → -0.15

健康分 = 1.0 - 0.30 - 0.24 - 0.15 - 0.02 - 0.15 = 0.14

→ 这个 skill 急需抢救。优先把 P0 清零可涨 0.30 分。
```

## 注意事项

- **健康分不是目标，是指标**。追高分不如追 issue 清零。
- **不要为了涨分而降低 issue 优先级**。P0 应该写 P0 的必须写 P0。
- **趋势比绝对值重要**。0.50→0.65 比一直 0.80 但 P0 堆积更有意义。
- **Incident Profile 不适用**。事故复盘是一次性的，不追踪长期健康。
