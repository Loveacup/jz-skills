# 动态计划校准

计划维护贯穿既有 Spec → Accept → Build → Verify 四步，不是第五阶段，也不新增默认工作台或规划模型调用。用当前项目已经选定的 todo/plan/三梁记录作为唯一权威落点。每步结束后计划都必须反映当前事实；没有事实变化时，可保留原计划并记录依据，不得为制造版本变化而全量重写。

## 触发点与记录

在每个 Spec、Accept、Build、Verify 阶段完成、失败或阻塞后校准；每个有独立完成条件的执行工作单元结束或 worker 返回后校准。新的用户指令、契约或环境变化、授权/所有权风险立即触发，不等到阶段尾声。连续只读查找若服务同一未完成工作单元，可在工作单元结束合并观察，但不得延后风险处理。

使用已有记录，最少包含：观察与证据锚、当前契约引用、计划修订引用、受影响工作与所有权、继续/增量调整/候选整体重规划/阻塞/升级的决定及下一步。记录可验证理由，不记录私有推理过程。L1 可在 checklist 或对话中记录；L2/L3 复用已有工作台，不默认另建日志体系。

| 阶段 | 计划校准需要吸收的内容 | 允许的计划调整 | 红线 |
|---|---|---|---|
| Spec | 用户意图来源、已核验事实、未决问题 | 调整调研/澄清顺序，标明已知/未知 | 环境事实和实现假设不自动变成用户需求；尚未冻结契约的正常澄清不计 slice |
| Accept | 可证伪 AC、授权、必要独立审计、未决分叉 | 将剩余工作映射到 AC 和 verifier；冻结契约引用 | 无 Acceptance checklist 不 Build；L3 缺契约审计不得进入相关 Build |
| Build | 产出、新事实、错误、依赖、所有权状态 | 更新剩余工作、阻塞和就绪前沿；局部调整受影响工作 | 执行完成不等于 PASS；不能改授权、风险底线或 AC；不得重派存活/未知 writer |
| Verify | 带锚 PASS/FAIL/BLOCKED、实际版本 | PASS 保留有效工作并推进；产物失败回 Build；契约问题回 Spec/Accept；缺证据冻结依赖 | 不为通过当前产物而降低 AC；不重置预算；不替代独立 auditor |

## 增量变更、修订引用与在途工作

默认只改新事实影响的未完成部分，保留其他已验证工作、证据和 PASS。未来未知处保持粗粒度，不提前拆完。主要路径不可行、关键假设被推翻或依赖失效影响面无法局部界定时，才整体重规划剩余工作；不能界定影响时，先冻结不能证明安全的工作，不能以全量重规划掩盖未知。意图、AC、范围或授权变化先回 Spec/Accept；未批准的新边界不得执行。

计划修订、契约修订、产物/证据版本分开记录。仅重排未开始任务，不会自动废弃无关 PASS；只有上游产出或 AC 变化影响到它时，才按实际影响范围传播失效。迟到 worker 结果按实际契约、产物和影响范围判断，不能仅因 plan revision 不同而拒收，也不能接受已受契约/产物变化影响的结果。

单一协调者维护权威计划。工作在派发时绑定当时契约、输入与唯一所有权；新计划不能靠改名或换版证明旧 writer 已停止。停止派发受影响后继；取得可定位 stop proof（stop acknowledgement、进程退出、锁/租约释放或等价事实）后，才能改变所有权。未受影响分支继续。

## 计数与终止（D1–D7）

1. D1：四阶段及每个可独立验收工作单元结束、失败、阻塞后校准；无变化须说明保持原计划的依据，无需重写/调用模型。
2. D2：新来源事实不是用户需求。契约冻结前正常澄清不计 slice；冻结后的实质契约重开不能改称 plan revision 逃避 slice。
3. D3：仅重排未开始工作不废弃无关 PASS；受影响产物/AC 改变时冻结其依赖闭包，无关工作继续。
4. D4：计划改变不得重派存活/未知 writer；迟到结果按真实契约、产物和影响范围验证，不按计划号一刀切。
5. D5：regen 上限 3、slice 上限 2、无人值守整轮不可锚率 >40% 计一次 regen、等待截止、独立审计和授权均保持原规则。
6. D6：计划/研究/方法论等交付物修正失败交付，按产物再生计数；同一事实重复规划不能无限推进。
7. D7：L1 不需要新计划文件；L2/L3 复用已有工作台；恢复上下文时能找到唯一当前计划、契约与事件。

日常增量调整和同一事实的 no-change 校准不计 regen/slice，也不改计数。新产物再生计 regen +1；已冻结工作单元整体打回或重开 Spec/Accept 契约计 slice +1，同一契约重开事件只计一次。重规划不得重置任务身份、预算或等待截止时间，不重新分派未知所有权。相同检查点、输入事实和证据已有裁决时复用它；无新证据、无合法就绪工作时 BLOCKED，不能靠反复造计划版本继续循环。硬顶到达后升级人工。

## Jev 边界

Jev 是可选的 `pick_context_file` shadow，只对已枚举、授权、封闭的候选集合给出辅助选择。执行流程及计划控制仍由协调者掌握；Jev 不写计划、不决定权限/依赖/验收/风险/计数/PASS，也不覆盖协调者已经冻结的选择。每个检查点校准计划不意味着每个检查点都调用 Jev。执行与样本界限见 [[jev]]。
