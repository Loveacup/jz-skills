# B站技术视频：标题/简介/评论 与 实际转录错位核查

## 触发场景

当 B站视频属于技术/产品解读，且出现以下任一信号：

- 标题或简介使用强叙事词："团队"、"军队"、"革命"、"全自动"、"操作系统"、"完整流程"。
- 简介列出很多功能点，但转录内容明显集中在其中 1-2 个点。
- UP 主置顶/热评是"省流总结"，且可能由 UP 主本人发布。
- 视频是 YouTube 搬运/中配，简介包含原视频链接。
- 评论区出现 clickbait / 广告 / 不符预期 等质疑。

## 工作流

1. **采集三层文本**
   - B站 metadata：标题、简介、UP主、发布时间、统计数据。
   - 实际字幕/转录：优先官方字幕，失败走自动 fallback。
   - 评论层：B站热评 + 原 YouTube 评论（如果是搬运）。

2. **做 Alignment Check**
   - 列出标题/简介承诺的功能点。
   - 从 transcript 中抽取实际展开的主题。
   - 标注三类：
     - ✅ 讲透：标题/简介提到，转录也有实质内容。
     - 🟡 带过：提到但没有机制/步骤/证据。
     - 🔴 缺失/错位：简介强调但转录没有展开。

3. **技术事实回到一手来源**
   - 对 Hermes / API / 框架 / 产品功能，用官方 docs / GitHub / release note 交叉验证。
   - 视频口播、UP 主热评、搬运标题只能作为二手叙事，不作为最终事实。

4. **报告中单独写结论**
   - 若错位明显，在 §0 或开头摘要写明："本报告以实际转录为主；标题/简介存在 X 类错位"。
   - 在 §2.5 或 §7 中区分：官方可核查功能 / 作者实践案例 / 商业 CTA。

## 输出模板

```markdown
### 标题/简介 vs 实际内容对照

| 承诺点 | 来源 | 转录覆盖度 | 证据 | 判断 |
|---|---|---|---|---|
| Agent Swarms / 多 Agent 团队 | 标题/简介 | 低 | transcript 主要讲 /learn 与 Petdex | 🔴 标题错位 |
| /learn 技能学习 | 转录/官方 docs | 高 | transcript 多段展开；官方 docs 支持 | ✅ 核心内容 |
| Petdex 状态显示 | 转录/官方 docs | 高 | transcript 与官方 docs 一致 | ✅ 核心内容 |
```

## Pitfalls

- 不要把 UP 主置顶评论当成客观社区总结，尤其评论作者就是 UP 主时。
- 不要因为简介列了 Kanban / Profile / Swarm，就在报告里假装视频讲透了这些机制。
- 不要让 `/tmp/{BV}_report.md` 的自动引擎报告替代人工全量版；自动报告常适合初稿，full mode 仍要人工补齐 G3/G4/G5/G7。
- 对搬运视频，YouTube 原标题/章节/评论是重要对照层；但原视频评论样本少时只能作为信号，不当作共识。
