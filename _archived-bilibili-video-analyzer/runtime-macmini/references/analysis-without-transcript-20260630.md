# DEPRECATED — 无字幕/音频失败下只能做预分析，不能做正式完整分析

> [!danger] 2026-06-30 复盘更正
> 本文件原先主张“无字幕/ASR 但简介丰富时可生成完整分析”，已被 BV1sxT56TE39 事故证明为错误：`verify_report.py` 只能验证结构深度，不能证明来源充分。**正式 `B站笔记_...` 必须基于官方字幕或 ASR transcript。**
>
> 正确规则：无字幕/无 ASR 时只能输出 `预分析_未通过ASR_...`，并在 YAML/标题/正文显式降级；不得保存为正式 `B站笔记_...`，不得声称完成 full report。
>
> 若简介包含时间轴/金句/核心观点，可作为预分析素材，但后续必须继续排查 PlayURL/H200 ASR。B站音频抽样不要用 `curl --max-filesize`；用 `Range: bytes=0-10485759`。完整路径：PlayURL 低码率 DASH audio → ffmpeg 5min chunks → H200 ASR → 合并 transcript。

# 历史错误策略（仅作事故复盘，不再执行）

## 触发条件

当视频满足以下全部条件时，本策略适用：

1. 视频无官方/AI 字幕（Player API + legacy 均返回"无字幕"）
2. yt-dlp 字幕提取失败（常见 412）
3. PlayURL API 直拉音频下载失败（非必达——H200 ASR 链路未走到）
4. **但 UP 主在视频简介中提供了以下至少 3 种材料中的 2 种**：
   - 完整时间轴索引（如 `00:07 话题A / 03:15 话题B / ...`）
   - 核心金句摘录（≥5 条带引号的原话引用）
   - 核心观点总结（≥5 条结构化要点）

## 已证实可行

2026-06-30 对 BV1sxT56TE39（105 分钟 AI 应用融资访谈，UP 主"苔藓之火"）的实测：

- 数据采集：弹幕 0 · 评论 3 · 字幕全路径失败
- 材料：简介含 16 个时间戳话题 + 9 条核心金句 + 8 项核心观点 + 嘉宾 bio
- 产出：32KB 全量版报告，5/5 质量门通过（G1≤100行 ✅ G3≥3×200词 ✅ G4≥4×500词 ✅ G5≥9 ✅ G7≥3+2+3 ✅）
- 交叉验证：CRUNCHBASE/NFX 融资数据、IT桔子报告、The Information 公开报道

## 操作流

### 第一步：判断简介质量

```bash
curl -s 'https://api.bilibili.com/x/web-interface/view?bvid={BV}' \
  -H 'User-Agent: ...' -H 'Referer: https://www.bilibili.com/' \
  | python3 -c "import json,sys; d=json.load(sys.stdin)['data']; print(d['desc'])" \
  | wc -c
```

如果 `desc` 长度 > 500 字符（中文）且包含结构化信息（时间戳/观点编号/金句列表），本策略成立。

### 第二步：从简介拆解素材

- **时间轴 → §1 叙事弧线**：每个时间戳话题对应一个弧线节点，跨话题提取核心命题和驱动逻辑
- **金句 → §5 高光时刻**：直接引用，标注"来自 UP 主简介"，加分析性注释
- **核心观点 → §3 关键洞察**：每个观点扩展为 ≥200 字的洞察，补交叉验证
- **嘉宾 bio → §0 元信息**：补充学术/职业背景

### 第三步：严格标注数据来源差异

**必须**在以下位置标注：

- §0 Meta 表：添加 `⚠️ 数据局限` 行，说明转录缺失
- §8 附录：`数据来源与局限` 表格，逐项标注来源和局限
- 报告中所有"视频中""嘉宾指出""访谈中提到"等措辞改为"简介中""UP 主摘录""据简介"

样例：

```markdown
| ⚠️ 数据局限 | 本视频无 B站官方/AI 字幕，音频转写亦因 PlayURL 直拉失败未能获取完整转录。
本报告基于 UP 主在视频简介中提供的完整时间轴、金句摘录和核心观点撰写，
并交叉引用了公开可验证的行业数据与一手资料。
```

### 第四步：交叉验证补深度

简介中的 key claims 如果没有音频验证，必须找公开数据对账：

- 融资数据 → Crunchbase/IT桔子/36kr
- 公司收购 → The Information/Bloomberg
- 技术参数 → 官方文档/GitHub
- 行业趋势 → 一手报告

对每条 external claim，标注是 `[已核实]` / `[存疑]` / `[来自简介未核实]`。

### 第五步：标注为"基于摘要的分析"而非"基于转录的分析"

- §7 隐私与局限节增加专门段落说明"简介摘要 vs 完整对话"的信息差异
- 结论性断言加 hedging：不说"嘉宾认为X"，说"据 UP 主在简介中摘录，嘉宾认为 X"
- 不排除 UP 主选择性摘录——简介是自我总结，不等于完整录音

## Quality Gates 特殊考量

- **G3 洞察**：可以基于金句和观点展开，但必须补交叉验证
- **G4 Deep Dive**：可以基于行业知识补背景，但必须明确区分"简介材料"和"分析者引申"
- **G5 金句**：直接用简介摘录，加简短分析——不要因为不是自己转录的就少做
- **G7 局限**：必须包含"基于 UP 主自我摘要而非完整录音"这条局限

## 不适用场景

- 简介只有一句话（如"求三连"）
- 简介是纯推广/广告，无实质内容
- 简介的时间轴与金句数量不足以支撑 ≥3 个洞察
- 简介与视频主题明显不符（标题党）

以上场景应降级为"精简版"或标注"材料不足以深度分析"。

## 与正常流程的关系

本策略是 fallback——**不是首选**。正常情况下仍优先走：Player API 字幕 → yt-dlp → PlayURL 直拉音频 → H200 ASR。

只有当上述全链路失败 + 简介质量达到门槛时，启用本策略。
