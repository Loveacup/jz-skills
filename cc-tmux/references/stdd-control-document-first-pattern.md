# STDD 控制文档优先模式

> 2026-06-27 实发：WRR 自适应改造任务中，用户纠正 Hermes 直接动手改代码的行为，要求"先写控制文档再拉起 CC"。

## 问题描述

用户要求：
> "Skill authoring 你先别急着改，你把所有的需求整理到文档目录下面，然后调用 OB 知识库里的 SDD 方法论，我们来逐步完成"
> "原则就是：你负责协调审核，然后拉起 CC 来干这个活"

但 Hermes 直接：
1. 读取 WRR extension.ts 代码
2. 尝试修改代码实现运行时检测
3. 创建 Hermes 插件目录
4. 被用户纠正后才停下来写控制文档

## 正确工作流

### 阶段 1：文档先行（Hermes 负责）

1. **读取 STDD 方法论**
   - 从 OB 知识库读取 `个人STDD通用方法论_20260622.md`
   - 理解四步循环：①Spec → ②Accept → ③Build → ④Verify

2. **创建控制文档**
   - L1 需求基准线：Why / What / 非目标 / 验收口径
   - L2 共维实现方式：架构决策 / 模块边界 / 数据模型
   - L3 执行层：任务拆分 / 验收契约 / 验证脚本

3. **确认验收契约**
   - 用户审核控制文档
   - 确认关键决策（D01-D04）
   - 明确验收标准

### 阶段 2：拉起 CC 执行（CC 负责）

1. **按控制文档执行**
   - CC 读取控制文档
   - 按 L3 任务拆分执行 Build
   - 遵守验收契约

2. **Hermes 审核**
   - 验证 CC 产物
   - 按验收契约逐条判定
   - 不通过则退回 CC

### 阶段 3：收尾（Hermes 负责）

1. **验证**
   - 运行验证脚本
   - 确认所有验收项通过

2. **回写**
   - 更新 OB 知识库
   - 同步 GitHub 仓库

## 决策树

```
用户要求复杂任务（多平台适配/架构决策/skill 改造）
├── 直接动手改代码？ → ❌ 错误
└── 先写控制文档？ → ✅ 正确
    ├── 读取 STDD 方法论
    ├── 创建控制文档（L1/L2/L3）
    ├── 用户确认验收契约
    └── 拉起 CC 执行
```

## 关键原则

1. **文档是权威**：控制文档 = 需求基准线 + 共维实现方式，产物只是编译物
2. **CC 只负责 Build**：CC 执行具体实现，Hermes 负责协调审核
3. **验收不可省**：没有验收契约不准发送任务给 CC
