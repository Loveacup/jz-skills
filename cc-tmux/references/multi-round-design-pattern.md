# CC 多轮设计迭代模式

> 来源：2026-06-16 hermes-deck 研究 → audit agent 设计 4 轮 CC 对话

## 四轮模式

用 CC 做架构设计时，不应一轮梭哈。本模式将长程设计拆为四轮，每轮只产一个确定性物的件：

| 轮 | 输入 | CC 产出 | 人审重点 |
|----|------|---------|---------|
| **R1 研究** | 外部源码 + 需求简述 | 判别性分析（能不能做、差异在哪） | 判断是否准确、有无遗漏 |
| **R2 设计** | 研究结论 + 参考文档 + 用户偏好 | 统一设计稿（决策 + MVP + 灰度路径） | 决策方向、是否过度设计 |
| **R3 纠偏** | 设计稿 + 用户反驳/追问 | 窄带裁决（3 个具体问题逐个回答） | 裁决是否正确、是否有 bug |
| **R4 终稿** | 完整设计 + 审核意见 + 简化指令 | 可落盘制品（copy-paste-ready） | 完整性、一致性、可直接执行 |

## 每轮约束

- R1：给足外部参考（源码 / 文档 / 论文），不要只丢一句话
- R2：附用户偏好（"我喜欢 X，不想要 Y"），用 `references/` 文件传参考
- R3：问题精确（"到底 A 还是 B"），不要开放式
- R4：说 "产出 copy-paste 可落盘"，指定输出文件路径

- R2 = 三向交叉评判 + 审核 Agent 槽位设计（6 决策 D1-D6）
