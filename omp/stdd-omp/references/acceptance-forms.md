# 可证伪验收形式库

## 核心口诀

> 一条一项、可判真假、模糊必量化、证据可回查。

## 跨项目类型适配表

| 项目类型 | 典型验收项 | 可叠加形式 |
|---|---|---|
| 代码 | 单元测试通过、lint 无错、diff 影响面 ≤N 文件 | + 性能基线、+ 安全扫描 |
| 写作 | 字数/结构达标、事实可溯源、目标读者可读性分数 | + 红队挑错、+ 引用完整性 |
| 研究 | 假设/数据/结论链可复现、来源可验证 | + 对立观点审查 |
| 产品 | 功能可用、指标可测、无回归 | + 用户路径走查 |
| 决策 | 选项清单完整、风险量化、回滚方案明确 | + Pre-Mortem |
| 创意 | 约束满足、差异化可说明、可快速验证 | + 竞品对标 |

## 验收形式库

1. **存在性**：`verifyArtifact('./dist/app.js')` 返回 PASS。
2. **命令通过**：`verifyTest('npm test')` exit 0。
3. **Diff 范围**：变更文件数 ≤ N；无未预期文件。
4. **指标量化**：加载时间 < 200ms；测试覆盖率 ≥ 80%。
5. **静态扫描**：无 danger pattern；无 lint error。
6. **红队 / Pre-Mortem**：列出 3 种失败可能并给出缓解。
7. **可复现**：提供最小复现步骤，第三方能 rerun。
8. **Browser E2E**（Web 项目）：用 `browser` 工具验证页面可访问、元素可见、前端状态正确。

   示例：

   ```text
   - [ ] browser goto http://localhost:3000 成功，无 console error。
   - [ ] tab.waitForSelector("[data-testid=submit]") 在 5s 内出现。
   - [ ] tab.evaluate(() => window.__APP_STATE__.user) 返回非空对象。
   ```

## 可叠加原则

- L1：1–2 条即可。
- L2：至少 1 条客观命令 + 1 条 diff/影响面。
- L3：必须含独立 auditor + 计数器 + GOAL 退出条件。

## 造契约口诀

把「质量好」改成：

```markdown
- [ ] `npm test` exit 0，且覆盖率不下降（≥当前基线）。
- [ ] 变更文件 ≤3 个，且无删除未记录文件。
- [ ] reviewer/oracle 审计全 PASS。
```

把「用户满意」改成：

```markdown
- [ ] 目标用户完成核心任务路径 ≤3 步。
- [ ] 错误场景有明确提示，不出现空状态。
- [ ] 可访问性：焦点顺序与键盘操作完整。
```

## 进阶验收

- **红队**：让独立 agent 专门找反例。
- **Pre-Mortem**：假设项目已失败，列出最可能原因。
- **对照实验**：A/B 指标差异在统计显著范围内。
