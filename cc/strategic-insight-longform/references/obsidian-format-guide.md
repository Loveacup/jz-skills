# Obsidian 格式规范指南

本文档整合 obsidian-docs (V2) 和 obsidian-docs-v3 的格式规范，供战略洞察长文输出时参考。

## 格式选择

| 格式 | 特点 | 适用场景 |
|------|------|---------|
| 标准Markdown | 无YAML头，通用格式 | 通用分享、非Obsidian用户 |
| Obsidian V2 | 双链、Callouts、块引用 | 需要构建知识网络 |
| Obsidian V3 | YAML属性、五维标签、无双链 | 纯属性驱动的知识库 |

## V3 格式规范（推荐）

### YAML Frontmatter

```yaml
---
# ═══════════════════════════════════════════════
#  管理维度
# ═══════════════════════════════════════════════
class: "30-Resources"      # PARA 分类
status: 常青               # 生命周期：种子/树苗/常青/归档
type: 概念                 # 笔记类型
priority: 重要             # 优先级：紧急/重要/正常/低

# ═══════════════════════════════════════════════
#  内容维度
# ═══════════════════════════════════════════════
aliases:                   # 智能别名（2-4个）
  - 主题英文名
  - 主题缩写
  - 分析类型别称
tags:                      # 五维标签
  - type/概念
  - status/常青
  - src/对话
  - topic/商业

# ═══════════════════════════════════════════════
#  分析元数据
# ═══════════════════════════════════════════════
analysis_type: industry    # 分析类型
std_framework:             # S-T-D框架覆盖
  spatial: point-region-nation-world
  temporal: T-5_T0_T+5
  domain: multi
sources_count: 12          # 来源数量

# ═══════════════════════════════════════════════
#  时间戳
# ═══════════════════════════════════════════════
created: 2025-12-29 10:00
modified: 2025-12-29 10:00
---
```

### PARA 分类决策

| class 值 | 判断标准 | 战略洞察适用 |
|:---|:---|:---|
| `"10-Projects"` | 有明确截止日期的目标 | 项目相关分析 |
| `"20-Areas"` | 长期维护的责任区 | 持续跟踪的行业 |
| `"30-Resources"` | 仅作为未来参考（80%） | **大多数战略洞察** |
| `"40-Archives"` | 已完成、失效 | 过时分析 |

### 五维标签体系

**维度1: type/（类型）- 必选**
- `type/概念` - 定义、理论、模型
- `type/案例` - 实战案例、场景
- `type/工具` - 方法、清单、模板
- `type/索引` - MOC 索引页

**维度2: status/（状态）- 必选**
- `status/种子` - 初稿，< 200字
- `status/树苗` - 发展中，200-1000字
- `status/常青` - 完整，> 1000字（战略洞察通常为此）
- `status/归档` - 过时

**维度3: src/（来源）- 推荐**
- `src/对话` - AI 对话整理
- `src/阅读` - 书籍、论文
- `src/原创` - 自己撰写

**维度4: ctx/（场景）- 可选**
- `ctx/工作` - 工作场景
- 战略洞察通常省略此维度

**维度5: topic/（主题）- 慎用，≤5个**
- `topic/商业` - 策略、管理、运营
- `topic/技术` - AI、软件、工程
- `topic/人文` - 哲学、心理学
- `topic/科学` - 自然科学
- `topic/生活` - 健康、兴趣

### Callouts 类型

```markdown
> [!NOTE] 补充说明
> 用于一般性说明和背景信息

> [!TIP] 核心洞察
> 用于标注核心观点和关键发现

> [!WARNING] 风险提示
> 用于警示风险和注意事项

> [!IMPORTANT] 关键判断
> 用于强调重要结论

> [!QUOTE] 引用来源
> 用于标注数据来源或专家观点

> [!EXAMPLE] 案例说明
> 用于展示具体案例
```

### V3 格式红线

1. **严禁在 YAML 内使用双链** `[[]]`
2. **标签不可包含空格**，用 `-` 或 `/`
3. **严禁使用行内注释** `#`
4. **字符串值用引号包裹**
5. **正文也不使用双链**（纯属性驱动）

## V2 格式规范（需要双链时）

### 双链使用原则

- 首次提及重要概念时添加双链：`[[概念名]]`
- 使用 `|` 自定义显示文本：`[[长笔记名|简称]]`
- 链接到特定章节：`[[笔记#标题]]`

### 块引用

为重要段落添加块ID便于精确引用：

```markdown
这是一个重要的观点。 ^key-insight-1
```

引用时使用：`[[笔记名#^key-insight-1]]`

### 简化的 YAML

V2 格式可以使用更简洁的YAML：

```yaml
---
tags:
  - 战略洞察
  - 行业分析
aliases:
  - 主题别名
created: 2024-12-29
---
```

## 智能别名策略

**必填**，生成 2-4 个有意义的别名：

| 策略 | 说明 | 示例 |
|:---|:---|:---|
| **缩写策略** | 专业术语缩写 | `LLM` `S-T-D` |
| **翻译策略** | 中英互译 | `咖啡市场` ↔ `Coffee Market` |
| **类型策略** | 分析类型标识 | `行业分析` `趋势预判` |

**禁止使用通用词**：
❌ "笔记"、"文档"、"内容"、"分析"
