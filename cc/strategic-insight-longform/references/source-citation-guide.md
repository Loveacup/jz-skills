# 来源标注指南

本文档规范战略洞察长文中的来源追溯和标注方法。

## 核心原则

> **所有数据和核心观点必须标注来源**

这是战略洞察报告区别于普通AI生成内容的关键——每个判断都可追溯、可验证。

## 来源类型编码

| 编码 | 类型 | 英文 | 说明 | 可靠性 |
|------|------|------|------|--------|
| U | 用户素材 | User Material | 用户上传的文档/数据 | 最高（用户指定） |
| D | 公开数据 | Public Data | 官方统计/公开数据库 | 高 |
| E | 专家观点 | Expert | 研报/专家文章 | 高 |
| W | 网络搜索 | Web Search | 搜索引擎结果 | 需评级 |
| I | 推理综合 | Inference | Claude综合分析 | 标注依据 |

## 标注格式

### 1. 行内标注（推荐）

最简洁的标注方式，适合大多数场景：

```markdown
市场规模达2000亿元[U1]，同比增长30%[D1]。
```

### 2. 多来源标注

当一个观点有多个来源支撑时：

```markdown
综合各方数据，增速在25%-30%区间[U1,W2,D1]。
```

### 3. 推理标注

当结论是Claude综合分析得出时，必须标注推理编号和依据：

```markdown
基于以上分析，预计未来三年将保持增长态势[I1]。

[I1]: 综合判断，基于U1市场数据 + W2行业趋势 + D1宏观环境
```

### 4. 脚注式标注

适合需要详细说明来源的场景：

```markdown
增长率超过30%^[来源: 艾瑞咨询《2024行业报告》，p.15]
```

### 5. 文末集中标注

在文章末尾提供完整的来源索引表：

```markdown
---

## 来源索引

| 编号 | 类型 | 来源 | 说明 |
|------|------|------|------|
| U1 | 用户素材 | market-report.pdf | 行业研究报告 |
| W1 | 网络搜索 | [艾瑞咨询](https://...) | 2024年数据 |
| D1 | 公开数据 | 国家统计局 | 行业统计 |
| I1 | 推理综合 | 基于U1+W1 | 趋势预测 |
```

## 来源优先级

```
用户素材 (U) > 公开数据 (D) > 专家研报 (E) > 网络搜索 (W) > 推理综合 (I)
```

**原则**：
1. 能用用户素材的，优先用用户素材
2. 能用官方数据的，不用二手解读
3. 能找到来源的，不做无依据推理

## 可靠性评级

对网络搜索来源(W)进行可靠性评级：

| 等级 | 标准 | 示例 |
|------|------|------|
| A | 官方/权威机构 | 政府统计、上市公司年报、学术论文 |
| B | 知名媒体/研究机构 | 主流财经媒体、知名咨询公司 |
| C | 一般来源 | 行业自媒体、企业新闻稿 |
| D | 未验证 | 论坛、个人博客、未标明来源 |

**使用建议**：
- A/B级来源可直接引用
- C级来源需交叉验证
- D级来源原则上不引用

## 推理标注规范

当某个观点是Claude综合多个来源推理得出时，必须明确标注：

### 推理记录格式

```json
{
  "id": "I1",
  "type": "inference",
  "conclusion": "综合判断：市场将持续增长",
  "based_on": ["U1", "W2", "D1"],
  "reasoning": "基于历史数据趋势 + 政策支持 + 需求增长",
  "confidence": "high"
}
```

### 置信度标准

| 置信度 | 标准 | 标注方式 |
|--------|------|---------|
| high | 多个可靠来源支持，逻辑链完整 | 可直接陈述 |
| medium | 2个以上来源，有一定推理成分 | "根据分析，可能..." |
| low | 单一来源或推理成分较高 | "初步判断..." + 说明局限性 |

## 特殊情况处理

### 用户素材未覆盖的信息

1. 明确标注来源为网络搜索(W)
2. 评估来源可靠性
3. 与用户素材中的信息交叉验证

### 数据矛盾

当不同来源的数据矛盾时：

```markdown
市场规模方面，用户提供的报告显示为2000亿元[U1]，
而艾瑞咨询数据为2200亿元[W1]。差异可能源于统计口径不同。
```

### 无法找到来源

如果某个重要信息无法找到可靠来源：

1. **不要凭空编造**
2. 标注为需要验证：`[待核实]`
3. 在质量报告中标记

## 来源索引模板

### 完整版（文章附录）

```markdown
# 来源索引

## 统计概览

| 类型 | 数量 | 占比 |
|------|------|------|
| 用户素材 (U) | X | XX% |
| 公开数据 (D) | Y | YY% |
| 专家观点 (E) | Z | ZZ% |
| 网络搜索 (W) | N | NN% |
| 推理综合 (I) | M | MM% |

## 用户素材

| 编号 | 文件名 | 类型 | 引用章节 | 引用次数 |
|------|--------|------|---------|---------|
| U1 | xxx.pdf | 报告 | 一、三 | 5 |
| U2 | notes.md | 笔记 | 二 | 2 |

## 网络来源

| 编号 | 来源 | 可靠性 | URL | 引用内容 |
|------|------|--------|-----|---------|
| W1 | 艾瑞咨询 | A | [链接] | 市场数据 |
| W2 | 36氪 | B | [链接] | 行业动态 |

| 编号 | 机构 | 发布时间 | 数据类型 |
|------|------|---------|---------|

| 编号 | 结论 | 依据 | 置信度 |

```

### 简化版（嵌入文章）

```markdown

## 来源索引

| 编号 | 类型 | 来源 | 说明 |
|------|------|------|------|

| D1 | 公开数据 | 国家统计局 | 2024统计 |
| I1 | 推理 | 基于U1+W1 | 趋势预测 |
```

## 引用密度阈值（v5.0 新增 / L3 闸门自动校验）

> 控制引用既不"贫血"也不"过度堆砌"。被 [`quality-gates.md`](quality-gates.md) L3 闸门作为硬指标自动校验。

### 标准值

**1 条引用 / 400 字（±30%）**

即每 400 字至少出现 1 条 `[U1]` / `[W2]` / `[D1]` / `[E3]` / `[I1]` 形式的引用标注。

### 计算方法

```
引用密度 = (全文引用条数 / 全文字数) × 400
```

落入区间 **[0.7, 1.3]** 视为合格。

**示例**：
- 全文 8000 字，引用 22 条 → 密度 = (22 / 8000) × 400 = 1.1 ✅
- 全文 8000 字，引用 12 条 → 密度 = 0.6 ❌ 过低
- 全文 8000 字，引用 36 条 → 密度 = 1.8 ❌ 过高

### 用途

L3 闸门（`output-finalizer` 中段）自动计算并嵌入 `<verdict>` 的 `subscores.citation_density` 字段：

```json
{"citation_density": 0.92}  // 落在 [0.7, 1.3] → pass
```

### 异常处置

| 偏离方向 | 可能原因 | 处置 |
|---|---|---|
| 密度 < 0.7（过低）| 数据点不足 / 推理成分过高 / writer 漏标 | 回 `source-manager` 补充来源 + 回 `longform-writer` 补标注（max 1 轮）|
| 密度 > 1.3（过高）| 来源堆砌 / 同一来源反复引用 / 数据轰炸式写作 | 回 `longform-writer` 精简引用（合并相邻同源引用 / 删除冗余）（max 1 轮）|

### 与"内容完整性"的关系

引用密度替代原 checklist 的"核心判断均有 ≥1 个数据点或案例支撑"布尔检查，从主观判断升级为可量化指标。

## 常见错误

### ❌ 错误1：数据无来源

```markdown
市场规模达2000亿元。  ← 缺少来源标注
```

### ✅ 正确

```markdown
市场规模达2000亿元[U1]。
```

### ❌ 错误2：推理不标注

```markdown
未来三年将保持30%增长。  ← 预测性判断未标注
```

### ✅ 正确

```markdown
基于当前趋势，未来三年可能保持20%-30%增长[I1]。

[I1]: 基于U1历史数据趋势 + D1宏观环境，置信度中等
```

### ❌ 错误3：来源编号混乱

```markdown
第一章: 数据来源[1]
第二章: 根据数据[U1]  ← 编号体系不一致
```

### ✅ 正确

全文统一使用U/W/D/E/I编码体系
